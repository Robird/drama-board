# 商业与协作管理：把目的、承诺和手段分开

2026-10-31。研究建议，未修改目标管理合同或生产代码。依据当前[设计草案](../../design/goal-management/design.md)与[用户故事](../../design/goal-management/user-stories.md)。这里借用管理框架的局部机制，不把游戏角色改成需要执行 Scrum 的项目团队。

## 1. 保留结果，允许替换方法

**来源与原义**：[《Scrum Guide》2020，Sprint Backlog／Commitment: Sprint Goal](https://scrumguides.org/scrum-guide.html#sprint-backlog)区分目标的理由、选择的工作及实现计划；具体工作可以随认识变化调整，而目标保持连贯。它是框架制定者的规范性指南，不是这种机制提高 LLM 成功率的实验结论。

**映射**：Goal 保存想达到的结果，GoalLink 保存某项子工作为什么服务父目的，Focus 指向当前优先处理的目标，下一步提示记录当前办法。例如父目标“让双方有饮水”，子目标“到溪流湾采水”；水源耗尽时，替换或放弃后者，不必删除前者。界面同时显示“想达成什么”和“下一步打算怎么做”，可以减少把动作清单当成最终目的。

**首版采用候选**：沿用现有字段即可；更新下一步不自动改写完成标准。若完成标准发生实质变化，要求显式说明，不允许为了关闭目标而悄悄降低要求。

**局限与反例**：目的本身也可能失效，不能强迫角色永远坚持旧目标。Scrum 的单一 Product Goal 与固定 Sprint 不适合直接限制角色同时承担生存、协作和探索目的。GoalLink 也不是执行先后关系：“采水服务补给”不表示所有补给行动都必须等待采水。

## 2. 挂起仍然占据未兑现事项的容量

**来源与原义**：[《The Kanban Guide》2025.5，Defining and Visualizing the Workflow、Actively Managing Items in a Workflow、Flow Metrics](https://kanbanguides.org/the-kanban-guide/2025.5/)要求明确开始/结束边界，控制已开始但未完成的工作，并处理阻塞和老化。WIP 不等于此刻正在操作的条目。这是规范性流程建议，不给我们提供通用的最佳容量数字。

**映射**：Focus 只有一个，不意味着角色只背着一项责任；Paused 也不意味着责任消失。挂起赠水目标时仍应留在上下文目录，显示原因和恢复线索。多个父目标引用同一 Goal 时，存储容量按目标身份计数，关联另计，不能把一次改焦点当成释放资源。

**首版采用候选**：Open 与 Paused 一起纳入未结束记录容量；这是材料容量政策，不宣称它们全部是 Kanban 的“已开始工作”。达到上限要求整理或拒绝新增，不通过 pause 绕过。Focus 展示优先级与实际 Activity 并行数继续分开。

**局限与延期**：长期目的和一次性任务尺度不同，不能拿目标总数推断角色负荷或吞吐量。若要统计停滞，可先在实验日志区分“挂起多久”和“最近一次实际进展”，但不让每次改字刷新进展时钟。自动催办、基于历史周期的完成时间预测暂缓；异质小样本容易产生虚假精度。

## 3. 复查应允许改变决策，而不要求每回合重写计划

**来源与原义**：[《Scrum Guide》2020，Inspection／Adaptation 与 Sprint Review](https://scrumguides.org/scrum-guide.html#scrum-theory)把检查结果、环境变化与下一步调整联系起来；检查的价值在于支持适应，不只是汇报。

**映射**：新 Context 自动提供未结束事项，本身就构成低成本复查入口。收到水源耗尽、同伴出现或身体警告后，模型应能判断继续、暂停、换方法或放弃；Focus 的返回只是恢复上层理由，不替模型证明原方法仍可行。

**首版采用候选**：提示控制器在新证据影响目标时检查相关事项；目标内容未变便直接行动，不强制调用 update。GoalLink 的来源理由帮助回答“这个成果现在还服务谁”，父目标结束后不级联关闭共享子目标。

**局限与反例**：不能把每次 Context 打开做成一次冗长评审会，也不能默认子目标结束就自动继续旧行动。事件到目标的自动关联先延期，现有观察加短目录足够开展实验。

## 4. 完成条目不是成绩，真实结果才是验收对象

**来源与原义**：[Ordóñez 等《Goals Gone Wild》，作者所在机构公开摘要](https://www.hks.harvard.edu/publications/goals-gone-wild-systematic-side-effects-overprescribing-goal-setting)讨论目标过窄可能忽略其他维度、扭曲风险选择并抑制学习。这是综合既有研究与案例的批判性论述；该页面为 2020 章节记录，本文只援引其摘要，不把它当作新随机实验或 LLM 证据。

**映射**：模型把“采十份水”当最高优先级时，可能忽视寒冷、同伴需要或逃离机会。目标材料不能挤掉身体警告；Completed 只记录角色判断，不能变成奖励、胜利或库存事实。共享目标也不能按引用次数累计成果。

**首版采用候选**：实验同时检查约定兑现、生存结果、误标完成和管理调用成本。角色完成说明与客观游戏事件并列核对。

**不宜搬入**：OKR 式计分、目标完成率排行榜、以关闭数量奖励模型。把一项工作拆成十项会抬高这些分数，却未必让同伴多获得一份水。此处也不推论“明确目标有害”；风险用于设计反例测试。

## 两个可玩实验

1. **水源变化，承诺不变**：双方分工后，原采集点耗尽，另一地点仍有水。观察真实模型是否保留赠水目的、改用替代方法、经过多个 Context 后兑现；同时记录暂停目标是否仍可见。世界记录判定赠与，不能用模型自报成功代替。主要覆盖 US-01、US-04，可扩展 EX-04。
2. **窄指标与突发危险**：角色准备较多补给，途中出现低温风险；设置足够信息让“先避险再继续”可行。观察是否切换焦点、保留原目的、没有用目标编辑取消 Activity 或确认警告。衡量生存与承诺结果、错误结束次数及编辑/行动调用比例，不评比完成目标的数量。主要覆盖 US-02、US-06。

建议先以现有 Goal／Link／Focus 骨架运行这些实验，不新增项目组合引擎。未决问题仍是容量数字、完成标准修改政策、进展与文字更新时间的区别；商业框架能提供检查问题，不能替我们裁决游戏语义。
