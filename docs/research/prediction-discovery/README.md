# 新组合发现：从物理模拟到 DramaBoard 预测引擎

> 2026-10-27。并行文献综述与当前源码对照。本文提出后续设计建议，不代表已经实现或批准全部 API；本轮不修改核心代码。核心改造方向见[预测对象草稿](../../design/prediction-objects-roadmap.md)。

## 结论先行

用户提出的类比成立：**局部运动、已知运动规律的有效区间、边界触发以及新交互关系发现，已有大量成熟成果可借鉴。** 最值得继承的不是完整刚体求解器，而是两件事：

1. 利用明确的作用范围，只处理可能受影响的对象与关系。
2. 对“这个范围目前足够”的依据进行维护；必要时预测它何时失效，提前重新发现。

因此，“每个已有预测判断是否需要重算”只覆盖了一半问题。另一半是：**一个尚不存在的预测，由谁在合适的时候发现并创建？** 事件驱动物理模拟中的跨格事件、邻域退出事件，以及动力学数据结构中的证书失效，都提供了具体答案。[Donev 的事件驱动模拟综述](https://math.nyu.edu/inmemoriam/donev/DSMC/AED_Review.pdf)、[CGAL 动力学框架说明](https://doc.cgal.org/Manual/4.1/doc_html/cgal_manual/Kinetic_framework/Chapter_main.html)

对当前 DramaBoard，建议先做“通道级发现 + 局部预测维护”，随后缩小为“变化运动段 × 同通道其他运动段”；再以测量决定是否引入邻域期限或排序证书。这个次序先建立可验证的契约，也为后续高级算法保留位置。无需一开始引入三维物理引擎。

## 可以继承的成熟机制

| 机制 | 解决什么 | 用于本项目的边界 |
| --- | --- | --- |
| EDMD 的 cell transfer / 邻域退出 | 在现有候选集合不再充分之前重新发现 | 维护事件必须与业务事件有正确的时间和同刻阶段关系；不能只在其他事件偶然发生时刷新 |
| Broad-phase 的 created/updated/removed → new/lost pairs | 由变化对象批次维护关系集合 | 关系未增删但运动改变，也要重新预测；普通离散索引不自动保证任意跳时安全 |
| KDS 的证书与 failure queue | 将结构正确性转换为可预测的失效条件 | 一维邻接很有吸引力，但需处理同位、多体相交及业务时间量化 |
| DEVS 的 passive 与 external transition | 没有当前到期项的过程仍可被外部变化唤醒 | 对应暂停生长、暂时无接触的发现入口；不要求照搬整个 DEVS 协议 |
| 混合系统的 mode / guard / reset | 当前规律持续到某个已知边界，之后切换规律 | 求已注册 guard 的根，不等于发现尚未注册的人对或关系 |

依据分别来自 [Donev EDMD 论文](https://math.nyu.edu/inmemoriam/donev/Packing/EDMD.pdf)、[PhysX BroadPhase 官方接口](https://github.com/NVIDIA-Omniverse/PhysX/blob/main/physx/include/PxBroadPhase.h)、[CGAL KDS 手册](https://doc.cgal.org/Manual/4.1/doc_html/cgal_manual/Kinetic_data_structures/Chapter_main.html)、[DEVS 作者教程](https://simulation.tudelft.nl/SEN9110/lectures/04%20VanTendelooVangheluwe_SpringSim2017_DEVSTutorial.pdf)和 [Modelica 事件规范](https://specification.modelica.org/maint/3.6/equations.html#events-and-synchronization)。

这里应避免一个误解：硬球碰撞的解析事件驱动算法，不代表所有刚体/CAD 系统都如此工作。持续接触、摩擦和多体约束常需要时间步进与联合求解。确定性的逐对事件排序，也不自动等价于同时冲击的物理解。当前游戏需要的是发现与失效组织，不是复现这些求解器。[Drake 离散接触模型](https://drake.mit.edu/doxygen_cxx/group__mbp__discrete.html)、[MIT 多体接触教材](https://underactuated.csail.mit.edu/multibody.html#the-dynamics-of-contact)

## 核心契约：不仅知道预测什么，还知道何时必须重新寻找

建议把责任分为下列四层；它们可以由少数对象实现，不要求四套框架：

```text
业务变化批次 / 发现范围失效
          ↓
发现与覆盖维护：哪些关系现在需要纳入？哪些可以暂时不看？
          ↓
失效判断与精确预测：哪些旧结果保留？哪些求解为新输出或零输出？
          ↓
调度：在完整有效的候选中选择下一项
          ↓
业务响应：消费机会、改变世界，进入下一次完整转换
```

“暂时不看”的关键不变量是：

> 对任何可能成为下一次合法交互的关系，要么已有候选覆盖它，要么必须保证在它可能被选中之前完成重新发现。外部业务变化一旦破坏该依据，也要在下一次选择前更新发现结果。

这里的“之前”按引擎的调度语义定义，不能只比较连续几何时间。同 tick 下，可能需要先完成发现，再执行业务仲裁。

当前通道模型有一个很强的天然保证：不同通道的运动段不会产生 contact；同通道内当前已知的恒速运动段可直接解析求交。因而不需要先安排定期刷新，通道成员/运动变化就是足够的发现触发。只有进一步排除同通道中较远的对象，或缩短预测时间窗，才需要额外的覆盖证明或维护唤醒。这是本项目推论，不是所有空间模型的通则。

暂停植物与空通道也揭示了同一个生命周期规则：**零输出不等于过程结束。** 可以由已有业务对象与可持久描述承担发现/预测职责，不必为每个可能的人对创建独立 DG 对象。无交点关系也不必全量存表，只要负责它的发现入口仍能接收所有会使它变得有效的变化。

## 必须先裁决的时间问题

当前 contact 是交互机会：精确交点时间向下取整，随后同 tick 按 seed/key 仲裁。它不改变双方运动。因此不能直接用“只预测几何相邻者的下一次相交”替换全量配对。

一个当前 Start API 可构造的例子：长度 100 的通道，b、c 从 tick 0 起以速度 2、3 同向行进，a 在 tick 1 从同端以速度 10 加入。此时位置为 a=0、b=2、c=3：

- ab 相遇于 `5/4`，ac 相遇于 `10/7`，都被量化为 tick 1。
- ac 当前不相邻，但在指定 canonical key、generation 1、seed 0 下，它的 rank 比 ab 小，应先胜出。
- 若先发布 ab 再发现 ac，已改变业务顺序；若消费 ab 后仍按当前几何邻接查询，ac 还不可见。

完整 key、rank、公式与 Python 复现代码见[源码约束反例](dramaboard-constraints.md#三邻接方案的可复现反例)。主线程已独立运行该探针并对照 scheduler 编码；这不是产品集成测试。

另一个前瞻陷阱：覆盖在连续时间 10.2 失效，新接触在 10.7。若维护取 ceil 得到 11，而业务 contact 取 floor 得到 10，维护就晚了。都取 floor 也还需要同刻阶段与推进规则。当前尚未实现这类邻域，本文是在指出设计条件，不是在报告现有 bug。

没有兼容性负担，后续可明确比较三条路线：

| 路线 | 收益 | 需要承担的工作 |
| --- | --- | --- |
| 保持 floor 与现有仲裁，先局部全配对 | 最容易以当前参考验证，先解决全世界重算 | 单个拥挤通道仍有平方成本 |
| 保持业务语义，内部精确扫描至候选 tick 的发现闭包 | 有机会使用 KDS 缩小搜索 | 必须在选赢家前找全必要竞争者；回应改变运动后重新验证预推演 |
| 明确调整为精确事件顺序或新的 tick 批次语义 | 算法与时间语义可能更自然 | 要重新定义交互时机、同刻规则与验收，不能当作透明优化 |

本轮建议以第一条作为初片，后二者作为实验，不在综述中提前批准。纯算法维护是否占用 Kernel occurrence、cursor、日志及同刻预算，也应独立裁决，不能把它无差别塞入业务仲裁。

## 建议的实施顺序与 API 边界

1. **先定发现入口与发布契约。** 通道发现 owner 在没有输出时仍可被唤醒；明确成员加入/替换/删除、输出消费、owner 结束的区别。子系统提供发现与求解逻辑，Kernel 不认识角色、植物或通道。
2. **按 dirty 通道完整发现。** 在最终 scratch 业务状态上重新计算受影响通道，输出按稳定业务身份完整替换。保留独立全量算法作参考，而不是两套生产权威。
3. **改为变化成员的增量 join。** 新建/改向的段与最终同通道成员配对；包含同批新成员之间的关系、去重和旧段清理。未变段对保留；contact 消费仅去掉对应业务输出。
4. **有测量再实验更强索引。** 可选完整已知运动段的保守范围，或有限范围加维护期限；密集一维通道可实验排序证书。每次明确覆盖不变量和时间语义，保持对照。

最小 API 应能表达：发现 scope 的稳定身份、业务变化批次、创建/撤销/更新关系或 owner、重算的零到多项输出。**仅有 Added/Removed pair 不够**，已存在关系的端点变化仍需进入 dirty 集。订阅用可持久的种类/目标描述和代码分派，不依赖序列化 Delegate；本轮不需要通用重入事件总线、任意预测依赖图或固定点求解器。

过程描述和权威输出应与业务结果进入同一个完整转换，经既有 E、S 两次发布完成；不是声称 E/S 只有一次物理写入。恢复 pending 只 Fold 已记录结果，不重新运行发现/预测维护或请求 Player；Fold 仍可进行确定性的事实合法性校验，包括现有 contact 的精确求交复核。运行时成员/反向索引可以从已发布状态重建，但重建不能增写新的业务真相。具体描述与输出的持久承载方式仍属后续 API 设计。

## 怎样证明有收益

局部性使倒水通常不用通知地球另一端的人，但这一收益来自**领域依赖确实有限**。全局昼夜、天气、共享资源或瞬移规则可能扩大作用范围，不能靠几何索引擅自忽略。

设受影响通道有 n 个成员，变化成员为 m：通道全配对约为 `O(n²)` 次检查，变化成员 join 约为 `O(mn)` 次检查。这里仅描述配对工作，未包含路由、候选选最小、集合复制、验证和持久化。当真实需要显式产生 K 个关系时，仅输出就需 `Ω(K)`；若契约只要求求下一事件，不能把这个下界直接套到尚未要求物化的全部未来关系。拥挤世界可能确实产生平方数量的机会。

验收应至少覆盖：

- 独立全量参考：从业务运动状态计算，绕过被测 dirty 路由/输出表；初片比较完整候选、赢家及轨迹。若后续改为惰性时间窗，另定下一事件完备性验收。
- 新关系：空→有人→新人、零输出后掉头、同批多段加入、删除、同位和三体同刻、跨覆盖范围。
- 时间：上述非邻接同 tick 赢家、维护与业务同 tick、业务消费后几何证书仍需维护、过期预测拒绝。
- 发布：S 冷开、E-only 恢复、重建索引与连续运行等价；恢复不重新调用规划。
- 代价：发现访问数、粗筛 pair 数、精确求交数、输出数、队列与索引大小、CPU/分配/发布成本分别测量。

有限场景上预测次数下降，不足以声称总程序加速；初版统一持久形状也可能暂时增加开销。研究应保留这些可证伪的边界。
