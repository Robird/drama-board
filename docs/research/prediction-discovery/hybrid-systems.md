# 混合系统、离散事件与刚体仿真：预测及新组合发现的借鉴

> 调研日期：2026-10-27。设计研究，未修改产品代码、未运行仿真实验。阅读了当前 [PROJECT-STATE](../../../PROJECT-STATE.md) 与[预测对象草稿](../../design/prediction-objects-roadmap.md)。下文把外部机制和本项目建议分开；建议尚非已裁决 API。

## 1. 同构在分段演化，不在所有求解细节

用户的类比很有价值：在一段时间内沿当前规则演化，遇到边界条件后改变规则，再预测下一边界。这同时适用于植物白天生长、人物匀速行走，以及部分机械系统的接触/脱离。不过，刚体仿真并不都采用“精确预测下一碰撞后跳时”。Tedrake 的课程区分柔顺接触、带冲击重置的混合模型、时间步进的平均冲量模型；Drake 的离散多体模型采用固定步长更新，并用约束求解处理接触。[MIT 多体动力学课程](https://underactuated.csail.mit.edu/multibody.html#the-dynamics-of-contact)、[Drake 离散模型](https://drake.mit.edu/doxygen_cxx/group__mbp__discrete.html)

对 DramaBoard 的判断：**更接近局部离散事件模型加可解析运动段，而不是通用物理求解器。** 我们可以精确表达“同一运动段持续到到达/掉头”“植物以固定速率积累到成熟/日落”，因此先继承模式切换、失效范围与事件边界的组织方法即可。引入摩擦互补约束、刚度求解或通用 ODE/DAE，并不会自动解决新组合发现。

“地球另一端互不影响”可以成为游戏模型的明确约定：某过程只读自己的依赖集合。空间遥远本身不是万能证明；全局昼夜、广播魔法、共享水源等规则仍可产生远程依赖。优化应尊重业务定义的影响范围，而不能仅按距离删掉依赖。这是本项目的建模判断，不是物理引擎对任意世界提供的保证。

## 2. 三种边界必须区分

Modelica 把条件变化作为离散事件，使连续演化停在边界、更新条件后继续；只依赖时间的边界可以预先确定，不必数值搜索。这个区分直接对应游戏中的定时完成与状态触发。[Modelica 3.6 §8.5](https://specification.modelica.org/maint/3.6/equations.html#events-and-synchronization)

| 问题 | 所需机制 | 本项目例子 |
| --- | --- | --- |
| 已知关系何时达到条件 | 求根、解析求交或业务公式 | 已知 A/B 在同一通道，计算交会时刻 |
| 当前方程或规则何时失效 | 模式切换、外部事件、版本依赖 | A 掉头；日落改变太阳花生长速率 |
| 尚未列出的关系何时需要纳入 | 发现范围变化或发现范围边界事件 | C 加入通道；此前不邻近的对象进入候选范围 |

第一行通常称为 guard/事件指示器定位或碰撞时间计算。SUNDIALS 的 CVODE 为已注册函数寻找零点，通常依赖符号变化；偶重根可能漏检。这说明“有求根器”也不等于“所有触碰均已完整检测”，更不等于求根器会主动发明尚不存在的 A/C 条件。[CVODE 7.8 Rootfinding](https://sundials.readthedocs.io/en/v7.8.0/cvode/Mathematics_link.html#rootfinding)

本项目应把第三行设为独立验收责任：**任何被暂时排除的关系，都必须有理由保证它在下一次发现机会之前不产生有效事件。** 例如整条通道作为发现范围时，所有在途成员均在范围内；新成员只能通过已处理的开始移动事实进入，因此可以在该事实后重建通道人对。若以后把通道划成小格，仅在“有人改变运动”时重建邻居就不够：匀速前进也会进入新格，必须安排跨格发现事件，或使用覆盖未来区间的保守候选范围。

这是从边界思想推出的设计要求，不是建议现在就建立格网。现有通道级发现器可以先满足它。

## 3. DEVS 与 FMI 提供的是生命周期和接缝

Parallel DEVS 的原子模型区分内部到期、外部输入与二者同刻的 confluent transition；time advance 可为无穷，表示没有自主到期，但模型仍具有外部输入处理能力。耦合模型通过连接组织输入输出。它支持“暂停不销毁、外部变化可唤醒”的表达。[Van Tendeloo / Vangheluwe，Parallel DEVS 教程，§3–4](https://simulation.tudelft.nl/SEN9110/lectures/04%20VanTendelooVangheluwe_SpringSim2017_DEVSTutorial.pdf)

对本项目的映射：太阳花日落后没有成熟输出，生长过程仍存活；空通道没有 contact 输出，通道发现入口仍存活。**无输出是一种正常状态，不是对象退出条件。** 但 DEVS 接口本身并不为游戏提供空间关系索引，仍要由领域代码创建/撤销连接或发现范围。

FMI 3.0.2 的事件模式允许模型报告下一绝对事件时刻；若更早发生其他事件，之前的 `nextEventTime` 失效。规范还公开变量依赖，用于识别耦合和稀疏性。这分别支持“预测只在当前前提下有效”和“显式描述依赖”的方向；不能把 FMI 的依赖元数据直接称为游戏事件订阅实现。[FMI 3.0.2：Event Mode 与 Dependencies of Variables](https://fmi-standard.org/docs/3.0.2/)

建议初版保留现有草稿的分离：业务过程描述其关注条件；重算产生零到多个可持久输出。对外先暴露稳定身份、业务目标和数据，不引入 FMU、端口协议、动态方程编译或持久 Delegate。

## 4. 同刻事件与局部重算：确定顺序仍是领域语义

Modelica 的 event iteration 会在同一事件时刻重复求值，直至离散值稳定，并允许实现只迭代必要的局部方程；这不是要求每次重新求解整个世界。[Modelica `pre` 与 event iteration](https://specification.modelica.org/v3.4/Ch3.html#SS7.SSS3.P1)

我们可借鉴局部收敛意识，但不必继承代数固定点求解：当前草稿要求 dirty 预测都只读同一份最终业务状态，不读取其他预测结果，因此一轮纯重算就应足够。若允许预测 A 的输出影响预测 B 的输入，再由 B 反过来影响 A，就需要额外定义依赖顺序或固定点；应暂时维持禁令。

同刻接触与到达也不能靠“都在同一时刻”自然解决。对游戏可采用明确的领域优先级和稳定仲裁，再在每笔 occurrence 后完成维护；这给出可复现行为。若将来要模拟物理意义上的多体同时冲击，逐对按 ID 处理未必是合适模型，需要共同约束或单独的同刻求解。前述刚体求解方法的区别在这里尤其重要。

需要三条分立规则：

- **独立过程可以顺序执行**：处理 A 之后不应让 B 的无关预测改变；用无关事件插入测试验证。
- **共享资源/同刻冲突要有业务政策**：例如先到达还是先相遇、先成熟还是先销毁；稳定排序只保证复现，不替代政策。
- **同刻链必须有进展与诊断**：禁止消费后原样反复生成同一事件；保留同刻次数上限，并输出涉及的过程和触发链。上限是故障防护，不是语义收敛证明。

以上三条为本项目建议；不要求将 Kernel 的单 occurrence 发布改成“合并所有同刻事件”。

## 5. 对“发现—预测—发布”的最小设计建议

建议把下列职责写进后续设计评审，而不急于各建立一套公共类层级：

| 职责 | 最小输入/输出 | 需要回答的问题 |
| --- | --- | --- |
| 发现范围维护 | 成员/运动变化 → 受影响范围 | 新组合由哪个存活对象发现？ |
| 范围内关系发现 | 最终业务状态 → 当前关系集合或预测集合 | 新增、消失、已消费关系如何区分？ |
| 已有过程重算 | 最终业务状态、通知批次 → 完整输出集合 | 依赖未变时为何可跳过？ |
| 到期执行 | 已发布输出 → 业务变化与维护结果 | 输出版本是否仍有效，消费后如何前进？ |

通道级过程可以同时完成前两行和第三行：成员发生变化后全量枚举该通道，计算并替换整个输出集合。这样先不引入人对对象，便有持续发现入口；之后再根据测量，把通道内关系细化为可独立维护的人对。

应特别避免两个漏洞。第一，发现器只订阅已有成员，会漏掉新人；需要通道级成员加入事实。第二，空间索引只在离散业务事件时更新，却用“当前附近”排除正在接近的对象；若时间可以直接跳跃，必须证明候选范围在跳跃区间内保守，或为范围失效安排更早的唤醒。

持久化继续沿用项目草稿：业务变化、过程生命周期和新预测共同进入完整 draft，E/S 发布完成后才对外可见。恢复只 Fold 已记录结果，不重跑发现/重算。外部文献没有替我们解决这个单根发布契约；它是 DramaBoard 对上述机制的独立工程约束。

## 6. 优先借鉴什么，以及如何证明没漏

首片应借鉴：过程与输出寿命分离、绝对到期时刻、依赖变化作废、局部发现范围、显式同刻政策。暂不需要通用数值积分器、摩擦接触约束、连续方程自动求导、分布式同步或任意预测间固定点。

建议围绕“通道内匀速运动”建立以下手写轨迹，并与独立全量枚举参考逐事件比对：

1. 空通道、单成员都没有 contact，但后来 C 进入后必须产生新关系。
2. 第三人加入、掉头、移除只影响相应通道，其他通道预测身份和到期时刻不变。
3. 两人目前分离但沿当前运动段会相遇，不能因当前距离远而漏掉；若使用有限发现范围，还要测无业务输入的越界进入。
4. 接触与到达同刻、两个接触同刻，按已定政策得到同样结果；排列注册顺序不得改变结果。
5. 暂时无输出的过程在相关变化后恢复预测；结束对象不会留下订阅、关系或输出。
6. 每个关键状态冷开与 E-only 恢复，后续轨迹一致；恢复过程不调用发现或预测代码。

性能实验分开记录候选配对数量、实际求交数量、dirty 过程数量、调度扫描、分配和发布成本。减少重算不必然降低总耗时。此综述仅建立借鉴依据和需要证明的边界，未声称已得到最佳索引、数值稳健性或扩展性结果。
