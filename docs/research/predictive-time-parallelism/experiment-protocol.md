# 实验协议：正确性、收益与证据

本协议服务 [C1–C8](README.md#完成条件)；候选机制见[研究设计](research-plan.md)。下列是待执行实验，**不是已经测得的结果**。

## 分开两条实验轴

**轴 A：同规则下的执行策略。** 固定场景、有效模型输入到响应的函数、世界随机规则和原有仲裁，比较串行参考、安全并行、有界投机。实际采用的输入与命令序列、世界事实和状态应等价；诊断调用数、请求 ID、墙钟顺序可以不同。

**轴 B：世界规则约束。** 范围、传播延迟、共享机制可能改变轨迹；每个规则变体内部重新做轴 A，不把不同轨迹的总耗时差直接记作调度收益。单独记录角色可见行为、交互等待和规则表达成本。

若研究必须改变角色服务顺序或输入语义，另立命名明确的实验，不称为轴 A 等价优化，不改变串行参考来迁就失败结果。

## 三层实验与固定响应

1. **独立小模型**：少量实体、有限行动/时间，枚举或穷举允许的因果路径。独立算出可能影响与到达时间，检验被测估计漏算；oracle 不共享被测算法的作用域剪枝或脏路由。
2. **实际应用离线适配**：使用 Playground 的实际 Context、命令、领域校验、Kernel 和恢复接缝，Completion 用确定性响应及可控延迟替身；检验调用重叠与同规则等价。涉及持久化的主张必须用真正存档/冷开验证。
3. **真实模型小批次**：实际端点、模型、协议、输入长度、并发和 usage 留证；用于检验真实集成、吞吐与浪费，不把随机输出的一致性当成等价证明。

固定响应按**完整有效输入指纹＋fixture seed**寻址，不按全局第 N 次请求寻址；投机废弃不能移动后续脚本。额外响应身份如需生成，按输入/角色逻辑身份确定，避免随机 ToolCallId 引发虚假分歧。真实响应回放只覆盖实际出现的输入，未命中必须明确报错或进入预声明的 fixture 分支，不能悄悄调用网络。

离线 fixture 还须控制宿主身份：当前 `LlmDecisionLoop` 为 OperationRecordId 生成 GUID，它进入领域事实和 Context。优先提供实验侧确定性身份来源；若用身份一一对应比较，列出允许对应的字段并验证全部引用一致，不能简单忽略所有 ID，也不能改写实际模型输入来制造命中。

指纹覆盖实际请求原值，任何非语义字段排除都须证明不进入模型或不影响行为；不能为了回放删除实际可见身份、经历、选项或原生 Tail。记录规范版本，能导出输入差异。

对照运行必须从相同的独立初态/存档副本开始，固定工作负载完成条件，例如同一批角色有效操作与预定模拟目标。不能只固定 Step 数：OpenContext、拒绝和即时动作会改变转换数。正确性实验检查完整轨迹；性能实验保留关键轨迹指纹及首个分歧。

## 最小必需场景

| 编号 | 场景 | 主要证伪对象 |
| --- | --- | --- |
| M1 | 远处独立角色，同时和错峰唤醒；包含尚无已开启 Context 的起始状态。 | 明明独立仍串行；伪造提前 OpenContext；未来时间输入错误。 |
| M2 | 同地争抢有限库存、市场额度或交易资产。 | 行动合法等同于输入有效；共享依赖漏算；重复执行。 |
| M3 | say/shout、即时接收后再次发言；有界一步与多步零延迟连锁。 | 一跳即全局有界；遗漏新的可见经历；同 tick 仲裁改变。 |
| M4 | 角色移动、进入/离开作用域、途中接触与未来抵达。 | 静态邻域漏掉新关系；过期空间证书仍生效。 |
| M5 | 唤醒被提前、延后、合并或取消，角色死亡/控制绑定或运行分支变化。 | 旧候选被错误采用；仅凭 actorId/预计时间匹配。 |
| M6 | 远程关系、共享市场变化、OpenContext 的交易维护。 | 地理隔离即因果隔离；“只读准备”偷偷改世界。 |
| M7 | 身体/昼夜的已知演化与不确定环境变化。 | 当前观察冒充未来观察；投影推进共享随机游标；普通全局版本使全部失效。 |
| M8 | feedback、多轮工具纠正、过期候选失败、调用中取消、预算耗尽、暂停/冷开与 pending E。 | 提前执行副作用；并发超预算；取消返还额度；恢复重问模型；顺序日志损坏。 |
| M9 | 缺失机制声明、零延迟大闭包、未知动态关系；与 Human 输入共存。 | unknown 被当安全；把人类行为当已知；错误承诺所有场景可加速。 |

可以用少量组合场景覆盖多行，但报告需逐项映射，写明哪些在小模型、实际应用或真实调用中执行。默认不要求真实模型穷举所有场景。

规模首先为 2–3 角色的真实 Playground。合成小模型再按 2/8/32 等级观察扩展性；当前 CLI 只支持 1–3 角色，不为跑表格强行扩展产品人数或把合成结果说成实际应用规模。

M5 中的控制绑定/分支变化通过新 run、冷开或测试用代次失配验证即可；当前绑定启动时冻结、冷开候选清空，不要求新增运行中热切换或并发分支。

## 正确性判据

- 串行与候选策略的实际采用输入、行动、领域结果及必要状态一致；对随机响应只能做协议与采用条件检查，不能声称轨迹确定。
- 返回快的请求不能抢先提交；同 tick 仍遵守事件种类和既有服务顺序。
- 包络估计在声明支持的有限小模型中没有漏掉可能影响，最早到达下界不能晚于实际可能到达。保守性须另有机制合同推导，样本零错误不能推广为一般证明。
- 失效候选不执行反馈或世界操作，不形成已接收操作，不进入角色经历。候选本地采用状态与远端请求状态分别记录：例如候选已 discarded，远端是否执行仍可 unknown；不能用一个合并状态混淆两者的计数与正确性。
- 正常停止时结清本地候选；进程中断留下的非终态记录在报告中标为中断/unknown，冷开丢弃候选。不要求恢复模型会话、补发请求或新增逐候选持久恢复协议。
- pending 恢复只应用已保存事实。提交前与提交后取消、候选仍在运行、日志刷盘失败和 client Dispose 失败，不能吞掉原有主错误或暗中重试。
- 使用可控的不同返回顺序验证共享预算、顺序 writer、会话隔离、资源释放和停止后不再采用，不能只靠压力测试偶尔未失败。

## 计量合同

| 指标 | 记录方式与解释 |
| --- | --- |
| 工作负载耗时 | 单调时钟记录开始到既定有效工作完成；另列取消/排空与释放完成时间。不能把后台仍计算的浪费隐藏在计时外。 |
| 有效吞吐/等待 | 每秒实际完成的角色操作、角色从实际可服务到采用决定的等待；尾延迟样本不足时不报有统计意义的 p95。 |
| 调用并行度 | admitted、queued、invoked、completed、in-flight 分开，记录时间线；请求已保存不证明远端收到。 |
| 候选收益 | 提前量、命中/采用、失效原因、缺少候选的需求调用数；明确分母，协议纠正/feedback 续调用分开。 |
| 计算与费用 | 所有实际 provider 请求含失败、取消和废弃的 usage；未知保持 null。有可核验价格才估费用，不把 token 数或零 usage 当免费。 |
| 估计/验证开销 | 构造预计输入、传播/闭包查询、重算、指纹/比较、日志和提交的耗时与分配；不能只报少了几次预测。 |
| 规则代价 | 新增声明/代码量、不可支持的交互、角色可见额外延迟及反例；先定性，不伪造综合评分。 |

加速比使用同规则、同完成条件的 serial 耗时除以候选策略耗时。优先比较配对样本的中位数和范围，保留全部样本；不用最佳单次结果作为代表。采用正确性不由性能阈值抵消，不预设必须达到 2x。

离线可控服务至少覆盖独立延迟、有限并发槽位和共享吞吐限制三种模型，区分调度潜力与后端容量；每项工作的延迟与失败抽样按输入/seed 决定，必要时附输入的逻辑尝试身份，不按请求到达顺序抽取共享随机数。首个微基准建议预热后至少 5 个配对重复；规模、种子、延迟分布和重复数在运行前写入 manifest，可因测量成本调整并说明，不事后挑选有利样本。

真实模型响应可能改变后续工作量。先用固定输入批次探测端点并发能力，再做短应用工作负载；若实际轨迹不同，只报告集成现象和条件化测量，不将其当作轴 A 公平加速比。缓存、连接预热、限流、上下文大小和模型配置均需列明。

## 在线预算与运行边界

2026-11-03 用户已启动 Goal，明确允许真实 LLM 按需使用、不必特别节约，覆盖原方案全研究 24 次的建议上限。仍先离线验证、分批预声明用量并持续留账；不以无限重试或无假设调用消耗资源。

- 先离线通过关键采用/失效检查；首批计划最多 **8 个实际 provider 请求**，后续批次由证据需要决定、运行前明确额度；不设全研究 24 次硬上限。初始每连接最多 **2 个同时在途**，提高并发需有明确实验目标。优先用已有廉价连接；首批探明协议与吞吐后才决定是否继续，不要求花完。
- 同一账本覆盖所有 subagent、策略、失败、纠正、feedback 续调用和取消；开始前由主线程预留额度。排队后未调用可释放预留，已经调用则不返还次数。未知远端结果仍计入，禁止自动无限重试。
- 全研究统一总账保存在 `artifacts/predictive-time-parallelism/online-budget.jsonl`，关联 ResearchId、预算、批次、请求及预留/已调用/未决记录。由协调者在调用前持久记录预留；每批与每次 Goal 续轮先对账。崩溃后的未决预留保守计入，只有证明未调用才释放；已开始研究的总账缺失或不可核对时停止新增在线请求，不重建空账、不换 ResearchId 绕过上限。它只约束实验花费，不是第二份世界/操作恢复日志。
- 每次在线批次固定样本计划、调用上限、宿主 CancellationToken 期限及可用输出限制；不能在 transport 新增 operation/idle timeout。另有金额/token 上限时同样预留或保守限制；缺少 usage/价格时如实说明不能精确保证金额。
- 使用新建实验 home/store，参考实际连接配置及 `atelia-completion/experiments/ToolCallIdMatrix/config.example.json` 的格式；只记录非敏感有效配置。凭据运行时读取，不打印环境变量全表，不写入 Git/fixture/raw 导出报告。
- 每个连接/模型/协议只声称其本次实际验证范围。端点不可用、限流、usage 未知或预算耗尽要记录，不把缓存回放、旧 JSONL 或提前返回的 live 测试称为本次在线成功。
- 达到单批预算后停止该批新增在线调用，分析后按用户已有授权规划必要的下一批并更新总账；若 C6 尚无必需证据仍保留未完成，不把缺失改称负性能结论。

## 实验工件与复现

每个 ExperimentId 在新目录写入：

1. manifest：主仓及相邻 DG/Storage/Completion commit、dirty 状态/补丁标识、SDK/OS、代码与规则指纹、场景与种子、策略、H、并发/预算、计时口径、连接非敏感身份及预定完成条件。
2. 时间线：候选来源 S/预测目标、实际请求与输入指纹、采用边界/原因、所有 provider 调用和实际世界提交；诊断 Sequence 不冒充模拟因果次序。
3. 结果：原始样本、计数/usage、完整性检查、退出码/异常类型、工件哈希和机器可读汇总；失败与废弃不删掉。
4. 报告：假设、命令、预期、实际、支持/反驳、适用范围、未验证项与下一项最小实验。记录实际输入差异及隐式依赖，而不只写“通过”。

文件名和 DTO 可由原型裁决，不先建通用遥测系统。可提交无敏感的人工场景和脚本；完整请求、原始 reasoning、存档与批量日志默认留忽略工件。正文可用必要的短摘录说明结论，避免泄露凭据或把模型思考当角色真实经历。

重跑命令必须能从新目录执行，缺失凭据要明确失败/跳过；离线复现不得隐式联网。报告区分本轮重跑、仅源码审查与历史证据。只改文档检查链接；代码变化按影响运行测试，最后集成按根 README 构建和 Schema Verify，同一可写 dotnet 图串行。
