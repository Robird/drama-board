## 一轮执行

1. A 的真实决策已进入普通 LLM 请求。在来源 world/cursor 对齐、无 pending E 的已提交边界捕获快照；真实请求优先准入，预测准备不能延迟它的发出。
2. 若没有在途候选且预算/配置允许，建立独立内存历史和预测 Kernel。可共享不可变业务图，但预测运行的指标、临时集合、控制器、日志和取消状态不得与真实运行混用。
3. 预测控制器只为当前 A 提供一个合法的假设操作。它按真实规则产生内存事实，不改真实历史，不输出普通角色 history，不调用模型。
4. 在事件步数、模拟时域和墙钟准备上限内推进机械事件，直到下一次真正需要角色输入。OpenContext 的交易维护也在 scratch 中正常执行，不能用只改时间的 Observation 代替。
5. 若下一位是另一个、位于不同场景的 LLM 角色 B，则用普通材料渲染和请求构造取得 B 的首个请求。若仍是 A、遇到 Human、同场景角色或其他不支持情形，首版停止本次预取；不越过这一决策去找更远目标。
6. 发送 B 的一个物理 Completion 请求，保存完整请求、目标身份和响应 Task。取得响应后不交回预测控制器，不执行任何工具或反馈；scratch 推演可以随请求捕获结束而释放。
7. 真实 A 返回后沿原路径提交，真实世界正常推进。到 B 的真实请求边界再比较；匹配则交付已有响应，尚未结束则等待原 Task；不匹配则废弃候选并正常请求。此后工具纠正/反馈续轮仍走实际控制器。
8. 候选采用或废弃后结束该预测代次。下一次普通决策才能再次启动；不从投机结果派生更深的投机链。

捕获快照和启动候选的精确插入点由第一工作包确认。不要为触发预取而新增第二个世界写者，或从仍在构造、尚未发布的 A 事实建立来源。

P0 接线裁决：在实际 `ChooseCommandAsync` 栈内一次性捕获 `history.State/Cursor`，其上层 Kernel 尚在等待 Plan、未发布本步 E；client gate 先调用需求 provider，再推演此快照。采用身份包括预计与实际的 `ContextSequence`、`LastOperationSequence`、角色、时间及运行/分支身份，不要求来源全局 cursor 相等，也不硬编码操作序号为 0。独立普通控制器捕获 B 的首请求后立即退出，不获得物理响应。完整请求首版限定为普通首轮的 Observation、空 Tail 及现有标量工具合同；不支持的形状停止预取，实际需求仍正常执行。

## 默认预测器

首版把“持续当前活动”作为假设，不把它称为保守安全证明。预测成功率只影响浪费率，正确性归实际采用验证。

- 正在活动/移动/跟随且可通过 continue 确认并放行时，预测 continue。
- 空闲且 wait 1 经实际检查合法时，预测 wait 1。
- 其余返回无法预测。不能绕过警告、跟随、活动冲突等校验，不能为了让默认动作合法而篡改世界。
- continue 合法不必然结束当前决策；若之后再次需要 A 输入，首版停止。不要在同一时刻无限确认，也不要无界反复 wait。

第一轮须记录具体上限值及其停止原因；这些是宿主研究策略，不是世界规则或领域持久属性。只有初始数据表明确指出瓶颈后才改预测器，不先设计插件体系。

## 采用合同

采用同时满足：运行/分支代次仍有效、目标角色及决策身份匹配、有效连接/模型/请求选项一致、完整请求原值相等。目标模拟时间若已进入实际模型材料，也必须自然参与比较；另有不可见调度身份则单独验证。

完整请求包括有序 Shared/Tail、system prompt、工具/输出合同、原生 payload 与实际可见身份。规范序列化可用于比较，hash 用于索引和诊断；不凭 Observation、信息集合去重、全局世界版本或“命令仍合法”代替比较。新增请求字段必须纳入审查，未知消息类型失败关闭。

不要求 A 的真实命令等于预测命令，也不要求其他角色状态或全局 cursor 相同。明确验证：预测 A wait、实际 A 在远处执行其他动作，但 B 的完整请求仍相等，缓存可用。

预测操作使用独立身份，不能伪造真实发布地址。若预测操作的 ID 或文本进入 B 请求而真实输入不同，就如实失配；不能为提高命中率删除或重写字段。缓存保存 Completion 的完整交付值，仍按现有 Completed/Incomplete/Failed 合同处理，不能把失败正文转换为成功操作。

采用后创建真实操作，重新做当前世界的命令/权限/警告校验；只使用实际决定上下文的委托。预测世界不安装到真实 history，其操作、E/S、随机游标和派生缓存也不搬运过去。

## 生命周期、预算和记录

用最少状态表达预测目标与物理请求：候选可以已废弃但物理请求仍在途，两者不能合并成一个“已取消”。已调用预算不返还；无法证明远端结果的取消保留 unknown，所有后台结果或异常最终被观察。

全局最多一个额外物理请求，尚未排空的旧请求也占名额。每个实际决定只触发一次；跨工具续轮或再次轮到同角色时不能重复预取同一目标。先保证需求请求准入，不让无效预取无限抢占额度。

沿用实际调用总预算和连接池；审计现有控制器逻辑次数与宿主物理调用计数，避免预取收费一次、采用时又重复计数，也不能让预取绕过上限。复用响应不借用另一个仍在使用的 ToolSession。单次请求期限由宿主 token 控制，不在 transport 添加超时或自动重试。

P0 已确认旧 `MaxCalls` 仅是共享 `LlmDecisionLoop` 的逻辑计数。开启预取时由运行级协调器统一控制物理调用上限，普通 loop 不再以相同额度对采用重复扣账；需求、候选、纠正及反馈续轮都经过物理准入。`LlmRawAudit.RecordLookahead` 以同一写锁记录独立 `lookahead-event`，普通 host/session Trace 仍只由实际串行控制器调用。raw 的物理完成与实际逻辑交付不可相加计算 usage。

P1/P2 的具体取舍：预取仅使用本次运行中已由真实需求解析成功的连接，以配置 connectionId 缓存其 binding；目标连接尚未就绪就跳过。这样不同连接可在各自被实际使用后参与预取，不让投机准备触发慢认证。完成且不再被候选持有的 Task/响应/CTS 在下一服务或调用前观察并释放，不保留全运行响应集合。停止时只取消仍在途请求，并在连接池销毁前观察全部剩余任务。默认推演上限为 128 步、24 模型小时、250ms；墙钟限制为步骤间协作式检查，不能抢占单次同步规则或渲染。

预计请求与真实采用边界分别记录。候选未采用前，其 reasoning/response/假设操作不能进入角色经历；采用时关联既有物理请求，保留实际边界。尽量扩展现有 raw/host 诊断接缝，不建设第二份恢复权威或重复写世界事件。

暂停、EOF、取消、异常和进程冷开要分别定义。正常结束观察/排空本地任务后释放连接，主错与清理错分别保留；进程中断后的物理结果可能未知，冷开不恢复候选、不自动补发。已持久的 pending E 仍只应用保存事实。原有 Human 等待边界不被推演跨越；首版不为 Human 预测并执行真实输入。

## 代码归属与配置

首先在 Playground 宿主层放一个小的预取协调对象，组合预测控制器、内存 Kernel 和 Completion 响应复用。可以在实际需求出现时提取纯推演辅助类；不要先新增程序集或宽泛 public API。

模式属于运行时 home 配置或 CLI 覆盖，沿用现有优先级和严格校验；不入 DurableGraph Schema。首版只需关闭/开启两个模式，数量上限和预测器可以先固定并进入实验 manifest，不必把所有内部常量都暴露为用户选项。最终实际命令和配置示例须在交接时记录。

当前实现为 `--lookahead on|off`，home 的 `playground.json` 顶层字段为 `"lookahead": "on"|"off"`，省略默认为 off，CLI 优先。raw 的 `lookahead-event` 内含种类、运行内单调时间、在途计数及细节；`actual-dispatch` 把真实逻辑 RequestId 与 PhysicalId 关联，采用缓存、协议纠正和反馈续轮分别保留关联。物理 usage 只按 `physical-completed` 统计。累计 Service/Demand/Projection/Comparison/RemainingResponseWait 存在嵌套与并发，不能相加冒充工作墙钟。

## 实验顺序和口径

先离线，再在线。先打通实际运行，再改预测策略。每次更改先声明假设、对照和停止点，保存失败结果；不事后选择有利样本。

| 工作负载 | 必须检验的现象 |
| --- | --- |
| 不同场景、连续活动与错峰决策 | 重复创建/采用候选；预测 A 动作错误但 B 输入相同；未来身体/昼夜/机械状态正确推进。 |
| 通信、共享资产或移动造成材料改变 | 旧响应失效，真实输入重新请求；停止候选不会执行过期动作或 feedback。 |
| 无可用预测 | continue/wait 不合法、下一决策仍为 A、同场景、Human、目标消失、步数/时域到限；正常串行路径可继续。 |
| 协议与退出 | 多轮纠正、feedback、候选先完成/后完成/失败、非协作取消、预算耗尽、冷开及 pending E；日志与物理调用对账。 |

确定性响应按完整有效输入及声明的 seed 寻址，不按全局请求序号发脚本；宿主操作身份需有可审查的稳定分配或一一对应比较，不能抹掉模型可见字段来制造一致。固定初态、游戏规则及有效工作结束条件，比较完整采用输入、操作、事实和最终状态；同 tick 次序不得改变。

性能以常驻宿主连续工作区间为准：初始化、加载和冷开核验分别计时。首次正式矩阵建议低/高耦合各至少五组配对、每 run 至少 16 个有效角色操作，能跨越多个模型时刻并反复创建/回收候选；可基于实际耗时预声明调整并说明。串行/开启策略轮换顺序，从相同独立初态开始，至少比较独立服务容量和共享瓶颈。不要用不同轨迹工作量直接计算公平加速。

记录：有效工作墙钟、角色从真实可服务到获得决定的等待、实际调用数、提前请求采用/废弃、在途峰值、未排空工作、推演步数/时间、请求构造与比较成本、日志/提交开销。分配指标只在可靠边界测量；嵌套或并发累计时间不相加冒充总墙钟。无候选、已完成命中、在途命中分别计数。

真实模型用于验证本阶段实际循环接线及条件化等待，不能用旧八次调用代替。使用独立实验 home/store；真实自由输出可能改变工作量，须分别报告轨迹与条件，不能冒充离线等价。若纯线上时序噪声很大，先解释样本范围，再决定是否值得新增批次。

## 在线预算和来源

用户启动 Goal 时的授权决定是否及如何调用真实模型。本方案建议首批最多 16 个实际 provider 请求（含预取、失败、纠正和反馈续调），最大物理在途 2；后续按证据需要先更新批次计划，再调用，不自动重试或重复成功 smoke。

本专题使用独立 ResearchId 和 `artifacts/playground-speculative-lookahead/online-budget.jsonl`，与已结束的前期研究区分。首次建立时注明旧研究总账与来源；续轮必须对账，不能重建空账绕过未决调用。额度在调用前预留，已调用与不确定结果不返还，未调用额度需证据才能释放。凭据只在运行时读取；未知 usage 保留未知，不补零、也不从无价格依据的 token 数伪造费用。

同一可写构建图的 dotnet 操作由主线程串行调度。最终按根仓约定执行 Release、Schema Verify 和受影响测试，独立代理从新目录重跑代表入口。新分支可以整理本地提交，但最终合并、推送和发布不属于此实验任务。


### Human Console 等待窗口

显式启用 lookahead 时，当前 A 可以是 Human Console；候选 B 仍必须是 scratch 遇到的下一个实际决策角色且绑定 LLM，不跳过 Human、同地或其他不合适角色。预测动作及完整 input、target、binding 三重采用条件不变。Human 新局先行允许在该等待窗口解析 B 的冷连接；LLM A 路径仍仅使用已就绪连接，不新增冷认证等待。

宿主先冻结完成世界并启动真实 Console 读取，再在后台准备 scratch 与冷连接。Human 的操作、EOF、取消或异常结束本次等待后，立即退休准备准入，取消并 join 准备任务，之后才向唯一真实 Kernel 返回；不等待已发出的候选推理。准入同时检查输入任务仍未完成，冷 resolver 迟到不得发请求。忽略取消的 resolver 可能延迟 Human 提交或退出，宿主会等待其返回以保证后台准备不跨越世界提交或与后续需求竞争。取消回调或准备诊断失败仍必须 join，并保留 Human 原失败。

候选物理请求沿宿主取消令牌存活，不能因 Human 正常提交而被取消；它在 Human 等待中只有物理审计数据，不执行反馈工具、不交付角色 history。已有未排空候选仍占唯一额外槽，真实与投机调用统一计入 MaxCalls；快速完成的输入及 EOF 无需启动准备。默认关闭时仍走原 Human 路径。程序化实验继续使用 Host 的 TextReader.ReadLineAsync(CancellationToken) 注入，ServiceCompleted 同时记录成功返回的 Human 服务（包含准备排空时间）。
