## 裁决

可考虑将当前实现作为默认关闭的实验能力合并；不建议默认开启。只有低耦合、完整输入稳定且服务有独立并行容量时，本次固定工作量实验呈现可重复收益。高耦合、共享瓶颈和短服务都有保留的负结果。实际是否合并由后续用户任务决定，本 Goal 不自动执行。

原 G1–G7 没有未完施工工作包。现有能力不改变默认玩法、领域 Schema 或跨仓合同；尚未覆盖的适用范围不伪装成已验证，也不倒过来扩张本次完成条件。

## 重开条件

1. 要扩展首请求缓存形状或升级 Completion 请求字段时，重新审查全量输入合同及失败关闭测试。
2. 要推广预取或调整预测器时，先取得实际容量、失效率、日志与调用耗时证据，再预声明新的同工作量对照；保留失败和负结果。
3. 多分支、影响图、候选持久恢复、改玩法扩大安全窗口或跨仓 API，需要新的明确目标；本轮不预建。
4. 新在线实验使用新预算预留，先核对既有账本，不重建空账、不复用已消费 grant。凭据只在运行时读取，未知 usage/远端结果不补零。

后续研究继续采用有界委派与主线程验收；同一可写构建图的 dotnet 操作串行。原始工件保留在 `artifacts/playground-speculative-lookahead/`，报告中的来源、计量范围和未覆盖项优先于概括性完成表述。
