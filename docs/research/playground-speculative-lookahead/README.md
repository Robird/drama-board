## 目标

在实际 Playground 连续运行中，实现并验证一个小型、可关闭的提前推理能力：A 正在调用 LLM 时，在独立内存世界中预测 A 的一个动作，按真实规则推进到下一位合适角色 B 的决策，提前请求 B 的首个模型响应。真实时间线到达 B 时，完整输入与目标身份匹配才交付该响应，否则正常重新请求。

**不要求猜中 A 的行动，也不要求整个分支状态与真实世界一致。要求的是 B 的完整模型输入和采用身份匹配。** 必须有一个实际反例证明：A 的预测动作与实际动作不同，B 仍可因输入相同而采用。

收益目标是减少连续有效角色决策的等待。正确性、调用浪费与实现复杂度共同决定是否适合合并。允许得到负性能结论；不预设必须实现某个加速倍数，也不以增加并发量本身作为成功。

## 已定范围

- 从实际宿主循环进入，沿用 home、角色控制、连接、日志及恢复入口；运行时显式启用，默认关闭。开关不进入 DurableGraph 领域状态，最终配置拼写由实施时裁决并记录。
- 一条内存预测分支、一个尚未返回角色的假设动作、最多一个额外物理 LLM 请求；一次实际决策至多启动一次预取，不随工具续轮重复启动。
- 首版优先考虑不同场景的其他 LLM 角色；跨场景仅是选择启发式，不是安全证明。同场景、Human 或无法确定地点时可以跳过，不能跳过其真实仲裁位置继续找更远目标。
- 预测器从合法 `continue` 或 `wait 1` 起步；遇到无法放行、未知选择、推演上限就放弃。不为提高命中率修改游戏规则。
- 分支仅构造预计请求。复用模型响应，不安装分支世界、不搬运分支事实、不合并对象图、不重放预测操作。
- 真实世界保持唯一 Kernel 串行发布 E/S；反馈和工具续轮在实际采用后走普通控制器。冷开丢弃候选，pending E 恢复不重问模型。
- 主要改动限本仓 Playground 宿主及必要的关联接缝；不先提取通用调度框架，不新增跨仓公共合同。需要越界时留下具体提案。

不实施多分支搜索、递归投机、世界回滚、分区时钟、候选持久恢复、模型预测器训练或一般影响图系统。后续是否扩大由本阶段实测决定。
