# 自主循环、研究与游玩

本文件规定项目工作方法，不实现 Goal 调度。用户启动持续工作后，Agent 每轮依据[完成条件](README.md)与[工作计划](work-plan.md)自主选择目标，直到条件满足；执行平台的预算、停止与状态规则优先。

## 每轮怎样推进

1. **恢复现场。** 读根 PROJECT-STATE 和专题工作计划，检查 Git、现有实现及最近证据。先接续未完成的集成/验证，避免每轮重新设计整个世界；保留用户及其他会话的改动。
2. **选择一个有价值的结果。** 写清要消解的缺口、关联 C 编号、拟改范围和可观察的完成证据。优先阻塞生活循环、导致误解或使角色无法继续的具体问题，不以文件数量衡量进展。
3. **自主决策与实施。** 能在已定方向内裁决就继续；必要时读源码、研究先例、构造对照或使用有界委派。常规接口和数值不逐项向用户请示。
4. **验证与体验。** 运行适用的工程检查和实际入口；本轮适合时安排模型实验或自由游玩。新失败先判断世界规则、材料、控制器与模型行为的责任边界。
5. **收敛与交接。** 把实际结论写回设计，证据放测试/实验记录，更新剩余工作和下一步，按需提交。局部切片完成后继续未满足的条件，不把轮次结束当作整体完成。

简短轮次记录足够：本轮问题、决定、变化、证据、剩余问题。不要把大量工具输出或讨论过程堆进工作计划。

## 委派与裁决

按需使用 `bounded-delegation`：每个工作包给出目标、写入范围、共享契约和验收证据；独立文件可并行，接口/共享文件变更要协调。同一可写 dotnet 构建图串行执行。主线程复核实际产物和关键运行结果，子代理完成报告不是验收。

重大语义分歧或持续膨胀的方案可使用 `dialectical-simplification`；先阅读当时可用的 skill，尊重其真实要求。不要每轮机械启动多名评审，也不要以等待所有人同意代替主线程裁决。独立审查优先投入到跨模块原子性、信息边界、恢复和关键体验决定。

对于多个合理方案，默认选择较简单、可逆、可验证的一项，记录理由及重开条件。确实需要用户价值判断的问题，记录选项、推荐、代价以及受影响范围；先推进独立工作。不能把偏好不确定当作整个任务停工理由，也不能将未满足的必需条件包装成“留给用户”后宣称完成。

## 借鉴成熟设计

当具体体验问题缺少好方案时，按需查找相似游戏的官方说明、开发者讲述或可核对的实际玩法。先写问题，再提取体验作用，最后选择适合当前世界的最小机制。研究结论保存来源链接，区分来源事实、个人推断和本项目决定。

一个短记录即可：问题 → 参考中的作用 → 本地最小方案 → 成本/边界 → 如何观察效果。无须先完成广泛游戏史调查，不照搬作品的文本/素材，不因参考某作品自动扩大为其完整功能集合。用户提到的三款游戏提供方向，具体机制未经查证不得写成它们的既定设计。

## 两种游玩都值得做

**验收试玩**带着可判定的行为目标进入，验证往返、经济账、忙碌响应或恢复等合同。脚本可提供可重复证据，但要明确人为控制和引导。

**自由游玩**不携带测试清单、固定通关路线或必须触发的合作故事。操作者可以临时产生兴趣、绕路、放弃计划，也可以什么都不修，单纯玩一段。安全与花费预算仍存在，但不预先要求某个游戏结果。

自由游玩期间：

- 使用真实产品入口，只依据角色可见材料行动。操作者知道自己是 Agent，不假装自己拥有真实人类的未知体验；可让未参与本片实现的 Agent 提供较独立视角。
- 不读取隐藏世界状态来优化角色决策，不编辑存档、暗补资源或中途改规则以制造成功。可用终端驱动辅助，但应如实区分临时逐步选择与预编脚本。
- 遇到错误可结束会话并转入诊断；从进入源码/改世界开始标记视角切换。修复后另开会话，不能把被干预的连续轨迹称为纯自由游玩。
- 退出后再记录“当时想做什么、界面让自己如何理解、哪里改变了计划、哪些选择有趣或无意义”。主观体验是线索，确认缺陷仍需证据；没有发现 bug 也是合法结果。

至少保留两次独立开始的自由会话（可同一操作者不同时间，优先不同视角），其中至少一次与两个真实 LLM 角色同局。可与混合控制验收共用一场会话的事实证据，但不能将预先安排的验收脚本重新贴上自由游玩标签。记录仅需足以还原体验的轨迹与反思，不用给每一步补写测试意图。

真实用户未参与时明确写“Coding Agent 操作 Human Console”。本阶段不等待用户本人来填验收缺口，后续人类体验反馈独立保留。

## 模型实验与运行证据

真实调用沿用已有授权和可用连接，凭据只在运行时读取，不写进仓库、日志或实验笔记。每次实验先声明模型、角色控制方式、模拟时长、调用/操作上限与墙钟上限；优先小规模探路，再扩大到 C7 所需的多日运行。不存在无限自动重试或悄悄提高预算的默认授权。

三日运行可以分多次暂停/冷开接续，但必须是同一条世界历史，累计实际推进至少 72h；不得把数个短分叉的时间相加。实现或内容语义改变后，旧证据只能支持未改变部分，受影响场景须复验。预算退出不是世界终局，退出码成功也不证明生活循环完成。

保留来源 commit/工作树说明、内容版本、随机种子、运行命令、模型身份、控制者、预算、停止原因和关键原始轨迹；最终报告明确哪些来自最终构建。统计至少包括调用/操作数量、模拟与墙钟时间、角色基本生存状况、生产消费与资金变动、拒绝/重复行为及开发者干预。不凭字符数推断 token，不把交易金额当作居民福利。

工程检查、离线 Completion fixture、真实模型行为、Agent 自由游玩和真人反馈分别报告。自发行为与提示诱导分开；一次成功不证明普遍合作，一次失败不直接证明规则缺陷。没有可用凭据或外部服务时，继续离线工作并明确在线验收尚未满足，不能编造成功。

## 完成与资料维护

- README 保存稳定愿景与 C1–C8；approach 保存当前设计依据；work-plan 是唯一专题动态施工状态；根 PROJECT-STATE 仅保留方向和入口。
- 专题设计和实验变多时按需增加文件，验收记录建立逐项证据索引；不提前制造大量空文档。已经解决的施工项移出待办，历史通过 Git 和实验材料保存。
- C1–C8 满足后汇总启动方式、实际证据、限制和少量可选决策，结束本阶段；不自动进入新地图、战斗或 Gym 二期。
- 必需条件仍未满足时继续处理，确实无法推进时如实交代具体外部依赖。平台预算耗尽不等于任务完成，平台 Goal 状态遵守其规则，不由文档自行重定义。
