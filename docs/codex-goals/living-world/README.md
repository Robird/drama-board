# 小镇与山野：可持续模拟的小世界

> 历史命名说明：本文保留当时的 ResourceCycle / Cycle 类型、命令与验证记录。当前应用已重命名为 Playground；现行入口与持久身份边界见[重命名说明](../../../docs/implementation/playground-rename.md)。旧名称源码链接固定到重命名前的 Git 版本。

2026-11-01。融合 Microtown 与 ResourceCycle 的本阶段 Goal 已完成 C1–C8，交付可供人类和 LLM 驱动角色生活的连续世界。本目录保留愿景、原定完成条件与实施依据。产品名“山野镇 / Hillside”；证据与使用交接见[阶段验收](acceptance.md)，当前状态统一见[工作计划](work-plan.md)。

## 愿景

小镇附近有山林，角色可以在镇内生活、生产、交换，也可以准备补给、结伴或独自进山，采集、探索、休息后返回。世界没有必须完成的主线，不因抵达某个出口或经过固定天数自动宣告全局结束。角色的行动留下可持续的状态与经历，暂停后可以回来继续。

人类玩家、通过终端操作 Human Console 的 Coding Agent，以及游戏内调用模型的 LLM 控制器，都可以参与这个世界。Human Console 是一种角色操作入口，不限定操作者必须是真人。开发者可以做有目的的验收，也可以暂时放下开发任务，作为玩家进入世界自由行动。

用户以《星露谷物语》的镇内生活、附近山林中的《迷失蔚蓝》式求生，以及未来村外《勇者斗恶龙》式冒险说明体验方向。这些是启发，不意味着复制这些作品、完整移植其机制，或在本阶段加入战斗和剧情。

长期方法是观察角色行为，再调整资源、时间、空间、经济、感知等世界机制，逐步积累可复用能力。角色可以合作，也可以独处；没有自发交易或没有走预定路线都是有效观察，不能靠暗中代操作制造涌现。

## 本阶段交付

交付一个融合后的主要游戏：同一个角色能带着同一身体、背包、资金、目标、探索知识与个人材料往返镇与山，完成重复生活循环。以现有能力为主体，补足融合和实际体验所必需的机制，采用清晰的新游戏身份和名称。

至少提供三角色规模，支持一个 Human Console 角色与至少两个 LLM 角色同局，也支持全 LLM 运行。先让这一级规模可玩、可解释、可恢复；此前讨论的 6–8 人、复杂社会关系和更远地图仍是后续候选。

“可持续”在本阶段指规则允许反复生活、世界不被实验时长强制终结、同版本存档能继续；不承诺无限时间经济稳定、所有角色永远存活或旧版本存档迁移。宿主预算暂停、玩家离开、角色死亡与世界结束应有不同含义。个体结束不应无故结束其他角色的生活；无人可行动时如何停止由实施设计明确。

## 完成条件

以下 C1–C8 是本阶段唯一的完成标准。具体玩法和结构可自主调整；不能通过删除失败项目或把必需项改称延期来宣布完成。证据逐项链接到实现、测试或实验记录，不能只写“已完成”。

| 编号 | 必须形成的结果 | 验收要点 |
| --- | --- | --- |
| C1 连续世界 | 镇与山在同一世界时间、空间与提交边界内，角色可以往返；有唯一推荐的新游戏入口。 | 越过地区边界不换人、不清背包/资金/目标/知识；原出口不再自动退休角色。旧原型最终归档或明确停止独立产品演进，保留必要历史证据。 |
| C2 可重复生活 | 采集、生产、消费、买卖以及居民间赠与/交易形成可执行循环；至少一种山林产物进入镇内生产或经济循环。 | 普通命令跑通两次出行返回及后续生活；资源和资金账可核对。规则不含有限实验天数的强制世界终局，初始平衡允许基本生活，不靠隐藏补给或关闭需求通过。 |
| C3 角色与控制 | Human Console 与 LLM 使用相同领域行动及角色可见材料，至少支持一人类入口＋两模型角色和全模型局。 | 文档说明启动、选择控制角色、暂停与继续；跨进程续局保留身份。可在启动/恢复边界改变控制绑定，运行中热切换不是必需。 |
| C4 可解释的互动 | 保留定向说话、赠与、报价交易、跟随、大喊及忙碌时响应的实际能力。 | 接收消息不悄悄取消活动、改变期限或脱队；个人 Goals/Context 不串人，角色陈述不冒充世界真相，远处话语不自动揭示地图或私有状态。 |
| C5 可靠恢复与观察 | 融合世界通过正常冷开、E-only 恢复、关键竞争/拒绝测试和 Schema Verify；Gym 能观察新游戏。 | pending 不重问控制器或重复结算；验证角色轨迹导出，以及从一个已完成 S 分叉后冷开行动，源分支不变。原生模型会话恢复不在此承诺。 |
| C6 可调整的世界 | 地图、角色初始条件、资源、配方、经济与身体/环境参数具有清晰的内容入口和校验。 | 无需改 Kernel 即可建立并运行一个配置变体；内容身份与存档绑定明确，不能用同一身份悄悄改变旧档语义。不要求热加载、编辑器或新配置语言。 |
| C7 实际运行与游玩 | 自动工程验证之外，完成多日真实模型运行、混合控制试玩和自由游玩。 | 最低实验目标为同一局至少三个模拟日（72h）、至少三名模型角色；另有 Human Console＋至少两个模型角色的实际会话，以及两次各自独立的自由游玩记录。会话可以兼任证据，定义见[推进方法](execution.md)。 |
| C8 可交接与收敛 | 新入口使用说明、实现边界、验收索引和少量剩余决策均清楚。 | 受影响构建/测试通过；完成与未完成分开，已知严重缺陷修复。没有必须由用户现场试玩才能关闭的隐藏依赖，也不以未来玩法无限延长本阶段。 |

实际模型的死亡、亏损和改变计划应如实计入，不要求人人成功；但只有启动、立即全灭、长期原地空转，不能证明 C2/C7。模型自主性是观察对象，不要求用提示词强制完成指定合作故事。有限实验证据不外推成任意模型、任意时长的保证。

## 自主权与边界

- 用户已认可总体融合方向，细节留给 Agent。可自主选择名称、默认地图与数值、合并路径、内部接口、必要重构和内容配置形式；优先简单、可逆且可观察的方案。按需 Git 提交，不自动推送、发布或删除用户存档。
- 没有旧开发档兼容包袱。可以变更 Schema 与游戏身份；拒绝范围必须清楚，实验材料应保留。旧原型的历史验收不自动成为新游戏的验收。
- 模糊之处先调查、讨论或做小实验；常规可逆选择不需要反复询问用户。重大体验分歧附具体选项、推荐和影响，集中留在工作计划；先完成不受影响的部分。
- 战斗、复杂剧情、家庭/声望体系、无限经济平衡、通用记忆/事件平台、并行模型调度、多人联网、GUI 和动态脚本系统不是首版必需。若当前证据暴露阻碍 C1–C8 的问题，可以实施最小修复，不以此为由全面扩张系统。
- 用户本人试玩是后续重要反馈，但本阶段允许 Coding Agent 操作 Human Console 完成入口与体验探索。必须标明操作者，不能宣称获得了真人体验验收，也不能抹去旧项目另行保留的人类合作验收事项。
