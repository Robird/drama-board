# 山野镇实施合同

2026-11-01。产品名 **山野镇 / Hillside**。本文件记录实现选择与切片边界，不单独宣告阶段完成；C1–C8 状态只在[工作计划](work-plan.md)维护。

## 唯一世界与命名

选用 ResourceCycle 为唯一运行时基底，吸收 Microtown 的经济语义。保留已有冻结 Context、身体、探索、跟随和大喊；不把 TownWorld/TownFact.NextBusiness 嵌进 Cycle 世界，也不通过跨世界快照传送角色。

推荐产品入口统一为 `src/ResourceCycle.Cli`，直接演化同一 Program。对玩家显示山野镇 / Hillside，内部项目、namespace 与 `Cycle*` 前缀保留；这不构成另一款产品，也不把机械重命名列为本轮完成条件。若未来因实际工程需求改名，需独立核对程序集、持久 DurableType 身份和 Schema，不能随显示名称顺手替换。

| 职责 | 融合落点 | 迁移合同 |
| --- | --- | --- |
| 角色 | CycleCharacter | 资金、背包、身体、活动、跟随、结束状态保留一份。 |
| 世界 | CycleBusinessState | 经济账、市场、报价集合由同一个事实提交。 |
| 生产 | CycleActivityKind.Produce | 开工原料进入在制品；完成产出和取消退料都须能结算。 |
| 交易 | 游戏内报价规则＋现有个人经历 | 接受时复查双方资产，不建立另一个交互历史或隐式预留机制。 |
| 身体 | CycleSurvival | 保留食物/水/温暖；不迁入小镇第二套 FoodReserve。 |
| 时间/空间 | 既有 Kernel/Spatial | 所有地区同钟同图；跨地区不清身份、状态或探索记录。 |
| 观察 | 冻结 Opening＋Items | 生产、市场和交易要进入同一材料链与校验，不向模型暴露业务根。 |
| 宿主 | 原 ResourceCycle.Cli 演化 | 默认生活世界；--llm 全模型、--human ID 指定一个 Console 角色。 |

Microtown 停止独立产品演进。其源码与测试保留作历史玩法、经济语义和共享模块回归的参照；后续新增玩法与面向玩家的入口只在山野镇推进，不再要求两个产品同步开发。旧 `CreateSurvival` / 采集工厂保留为底层测试夹具，不进入产品模式选择。

当前新局可用 `--content hillside|gentle` 与 `--characters 1|2|3`；省略内容的新局采用 hillside，续局省略内容和人数则沿用保存定义。默认共用 Human Console；`--llm` 控制全体，`--human ID` 指定一个 Console 角色。管理查询不接受这些游戏参数。完整命令见[根 README](../../../README.md)与[Gym 使用说明](../../design/character-gym/usage.md)。

## 第一片：连续地点、默认居民与控制（修订 19 的切片边界）

首片采用 `hillside-v1` 地图与游戏修订 19；当前有效定义和修订由[内容定义](content.md)说明。增加 home、market、workshop 三个庇护地点；保留 road 为镇口，signal 为可停留庇护山站；所有地点均无“抵达后获救离场”规则。正常退休仅由死亡引起，禁止伪造旧 Escaped 状态；旧枚举形状暂留，后续清理。

镇内三条路各 15 分钟，market—road 为 15 分钟，road—camp 为 1 小时；原山路与两条声音连接保留。路的线索可以说明朝小镇方向，不自动授予精确地点观察、远处库存或角色私有信息。

`CreateLivingWorld` 默认 08:00、三居民同处 home，身体为 80/80/80、每人初始 3 食物和 3 水。初始有限资产公开，不在回镇时重新补满。新资源模板集中在 LivingWorldContent；增加市场井台并提高食物/水再生量，为三人提供可重复采集的基础路径。身体速率与天气算法保持现有规则，不以关闭需求通过验收。

首片验收仅覆盖工坊和市场的空间地点；生产、买卖与资金由下述第二片接入，这一历史切片边界不表示当前产品缺少这些能力。

宿主默认 Human Console 控制全部角色；--llm 时全部由模型控制，--human ID 可把任意现存角色交给 Console。绑定是每次运行配置，不属于角色语义记忆。等待输入时世界暂停。--until-hour/--steps 是宿主预算，不写世界终局；已发布 pending 必须恢复，不能为守住宿主上界丢弃既定事件。

混合模式的终端属于 Human 角色视角：不能打印其他角色的私有 Context、Goals、原始工具参数和操作回执。完整审计写入独立宿主证据；全模型观战与角色界面明确区分。

## 第二片：生产、市场与现金

游戏修订 20，沿用 `hillside-v1` 地图。LivingWorld 启用唯一 `CycleEconomyState`（Market/Totals），每居民初始 12 钱。基础无经济夹具保持零资金，经济命令明确拒绝；产品不新增第二运行模式。

`buy` / `sell` 在市场即时结算，`produce` 在工坊开始耗时活动；数量/批次 1–1000。`give <actor> money <amount>` 沿用同地通信额度与唤醒机制，不改变生产或跟随期限。市场每日按有限模板刷新，剩余额度不累积，固定 market owner 管理预测。

生产订单快照记录配方、批次、原料/成品及数量。开工原料进入托管，全部完成后记投入消耗并交付产物；取消和死亡退回完整未完成订单原料。接收物品前分别检查完工与取消的容量。具体配方与价格见[经济合同](economy.md)。

经济和身体变化一起进入冻结材料，只有本人现金可见；市场报价/配方只在相应地点显示。消费校验精确物品增益；Fold 验证每种事实的精确资产变更及合法地点记忆，不以全局守恒替代动作合法性。

## 第三片：居民报价与交付

游戏修订 21，经济根加入 `CycleTradeState`。报价不预留资产，接受时复查双方完整支付额、溢出与生产完成/退料容量；资产双向变化、报价关闭和材料在一个事实中记录。命令和额度见[经济合同](economy.md)。

`trade:{actor}:{context}:{operation}` 保证跨回合身份；固定 trades owner 管理最早期限，同刻到期先于输入。SurvivalFailed 与 WeatherResolved 都关闭新死者相关报价，按幸存参与者合并通知，保持原活动、跟随与提醒。

角色只能看到自己的条款及相关结果，内部交付游标不进入材料。纯候选检查只使用本人可见条件，提交再检查对方资产；失败不给出对方余额。只有真实发布的 Opening 标记交付；后续回收若改变另一方仍打开的 Context，同一事实追加普通观察项，不伪造对方操作或增加其决策代次。

领域、两布局、增量材料与 Completion 已贯通；[交易验收](../../experiments/living-world-trades-acceptance.md)记录工程与实际 Console 证据。

## 经济迁入时必须守住的合同

- 账本增加采集来源 Harvested，否则原 Town 的“初始＋进口＋生产－出口－消费－配方投入”无法解释野外新增物品。死亡角色持有物及在制品的处理同样必须记账。
- 生产开工将投入从背包转到在制品，完成/取消分别验证产出/退料容量。生产期间的买入、赠与、成交不能破坏任一可达结算路径。
- TownFact 的整根替换不迁入；扩展 CycleFact 的明确变化并验证原始命令、参与者、账与无关状态不变。
- 交易通知、成交与过期保留活动期限、跟随和身体参数；终态按角色实际交付后回收，不因时间到就抹掉未读结果。
- 新市场与交易预测需运行中生效。首版可用固定 market/trades owner 维护最早事件；不能只有 Rebuild 才发现新报价过期。
- 价格、物品、配方和内容身份统一绑定；修订 22 的不可变有效定义随 Business 保存，S/E 与分叉核对规范指纹，运行不回退到默认内容。具体入口与边界见[内容定义](content.md)。

## 验证与资料

已有出口测试迁移为活着到达/返回；终态冻结与 E-only 覆盖用真实死亡保留，不能把旧测试直接删除。新增普通命令的镇—山—镇及冷开第二次往返，始终开启需求与天气。控制绑定以真实宿主配合离线 fixture 先验证，再做真实模型实验。

首片工件保存在 `artifacts/living-world-foundation/`；其后的生产、交易、内容与试玩证据分别由[工作计划](work-plan.md)链接到对应验收文档。某个切片的构建、脚本或旧原型成功不能替代 C7 三日模型运行与自由游玩；每项结论必须指向实际执行结果。
