这些问题当前没有外部阻碍，先由实现与试验消解。普通数值、材料排版及局部命名可按证据自主调整。出现需要扩大产品范围或改变已有关键合同的选择时再明确提请用户，同时继续无依赖工作。

下一实验拟定 30h 有限父局，三个居民均由模型独立行动；预算 200 calls / 180 operations / 45 分钟，后续选真实反馈另开最多 12 calls / 10 operations 的子局。准备稿与未执行的单次运行脚本在 `artifacts/microtown-economic-day/`；启动前核对当前 DLL 并向用户说明预算，不自动续局扩大限额。记录生产、消费、进出口、社交与报价机会、hour 24 更新及终点；初始储备可能足够活过 30h，不能只凭存活证明经营覆盖。允许有效失败，但调用预算暂停、全灭后系统空转到终点都不能冒充完整生活体验。模型未自然覆盖的能力如实记录，再依据证据选择后续实验或改进。移动中响应/取消保持延期。

## 每轮维护方式

1. 选一个问题或紧密相关的小切片，写清输出、文件所有权、共享契约与退出证据，再实施。适合委派时使用有界工作包；主线程复核源码、测试及运行材料，不能只收成功报告。
2. 根据证据更新 design.md。已解决问题从表中移除，结论进入设计、代码和测试，不积累讨论日志；未解决项补真实阻碍和下一项最小验证。
3. 同步“当前下一步”和切片状态。PROJECT-STATE 只在焦点或能力边界变化时更新，不复制任务表；细节证据放 tests、docs/experiments 和 Git。
4. 先确认是否属于本目标。增强提案超出有限小镇与双游戏复用时转入延期，不靠“以后也能复用”扩大工作量。
5. 每片按影响面构建/测试；持久化改动验证 Schema 与真实磁盘恢复，交互改动用实际 Console/模型试玩。通过后只因新变化、失败或未解风险扩大测试。
6. 真实模型前说明本次实验长度、调用预算、要观察的路径与停止条件，保留配置和原始材料；模型停滞、明确提示、脚本介入和实际完成分开记录。预算结束是暂停，不是验收完成。

当 README 所有完成条件有证据且没有必要剩余项时结束 Goal。回填使用说明、共享模块/消费者映射和验收报告，再将本文件改为完成态；不自动开始 Gym 二期或第三款游戏。
