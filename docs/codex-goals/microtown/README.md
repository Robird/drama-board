# 微型小镇与多游戏共享代码库

状态：2026-10-31，本里程碑已完成，见[六项条件总验收](../../experiments/microtown-acceptance.md)与[真实模型试玩](../../experiments/microtown-playtest.md)。三居民完成 30h 经济日及市场刷新，另有精确反馈分叉和有引导的社会交易；后两段因预算暂停，不作为完整终局。本目录保留愿景、范围和实施依据；后续重开条件见[工作计划](work-plan.md)。

## 愿景与本轮意义

长期建设一组具有不同规则和生活体验的虚拟环境，让 LLM 驱动的角色在其中独立行动、规划、交流和协作。每增加一款游戏，就从已有实现中提炼经实际使用验证的共享机制、组件和内容构造代码，再为新玩法补充必要能力，逐渐积累丰富的多游戏共享代码库。

这类似“多张地图共用基础代码与素材库”的开发方式；这里优先采用普通 C# 模块、对象图工厂与显式组合，不要求地图编辑器 GUI、配置语言或动态插件系统。

本轮以**第二款独立游戏：微型小镇**为实际消费者。居民从外界购买部分原料，生产多种商品，消费、交换并向外出售；角色有各自的生活需要与目标。开发者能观察小镇总体经济与处境最差居民的状况。它应有自己的规则组合、内容、结束条件和存档身份，不能只是山林求生更换地名。

同时保留山林求生的可玩性与 Gym 能力。共享代码应由两款游戏实际使用，而不是复制旧实现、批量改名，或只把旧游戏移入名为 Common 的程序集。

## 持续扩充的工作思路

每款新游戏同时承担两个职责：提供一种值得体验和观察的角色生活环境，以及检验已有代码的组合能力。共享库的丰富程度由实际可复用的能力衡量，不以程序集数量、接口数量或迁移代码量衡量。

本轮按“玩法需要 → 查找已有能力 → 复用或必要重构 → 补充新规则 → 两游戏验证”的顺序推进。能直接使用的模块直接使用；相似代码先核对规则、状态所有权和失败语义，再决定提取；只服务小镇的新机制先留在游戏层。提取后的组件管理自己的局部规则，游戏组合仍负责跨组件效果和单根发布。

普通数值、配方、地图与代码组织属于可调整的实验选择。每个切片留下可运行结果、边界说明及验收证据，并根据试玩反馈修订下一步。不要求先穷尽设计问题；也不将尚未证实的抽象固定为后续所有游戏必须遵守的平台契约。

[新增游戏接线说明](../../implementation/adding-a-game.md)记录两款游戏已核对的实际调用点：如何组装初始世界，接入时间/空间与组件，形成角色材料，绑定控制器，保存和恢复，并接入 Gym。说明应引用两个现有消费者，指出游戏仍需自行提供的规则；第三款游戏出现后再检验这条路径，必要时继续调整。

## 本轮完成条件

1. **独立、可运行的小镇。** 默认三个角色，普通情况下均由真实 LLM 独立决策；支持有限游戏日的实验与明确结束/暂停，Console 能旁观和提供必要的人类调试接管。居民可以采购、耗时生产至少两种有用途的商品、消费、向外出售，并通过交流及物品/货币交换互动。具体数量、配方、地图与初始目标可按证据调整。
2. **真实的多游戏复用。** 山林求生与小镇共同使用经提取的组件及运行设施。至少交付共享的目标管理能力、控制器调用/反馈流程和 Gym 记录能力，并解决所需的 Context/呈现与存档适配边界；不强制所有观察类型或世界根相同。列出共享模块、两个实际调用点及保留在游戏层的职责。
3. **经济可核对。** 输出生产/消耗/库存、进出口/资金流，以及每个居民的基本生活状况和最差值；明确单位、统计区间、边界和失败居民的计入方式。不能把现金流当作福利或把任意标价库存当成可兑现收入。
4. **可恢复与可分叉。** 小镇支持保存、正常冷开与 pending E 恢复。每个角色可导出轨迹、提交反馈，从支持的决定前完成 S 分叉并重新行动。游戏选择、版本与分支身份不能串档；源分支和其他角色的私有材料不被污染。
5. **工程与实际体验均有证据。** 确定性脚本跑通完整经济循环与账实核对，测试拒绝/竞争/中断恢复；独立真实模型试玩覆盖多个居民、至少一个完整经济日及一次外界补货/需求更新，达到事先声明的有限实验终点。实际完成反馈→定位→fork→冷开合法行动；失败与提示引导如实记录。保留原始输入、输出、配置和结果，主线程复核，不以构建或 subagent 报告替代验收。
6. **旧游戏保持成立。** 受影响的山林求生行为、角色信息隔离、Context、目标与 Gym 恢复通过回归；提供新的启动/接线说明与新增游戏的最小开发路径。更改表示时明确支持范围，不能默默以新游戏规则打开旧存档。

无需证明 LLM 达到最优经营、人人富裕或某项改动提高了得分；有效失败也是环境产物，但仅有启动后立即停滞不算完成玩法验收。若真实模型始终无法展开基本经营，应先检查材料、可行动性及初始平衡，再记录模型限制。

## 范围外与重开条件

本轮处于 Character Gym 一期之后、二期闭环改进之前。评估反馈、自动生成改进、A/B 收益证明、批量统计、多模型排名仍留二期。周期性的价格/流行信息是可选增强，不得阻塞完成。

不要求战斗、复杂故事、银行/信贷、订单簿、动态定价、税收、复杂家庭关系、无限时间经济稳定或第三款游戏。也不要求万能世界根、通用 ECS/事件总线、动态 mod 加载、并行模型调用、完整原生工具会话恢复、全历史存档兼容。

新规则先完成本游戏需要；明确的共性可以直接抽取，尚不清楚的部分留在小镇。未来其他游戏出现真实需求时再扩展，避免为了“丰富共享库”无限延长本 Goal。
