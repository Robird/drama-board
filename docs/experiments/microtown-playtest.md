# 小镇真实模型经济日与反馈分叉试玩

> 历史记录：Microtown 源码、测试和 smoke 已于 2026-11-02 从主线移除，见 [Git tag 归档](../archive/microtown.md)。本文命令、实现状态和测试结果属于当时版本。

2026-10-31，在 `d5a9b89` 的小镇 GameRevision 3 上运行。三个居民均由真实 `gpt-6.1-sol` 控制，使用产品 CLI、共享 Completion/Gym 和真实 DG 存档；Coding Agent 负责启动及核验，没有替居民输入游戏命令。构建后固定程序集哈希，三段模型运行之间没有修改生产代码。

本报告区分完整经济日、精确反馈分叉和有引导的社会实验。它不证明模型最优经营、自发合作或某次修改提高得分；Character Gym 二期的自动闭环仍未启动。

## 预算、控制与原始材料

事先声明父局 30h、最多 200 calls / 180 operations / 45 分钟；反馈子局另限 12 calls / 10 operations / 10 分钟。观察到父局没有居民交互后，另声明社会子局 20 calls / 15 operations / 10 分钟。运行器只启动一次，不自动重试、续预算或代选行动，支持 STOP/墙钟中断；本次均正常退出，没有人工中断。

| 运行 | 实际调用 / 操作 | 游戏时间与停止原因 | 墙钟约值 |
| --- | --- | --- | --- |
| 父局 | 82 / 81，全部操作成功 | 0→30h，实验自然结束；24h 市场刷新一次 | 389 秒 |
| 反馈子局 | 11 / 10，全部操作成功 | 从 0h 精确前态重新行动，因操作预算暂停，仍为 0h | 43 秒 |
| 社会子局 | 15 / 15，全部操作成功 | 从 13h 前态推进至 24.5h，因操作预算暂停 | 120 秒 |

共 **108 次真实模型调用、106 次成功游戏操作**。两个子局退出码都是 0，但都不是游戏完成；以 `[Host]` 原因、领域 Ended/Time 和 `run-end` 判断。其中两次模型响应调用反馈工具，其余 106 次产生游戏操作。

本地原始材料保存在 `artifacts/microtown-economic-day/`：

- `PLAN.md`、`run-parent.ps1`、`run-existing.ps1`、各局原样实验 note、argv/预算/程序集 SHA256/UTC 起止/退出记录。
- `run-001/evidence/`：父局独立 stdout/stderr、各阶段完整 Gym JSONL 快照、三分支元数据、每分支三个角色的 Markdown 导出、实际领域审计 JSON；真实存档在 `run-001/store/`。
- `feedback-child/`、`social-child/`：子进程原始输出与运行配置；`social-child/review/` 和 `run-001/review/` 保存独立核验及统计脚本。
- `audit/`：只读领域核验小工具源码及构建日志；从游戏 E/S 而非 Gym 发现操作，验证账本与完成回执，并对每次读取前后的所有分支 head、存档文件 SHA256 作相等检查。

凭据仅通过 auth-file provider 使用，没有复制、打印或哈希凭据内容。实验指令明确标为开发者介入，不是世界事实或角色记忆。父局 note 鼓励自主经营，并邀请 a 首次查看真实界面后提交有依据的反馈，不指定配方顺序、角色职业或交易价格。

## 真实反馈与精确分叉

a 的首条反馈请求显示“所选生产批数在饥饿前、实验终点前完成的上限”。它承认当前 UI 已显示单批预测和多批公式，要求减少人工计算，而不是声称这些信息不存在。当前合法批数范围也不等于生存推荐范围。这是一条有实际材料依据的 feature request，非已证实缺陷；未在本轮加入自动批量建议器。

| --- | --- |
| 父分支 | `11427551` |
| 反馈 | `2011a23a2f464c828407e315552c7e8d` |
| 源请求 | `d873c425502a4ea2858c965925cfe83c`，Gym seq 8 |

通过产品 `--gym-fork` 创建子分支，随后另进程 `--branch ... --llm --feedback` 冷开。第一次请求的 ModelId、SystemPrompt、OutputContract、Shared 与源请求的保存投影相同，原生 Tail 均为空；请求 ID 是新的。子局重新提交的一条反馈也是新模型调用，不是重放父局工具历史。

三角色都进行了新的成功操作，包括采购、进食与移动。独立 verifier 实际核对了完整 Gym 哈希链、反馈对应的真实 tool call、源边界、精确 fork、10 条操作的 response/回执身份，以及实际领域 E/S 提交 ID。父 head 未变，三个角色导出不包含源请求之后的父未来或其他居民私有记录。详见 `verification-feedback-fork.json` 与 `verification-feedback-fork-domain.json`。

这里证明的是完成 S 边界的世界恢复和重新行动；不是 HTTP 请求字节级相同、原生模型会话恢复，或子局已完成经济日。

## 有引导的社会分叉

另从父局 c 的真实请求 `20820345ff0f44d1aeccec814a2ca078`（seq 408、13h、S `114275510e0000a037000000`）使用 `--gym-fork-request` 创建 `13427551`，继承证据截止 seq 407。当时市场售罄，c 可见自己钱多、饭少，附近居民正在等待；实验指令仅邀请 c 自行判断是否探索一次互惠交易。没有告诉模型其他人的余额/库存，没有指定交易对象、价格或强制成交。

实际模型操作：c 提出 `offer a money 4 meal 1 1`，a 在等待期间得到响应机会并执行 `accept trade:c:14`。一次提交中 a 的钱 28→32、饭 3→2；c 的钱 50→46、饭 1→2，双方资产守恒。c 随后 `wait 11`，a 执行 `continue`，保留原等待至 24h 的截止。它们之后继续自己的经营。

独立领域核验逐条读取转换前 S、事实 E 与完成 S：a 的 Wait 活动 ID 始终为 5，DueTicks 为 86400000；报价将 NeedsResponse 置为 true，接受保持，continue 才清除。外部收支不因居民交易增加。原始转换见 `domain-social-transitions.json`，分叉/回执核对见 `verification-social-fork.json`，独立逐项检查见 `social-child/review/transitions-checks.json`。

这证明模型能理解报价、忙碌时接受和继续原活动；由于有明确探索提示，**不宣称自发合作**。父局自然运行没有产生居民交换，两段证据分别保留。

24h 时 c 再提出 `trade:c:16`（饭 1 换钱 5），未遵守“最多探索一次”的实验提示。此时此前成交终态已按合同回收，Goals 仍为空，观察不再提供那次交易，且开发提示仍在每次请求重复。证据说明跨回合记忆不足可能影响一次性意图的遵守，但无法唯一归因，也不是双边结算错误。第二份报价在预算暂停时仍有效；没有擅自替另一位角色接受或取消。

社会子局停止于 24.5h，S `134275510e0000f811000000`，没有 pending，完整历史有 46 条继承操作和 15 条新操作。它是交互覆盖探针，不替代父局完整经济日。父分支及反馈子分支 head 不变，父三角色重新导出的 SHA256 与原导出相同。

## 体验结论与限制

核心经营、时间推进、两个商品、补货、真实反馈及分叉可用；引导式社会探针也能触发实际成交和忙碌响应。剩余观察不作为本里程碑必做的新系统：

- 当前只有整数小时 `wait`，移动可落在四分之一小时；b 在 23.5h 无法精确等待到 24h 刷新。这是可表达性限制，不是隐式时间偏移。
- 常驻 Goals 教程及规则占用较多材料；样本中 Goals 教程约 2,279 字符，完整 Shared 约 11–13k 字符。没有观察到由此导致的错误，不把字符数直接当 token 数或性能结论。
- 部分阻因有双句点，属于轻微文本问题。合法批数、饥饿安全批数和有限终点内批数值得后续比较更紧凑的展示。
- 本轮没有真实模型的自由对话、赠与、Goals 编辑、拒绝报价、撤回或取消活动证据；这些能力由领域测试及 Human Console 证据支撑。单次实验不代表任意模型/提示词的可靠性。
- 报价的可靠终态交付不等于交易历史记忆。后续若研究长期承诺与重复行为，应结合角色 Context/Goals 或结构化经历召回设计；不把开发者实验 note 当作持久记忆补丁。

本片没有修改生产规则或通过脚本替模型选行动。最终里程碑条件及分层交付对照见[总验收](microtown-acceptance.md)。
