# 研发计划 003:Kernel 攻击性评审(2026-08-16)

> **来源**:WP8 完成后、WP9 设计前,由异构高推理模型(Claude Opus 5)对 D1–D9 + 全部 Kernel/Protocol 源码做的 adversarial review("Assume this architecture is wrong")。
> **主线裁决**(2026-08-16):
> - **已修**(同日 commit `40d70c5`):A5 的 journal 严格递增、A6 活锁预算(同刻 resolve 预算,默认 10_000)、A7 EventKind 按 Id 路由 + EventKindRegistry + 撞名修复(`interrupted-mining.*` 独立命名空间)、A10 变异探针测试。
> - **进 WP9 规格**:A1+A2(显式输入端口 + SimulationCursor 可暂停恢复 + StopReason + "切 N 段==一次跑完" property)、A3(WorldVersion = LineageId + LogicalTimestamp,Protocol 补 Microstep/LineageId 字段)、A4 的身份部分(SourceId 由世界持久身份派生)。
> - **推迟到 WP10 前**:A4 的争抢仲裁剥离、A8(RNG 坐标纪律)、A9(system 静态集合 → 无状态规则 + 实体身份)。
> - A5 的 provenance(事件带 Cause + resolve 批次)与 μ 相位问题:envelope 变更在 WP11 落盘前完成,记入 WP11 前置检查。

以下为评审报告原文。

---

## A1 — 外部输入没有入口:D2 的"事件链是 replay authority"今天就不成立

**Scenario**:把 ForkHarnessTests 的 `CreateSystems(includeAlice: false)` 换成 `true`,同一段 journal 前缀能重放出两条完全不同的世界线——分支由 C# 构造参数决定,journal 里没有任何痕迹。

**Invariant violated**:D1「所有非确定性(随机、玩家决策、外部输入)必须显式作为输入进入 Kernel」;D2「唯一真理源是 DomainEvent 序列(加初始状态与显式输入)」。代码事实:事件的唯一来源是 SimulationLoop 的 `owners[...].Resolve(...)`;外部输入的唯一载体是 system 构造参数。ReplayHarness 的 Fork 必须额外接收 `systems` 才能重放,这就是证据。

**Root architectural weakness**:Kernel 只有"世界→候选→事件"的内生闭环,没有"外部→事件"的注入通道;D9 又封死了绕过 Resolve 写 world 的路径。于是 WP9 的 PlayerDecision 只剩两条出路,两条都破约:Host 直接 append journal 并自行 fold(第二条状态写入通道,破 D9);或把 decision 塞进 TWorld 让伪 system 读取(但 TWorld 只能由已提交事件产生,鸡生蛋)。

**Minimal repair**:给 `Run` 增加一个"本轮已就绪的外部输入"参数(有序、带落点意图),由 Loop 在时间推进点将其作为事件提交(`player.decided` / `external.input`),走同一个 reducer。Loop 从闭环变成"闭环 + 单一显式输入端口",输入本身入 journal;system 集合退化为纯规则表,replay 只需 (initialWorld, journal)。

**Cost-of-delay**:**高**。WP9 会以最省事的形式(Host 侧直接 append)落地,WP10 FirstBoard 录下的第一批轨迹就是"不可独立重放的历史"。

---

## A2 — Kernel 没有"停在决策点"的语义,Run 不可中断也不可恢复

**Scenario**:WP9 要在 DecisionPoint 暂停。Host 让 SimulationLoop.Run 返回的手段只有 `until` 时间边界或抛异常,而决策点是事件条件、不是时间条件。

**Invariant violated**:003 §3 的循环含 `DecisionPoint? → ask Players → loop`;002 §9 要求 Host 判断"世界是否仍处于该决策成立的前提"。SimulationRunResult 只有 World/CurrentTime/两个计数——没有 StopReason,Host 连"队列耗尽"和"到达边界"都区分不了。

**Root architectural weakness**:整轮循环状态在栈上:`now / world / lastCommittedTimestamp / lastResolvedCandidate / lastResolveProducedNoEvents`。Run 返回即丢失,重进只能从 journal 尾部部分重建 timestamp,防死循环守卫状态**无法**重建。

**Minimal repair**:(a) Run 返回 StopReason(Exhausted / BoundaryReached / DecisionRequired)+ 触发因;(b) 抽出显式 `SimulationCursor` 承载上述状态,作为 Run 的入参与出参。随之得到一条极强的 property:**把一次 Run 切成 N 段,结果必须与一次跑完逐字节相同**。

**Cost-of-delay**:**高**。这是 Kernel/Host 分界的第一次真实检验。若 WP9 用"每个决策点新建一次 Run"绕过,切分等价性从此没被测过。

---

## A3 — "世界版本"在 Kernel 里没有对应物,且 Protocol 的版本比 Kernel 自己的因果序更粗

**Scenario**:Alice 与 Bob 在同一 ModelTime 各拿到 DecisionRequest。Alice 的决策先 resolve 并改变世界(同刻顺序 Resolve + 因果穿透)。Bob 的迟到决策回来时 `BasedOnWorldVersion` 与 `ModelTimeMs` **完全没变** → Host 判定"未过期" → 提交一个前提已被推翻的决策。

**Invariant violated**:002 §9「Host 可以判断世界是否仍处于该决策成立的前提 / Decision 是否过期」。DecisionRequest.BasedOnWorldVersion 是裸 `long`,Kernel 中**没有任何生产者**;Observation 只有 `ModelTimeMs`,没有 Microstep——而 Kernel 的总序恰是 `LogicalTimestamp = (ModelTime, Microstep)`。

**Root architectural weakness**:版本语义在 Protocol 层先占了个坑,Kernel 侧从未定义它是什么。更糟的是 fork 是一等公民:两条分支各自 version = N+1,纯标量无法区分谱系,A 分支的决策可以"合法"打进 B 分支。

**Minimal repair**:定义 `WorldVersion := (LineageId, LogicalTimestamp)`(或 LineageId + journal 长度),由 Loop 生成;Observation / DecisionRequest / PlayerDecision 同时携带 Microstep 与 LineageId;Kernel 提供"该版本是否仍是当前分支前缀"的判定谓词。

**Cost-of-delay**:**中高**。现在是 4 个 record 加 2 个字段;WP10 之后 = 已录轨迹作废或需要 upcaster。

---

## A4 — 同刻仲裁是固定全局优先级,而 SourceId 没有所有者、没有稳定性契约

**Scenario 4a**:Alice 与 Bob 同一毫秒抢同一件物品。CandidateComparer 按 (Due, SourceId, Id) 全序,SourceId 小者恒胜;而 SourceId 小只是因为它在 Host 里先被 new 出来。"谁先出生谁永远抢赢"成了事实上的世界规则。

**Scenario 4b**:SourceId 分配策略一变(角色重排、fork 后重建 system、存档加载 spawn 顺序不同)→ tie-break 改变。由于同刻是**顺序 Resolve + 因果穿透**,第一个 resolve 会改变后续 forecast——**顺序改变会改变结果本身,不只是顺序**。

**Invariant violated**:003 §11「不能依赖 PriorityQueue 插入顺序」的实质精神。现在改为依赖一个同样脆弱、且**无人负责**的数字:Kernel 里没有任何地方规定 SourceId 从哪来、必须稳定、必须绑定世界持久身份。

**Root architectural weakness**:把"确定性 tie-break"和"游戏内争抢仲裁"压进了同一个字段,而该字段是宿主构造顺序的副产品。附带发现:ForecastQueue.InvalidateSource 与 EventCandidate.Generation 在 Loop 中**完全未被使用**(每轮新建 queue,generation floor 恒空),Generation 目前是"文档承诺、Kernel 零强制、各 system 自己在 Resolve 里手工校验"的假承诺字段。

**Minimal repair**:(1) SourceId 必须由世界持久身份派生(actor/activity 稳定 id),写成正式决策;(2) 把"同刻争抢"从 tie-break 剥离——同刻竞争同一资源应产生显式 contention 事件,或用 (worldSeed, LogicalTimestamp) 派生的确定性随机仲裁,(SourceId, CandidateId) 只作最终兜底;(3) 要么让 Loop 真用 Generation 失效路径,要么删掉它。

**Cost-of-delay**:**高**。WP10 立刻会遇到同秒争抢,那时 tie-break 已被玩具模型当隐式规则依赖。

---

## A5 — 事件没有 provenance,Resolve 不原子,fork 可切在半个 resolve 中间

**Scenario**:一次 Resolve 返回 3 个事件 → μ0/μ1/μ2。`ReplayHarness.Fork(eventCount = k)` 在 μ1 后截断,forkTime 取 prefix 末事件的 ModelTime。得到的 forkWorld 是循环从未观察过的撕裂中间态,resolve 的后半截永远丢失,系统随即在这个态上重 forecast。

**Invariant violated**:D2「Fork 语义必须按 (ModelTime, Microstep) 事件边界定义」。但 DomainEvent 只有 (Timestamp, Kind, Payload)——没有任何字段说明它属于哪次 Resolve、由哪个候选引起。003 §17 要求 journal 能回答"为什么 Alice 在 09:22 获得 DecisionPoint / 哪个 Forecast 因何失效",现在答不了。附加缺口(已修):InMemoryJournal.Append 允许相同 LogicalTimestamp 重复。

**Root architectural weakness**:D9 定 envelope 时只回答了"是什么事件",没回答"因何而来"。Microstep 也只是同刻递增计数器,不是 003 §11 设想的 μ 相位(μ0 scheduled / μ1 consequences / μ3 perception / μ4 decision)——将来引入相位会改变所有已录 journal 中 μ 的含义。

**Minimal repair**:envelope 增加 `Cause = (SourceId, CandidateId, Due)` 与 resolve 批次序号;journal 把 `<` 收紧为 `<=`(**已修**);Fork API 只接受 resolve 边界并用批次号断言。若确定要做 μ 相位,现在就把 Microstep 拆成 (Phase, Ordinal)。

**Cost-of-delay**:**中高**。envelope 现在字段少、调用点集中;WP11 落盘后改 envelope = 版本升级 + upcaster + 全历史迁移。

---

## A6 — 产生事件的同刻活锁完全无保护;no-op 守卫可被绕过(已修)

**Scenario 6a(绕过)**:两个 no-op 候选 A、B 同刻交替成为 next——守卫只比较紧邻上一次,交替永不触发 → 无限循环无诊断。
**Scenario 6b(绕过)**:WP9 每个决策点退出重进 Run,守卫是栈上局部量,跨 Run 必然重置。
**Scenario 6c(管不着)**:任何 `Due == now` 且每次都产出事件的系统 → 模型时间冻结直到 Microstep 溢出。
**Scenario 6d(饥饿)**:系统 forecast `now + delay` 而非从持久锚点计算 → Due 被无限推后,永不发生。

**修复状态**:6a/6c 已修(同刻 resolve 预算);6b 待 WP9 的 cursor 承载预算状态;6d 的"候选 Due 只能由世界状态决定、不得依赖 now"契约 property 待补(记入 WP9/WP10 前置)。

## A7 — EventKind.Version 参与相等 + Kind 无注册表已撞名(已修)

**修复状态**:reducer 一律按 `Kind.Id` 路由;EventKindRegistry 注册 kind↔payload 类型、重复 Id 抛异常;撞名改 `interrupted-mining.mineral-discovered` 独立命名空间;同 Id 不同 Version 路由到同一分支的回归测试已加。Version 下沉到 codec envelope 的完整方案留给 WP11。

## A8 — RNG 坐标除 worldSeed 外全是宿主自由约定,且不入 journal

**Scenario**:生产中若按 spawn 序号或对象哈希分配 streamId,fork 后以不同顺序重建实体 → 同一世界前缀采出不同随机数。generation 由各 system 自选:activity 被打断后重启却不推进 generation → 同坐标复采出同一延迟;为"重掷"把 now 折进 generation → forecast 不稳定。

**Minimal repair**:规定 streamId 只能由世界内持久 id 派生(禁止字面量/构造序号);generation 正式定义为"该流的重采样代数,必须由已提交事件推进";随机产生的事件在 payload/envelope 携带采样坐标,使 replay 可**校验**而不只是可复现。

**Cost-of-delay**:**中**。FirstBoard 多角色多 activity 后,坐标冲突表现为"两个角色运气完全相关"这类极难定位的 bug。**裁决:WP10 前做。**

---

## A9 — 系统集合在 Run 期间不可变:生成/死亡/入场无处安放

**Root architectural weakness**:"system"同时承担三个角色——规则代码、forecast 单元、身份(SourceId)。前者天然静态,后两者天然动态。

**Minimal repair**:把身份从 system 摘下来——system 变成无状态规则,对世界中的实体集合 forecast,候选携带由 EntityId 派生的 SourceId;实体生死只是世界状态变化,全量重 forecast 自然处理。这同时修掉 A4 的稳定性问题。

**Cost-of-delay**:**中**。**裁决:WP10 前与 A4 合并处理。**

---

## A10 — TWorld 的不可变性是承重却未强制的假设(已修)

**修复状态**:快照留存测试 + fork 前缀 fold 契约测试已加(WorldSnapshotContractTests)。

## 未成立的攻击(架构已防御)

| 攻击 | 防御点 |
|---|---|
| 同时事件依赖插入顺序/系统注册顺序 | ForecastQueue 全序 + SameTimeSemanticsTests 的 reverseSystems 用例(残留问题在 A4) |
| Forecast 被改道后仍生效 | 每次 resolve 后全量重 forecast;property 锁定"被改道的到达事件永不提交" |
| 陈旧候选被 resolve | 单次 Run 内结构上不可能(跨 Run 边界见 A2) |
| Observation 构造到一半世界变了 | Loop 单线程、world 按值传递(前提是 A10 成立——已加探针) |
| Speculative 结果偷偷写进 Journal | journal 唯一写入者是 Loop(提交判定键缺口见 A3/A5) |
| Forecast 泄漏给 Player | 候选队列不出 Loop;Observation 无未来字段 |
| Journal 时间倒流 | 拒绝倒序 + property 锁定(等号缺口已修) |
| Forecast 连续 invalidation 重算风暴 | 全量重 forecast 是 O(systems) 纯函数,无累积状态 |

## Top-3:WP9 设计中必须直接解决

1. **A1 + A2(同一件事):给 Kernel 加"显式输入端口 + 可暂停可恢复的游标"。** PlayerDecision 必须作为显式输入进 Loop、作为事件落 journal;Run 必须能因"需要决策"而返回并被无损恢复,并用"切 N 段 == 一次跑完"的 property 钉死。
2. **A3:定义 WorldVersion 的真实对应物,把 Microstep 与 LineageId 补进 Protocol。** 迟到决策判定、并行 AI Player、speculative 提交判定共用同一个谓词。
3. **A4(含 A9 的身份部分):SourceId 从"构造顺序副产品"改为"世界持久身份派生",并把同刻争抢从 tie-break 剥离。**

顺手做掉的低成本项(**已全部完成**):A6 活锁预算、A5 journal 严格递增、A7 Kind 路由与注册表、A10 变异探针。
