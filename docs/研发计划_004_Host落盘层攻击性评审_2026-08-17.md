# 研发计划 004:Host/Protocol/落盘层攻击性评审(2026-08-17)

> **来源**:WP0–WP11 全部完成后(159 测试绿),第二次 adversarial review(Claude Opus 5),攻击对象为 Kernel 之上的 Host/Protocol/Journal.Atelia/FirstBoard 与整体组合。第一次评审(研发计划_003)的 A1–A10 已全部修复,本次不重复。
> **主线裁决(2026-08-17)**:Top-3 修复组 + S8 作为第二阶段(AI Player)前的**必修门槛**,按下列顺序执行:
> 1. **修复组 α(S1+S2+S13)**:感知/反馈闭环——affordance 从角色信念计算(禁读全局 world flag)、拒绝成为角色可感知事实(KnownFact + DecisionReasons.ActionRejected + 回带上次 Intent)、物品可见性区分 placed/carried。全在 FirstBoard 装配层 + Protocol 小改。
> 2. **修复组 β(S4+S3+S5)**:Host 决策生命周期状态机——pending 决策提升为会话显式状态(三态 Open/Answered/Invalidated,进 Result);同刻决策屏障(一次 Resolve 发出该时刻全部决策请求,Host 整批回应整批提交——A4 仲裁路径重新可达,消除"低 Id 恒先手";同时修 S5 的会话级切分不等价)。
> 3. **修复组 γ(S6+S7+S8)**:持久化契约补完——lineage.created 元事件、批次完整性标记(envelope 加 batchIndex/batchCount 或 AppendBatch)、SimulationCursor 可序列化快照、反序列化委托收 EventKind + envelope 加 codec 标识、**FirstBoard 完整一局真落盘作为验收**。
> 4. **速修组 δ(S11+S14+S9+S10+S12)**:EventKind 相等语义机制化(== 只比 Id 或暴露 Matches)、Session 重入防护、Intent 数值域校验、外部输入批次决策谓词扫描、RandomPlayerDriver 坐标寻址化。

以下为评审报告原文(不成立攻击表已精简)。

---

## S1 — 信息不对称在 affordance 通道被违宪泄露;action.rejected 对 Player 零反馈

**Scenario**:Bob 从未去过地窖、从未获知封闭事件,但 deadline 一触发,他的 Travel 候选里 "cellar" 凭空消失。

**Invariant violated**:002 §3.1「Player 只能获得角色合法可知的……行动 affordance」「信息不对称不是 UI 技巧,而是 Core 规则」。AvailableActions 直接读 world.CellarSealed;CellarSealedEvent 的 reducer 只翻全局 flag、不产生 actor 可知事实。镜像面:ActionRejectedEvent.Reason 只进 journal,玩家看不到自己被拒绝(DecisionReason 恒为 Scheduled)。

**Root weakness**:002 §3.1 的 "Objective World → Perception → Observation → Belief" 只在 KnownFacts 上实现了一半;affordance 是客观世界直投,绕过信念层。

**Minimal repair**:AvailableActions 只能由 (actor.KnownFacts + 当前 Observation) 计算;地窖封闭须先成为该 actor 的 fact 才影响其选项。拒绝落成 KnownFact + 新增 DecisionReasons.ActionRejected + DecisionRequest 回带上次 Intent。

**Cost-of-delay**:高——违宪轨迹是污染的评估语料;且与 S2 组合 AI Player 立刻死循环。

## S2 — Player 驱动的同刻活锁:被拒 Intent 无反馈可循环重试,唯一兜底是 10k 预算异常

**Scenario**:LLM Player 坚持"去地窖";被拒后世界回到完全相同状态与完全相同 DecisionRequest,它再次给出同一 Intent。全部事件 Due=now,模型时间不进,约 5000 轮后 Kernel 抛预算异常,整局崩溃。

**Root weakness**:决策闭环缺"结果反馈"边;CompleteAction 使 actor 立即重新 idle,构成零成本重试环。Host 侧无每 actor 拒绝预算/退避/降级。

**Minimal repair**:Host 对同一 (actorId, ModelTime) 连续未推进时间的决策计数,超阈值强制降级为 Wait 并落 host.decision-forced 事件。与 S1 合并修。

**Cost-of-delay**:高——第一个真实 LLM Player 就触发,且症状指向错误的层(Kernel 异常)。

## S3 — 同刻决策强制串行+因果穿透 ⇒ 低 Id 恒定先手且信息更多;A4 仲裁在 Host 路径不可达

**Scenario**:Alice(id=5) 与 Bob(id=6) 同刻 idle 同地抢钥匙。Loop 在第一个决策事件处返回,Host 先问 Alice;Alice 的 take 同刻 resolve 后 Bob 的请求才构造——Bob 的选项里已没有钥匙。competitors>1 分支在 Host 路径上永远走不到(唯一覆盖它的测试是手工 external batch)。

**Root weakness**:Loop 在"第一个含决策事件的批次"处返回,Host 拿到的永远是单点决策而非"该时刻的决策点集合"。tie-break 升级成了游戏规则:持久 Id 小的角色永远先手、永远多一手信息。A4 修掉了"构造顺序副产品",没修掉"顺序即优势"。

**Minimal repair**:同刻决策屏障——装配方把决策调度改为世界级单候选一次发出全部 decision.requested;Host 整批回应、作为**一个** externalInputs 批次提交。仲裁路径随即可达,Player 间恢复"同刻互不可见"。

**Cost-of-delay**:高——更丰富 Board 必然同刻争抢;轨迹一旦录下就带着"低 Id 恒赢"的隐式规则。

## S4 — Host 重蹈 A2 覆辙:决策生命周期状态在栈上,取消/异常即永久丢失决策点

**Scenario**:RunUntilAsync 在 pending 队列非空时被取消(或 driver 抛异常)。队列是方法内局部变量随栈销毁;_world/_cursor 已被改写。这些 actor 世界里 AwaitingDecision=true 故 IsIdle=false,调度系统永远不再为它们 forecast——角色永久冻结,无诊断。

**Root weakness**:A2 的教训只应用到 Kernel;Host 重建了同一形状的隐式状态机。同根因:requestBuilder null 跳过是终局的(决策消失);ValidateDecision 失败只能抛(无重问、无重生成 Observation,而 002 §9 恰恰要求后者)。

**Minimal repair**:pending 决策集合提升为会话显式字段并进 Result;每个待决点三态(Open/Answered/Invalidated-with-reason);skip 与 stale 走同一条"重新构造请求并重问"路径,只有超预算才抛。

**Cost-of-delay**:高——LLM 调用超时/取消/失败是第二阶段常态。

## S5 — 会话级切分不等价:同一决策的输入落在哪个 ModelTime 取决于 until 怎么切

**Scenario**:一个批次同时发出 decision.a 与 decision.b。RunUntilAsync(10)+RunUntilAsync(20) 与一次 RunUntilAsync(20):decision.b 的输入分别落在 t=10 与 t=20——同一玩家同一决策,模型时间差 10。已有测试把该行为锁定为"正确"。

**Root weakness**:外部输入无条件提交在 cursor.Now,而队列中的决策在被回应前世界已被推进任意长模型时间;BoundaryReached 后队列继续处理使 until 不再是硬边界。

**Minimal repair**:决策请求携带提出时刻,externalInputs 带"意图落点"并由 Loop 断言;或禁止跨 Run 复用队列——一个批次的决策整批回应整批提交(与 S3 修复同源)。

**Cost-of-delay**:中高——Kernel 最硬的 property 被 Host 层作废;越晚修,越多轨迹时间戳不可信。

## S6 — LineageId 不落盘:branch↔lineage 映射无人维护,(LineageId,EventCount) 跨分支必然碰撞

**Scenario**:main 100 事件,fork 于 60。两分支各跑到 EventCount=70。DomainEvent 无 lineage 字段,sink 不写,装配方按同一常量重建 cursor——两分支 WorldVersion 完全相同,fork-1 上的 PlayerDecision 可合法提交进 main。

**Root weakness**:WorldVersion 两个分量分属不同权威——EventCount 来自 journal,LineageId 来自宿主内存;adapter 只持久化了前者。附带:SimulationCursor 整体不落盘,今天没有"读档续跑"路径(LineageId 不可恢复)。

**Minimal repair**:lineage 作为 journal 一等内容——分支创建时写 lineage.created 元事件(LineageId、parent lineage、fork prefix count),sink 打开时校验;SimulationCursor 可序列化快照成为 adapter 契约。

**Cost-of-delay**:中高——现在是一条元事件;多分支轨迹之后是全历史迁移。

## S7 — 落盘无批次完整性标记:半个批次的尾部不可检测,A5 撕裂中间态从持久化层回归

**Scenario**:一批 3 事件写到第 2 个时崩溃。重开 replay 只校验时间戳递增,残缺前缀合法通过;ForkBranch 的完整性检查只覆盖内部切点,尾部一律放行——可以在残批尾 fork。

**Root weakness**:IJournalSink.Append 是逐事件 API,无批次/事务边界;BatchOrdinal 只标注"属于哪批",不标注"写完没有"。同根因:Append 抛出后 Loop 不返回而 journal 已多出事件——会话状态与盘上状态分叉。

**Minimal repair**:AppendBatch 或 envelope 加 (batchIndex, batchCount);重开时残尾截断到最后完整批次并记 reflog;fork 尾部走同一断言。

**Cost-of-delay**:中高——envelope 变更趁现在只有一个写入点。

## S8 — codec 无法升级:反序列化拿不到 EventKind,envelope 无 codec 标识;FirstBoard 从未落过盘

**Scenario**:payload v1→v2。盘上老事件 kind.ver=1 正确读出,但 `Func<byte[],TPayload>` 收不到 EventKind,无法按版本选 upcaster。另一硬事实:adapter 只跑过单一具体 record;FirstBoard 的多态 payload 从未落盘(默认 JsonSerializer 序列化抽象基类会静默产出 {})——002 §3.3「原型历史不可弃」今天不成立:唯一在产生的历史从不落盘。

**Root weakness**:版本语义切成三段互不相通——envelope v(帧)、kind.ver(声明 schema)、装配方 codec(实际字节,无标识无版本),而 payload 字节的真正决定者是第三段。

**Minimal repair**:反序列化委托改 `Func<EventKind, byte[], TPayload>`;envelope 加 "pc"(codec id+版本);EventKindRegistry 做落盘路由;**FirstBoard 完整一局接 AteliaJournalSink 跑通作为验收**。

**Cost-of-delay**:中高——签名改动现在只有 3 个调用点。

## S9 — Player 提交的整数可让 Kernel 抛 OverflowException 崩局

**Scenario**:Wait(DurationMs: long.MaxValue) 通过 duration>0 检查,`now + duration` 在 checked 溢出,异常穿透全栈;此时 wait-requested 已入 journal 而 session 状态未更新——分叉。UntilModelTimeMs: long.MinValue 同崩。

**Root weakness**:Protocol 零校验(StableIdentifier 只查非空白,无长度/字符集约束),system 合法性检查只覆盖领域语义不覆盖数值域;Player 边界无输入净化层,尽管该边界的设计目标就是接 LLM。

**Minimal repair**:Intent 构造校验数值域与文本长度;system 侧时间运算显式范围检查后 reject。

**Cost-of-delay**:中——脚本不会触发,第一个 LLM Player 会。

## S10 — 外部输入批次不参与决策谓词扫描:输入形式的决策请求被静默吞掉

**Scenario**:外部"打断"输入产生 decision.requested——进了 journal、改了世界,但 Loop 对 external 批次不跑谓词,DecisionEvents 永不包含它,Host 永远不问。

**Minimal repair**:external 批次也扫描;或契约声明"外部输入不得携带决策请求"并断言。

**Cost-of-delay**:中——"打断/事件驱动决策点"是第二阶段必然需求。

## S11 — 装配方按 EventKind 全等(含 Version)路由:A7 的"按 Id 路由"没有被继承

**Scenario**:decision.requested v1→v2:谓词 `Kind == BoardEventKinds.DecisionRequested` 不再命中(record struct 相等含 Version)——所有决策点静默消失;旧 journal 重放 reducer 抛 unknown kind。FirstBoard 全部用 == 路由;EventKindRegistry 全仓零使用。

**Root weakness**:A7 的修复是"约定"而非"机制"——EventKind 暴露一个把 Version 计入相等的 ==,装配方最自然的写法就是错的。

**Minimal repair**:EventKind 相等只比 Id(Version 非相等字段)或移除 ==/暴露 Matches;FirstBoard 改 Kind.Id 路由。

**Cost-of-delay**:中——第一次 payload 演进踩到,症状"静默不发决策"极难定位。

## S12 — RandomPlayerDriver 随机流非坐标寻址、不入 journal:affordance 形状一变全序列漂移

**Minimal repair**:改坐标寻址(worldSeed/actorStreamId, generation=BasedOnWorldVersion, sampleIndex),无内部可变状态。

**Cost-of-delay**:中低——影响回归语料寿命。

## S13 — Observation 的"口袋透明":持有物同地即可见,不需 Observe

**Minimal repair**:区分 placed(地上同地可见)与 carried(需 Observe 或显式展示)。与 S1 同源同修。

**Cost-of-delay**:低。

## S14 — PlayerDecisionSession 无重入保护

**Minimal repair**:Interlocked 忙标志,重入抛异常。

**Cost-of-delay**:低——一行防御,缺失时症状是无法复现的历史损坏。

## 不成立的攻击(已防御,摘要)

| 攻击 | 防御点 |
|---|---|
| 落盘 JSON 确定性 | 手写固定 key 序 Utf8JsonWriter,无浮点无 culture;双目录逐字节相等测试 |
| CAS orphan 分叉 | Append 先抛再改内存,orphan 只是不可达垃圾(真洞是半批次 S7) |
| requestBuilder 误跳/漏跳 | AwaitingDecision+OpenDecisionId 双重匹配;误清后 IsIdle 自愈 |
| deadline 竞态(当前 Host) | 严格串行,dequeue 时重算 affordance,无推进窗口(并行化后失效→S4) |
| 畸形 PlayerDecision 绕过 system | 未知 ActionKind 兜底 unknown-requested→reject;领域校验完备(数值域缺口→S9) |
| 队列丢失/重复/乱序 | 单线程 FIFO+三重校验+ActorId 交叉校验 |
| 推进不动/无限循环 | 空翻译不触发 Run;no-op 守卫+预算跨 Run 承载(Player 活锁仍烧预算→S2) |
| affordance 枚举顺序不稳定 | Ordinal 排序,同世界同种子严格复现(跨规则变更→S12) |
| Observation 泄露在途/他处/他人知识 | IsPresent 排除在途;Talk 拒转述未知事实(口袋透明残留→S13) |
| journal 时间倒流/同刻重复 | 双实现拒绝 <=,replay 时重校验 |

## Top-3(+1):进入第二阶段(AI Player)前必修

1. **S1+S2:感知与反馈闭环**——affordance 从信念计算,拒绝可感知。不修,第一批 AI 轨迹既违宪又在同一毫秒空转到预算耗尽。
2. **S4+S3:Host 显式决策生命周期状态机 + 同刻决策集合批量驱动**——A2 教训在 Host 层的重演,一次修透;同时让 A4 仲裁重新可达,消除"低 Id 恒先手"。
3. **S6+S7:持久化契约补完**——lineage 元事件、批次完整性、cursor 快照。「原型历史不可弃」今天在机制上不成立。
4. **S8(第 3 条的前置)**——codec 升级路径 + FirstBoard 真落盘。不修它,落下去的历史读不回来。
