# 属性附近的阈值预测与行动例外

状态：2026-10-29 已实施，通过[工程与独立 Console 试玩验收](../experiments/attribute-threshold-forecasts-acceptance.md)。承接[属性速率解释](attribute-rate-explanations.md)与[角色上下文 Model](character-context-model.md)，不改变生存数值、时间推进或警告机制。

## 问题与目标

旧版对每个等待时长、采集和通路生成一段“身体预计告警／耗尽”的风险字符串。预测只保留最早时刻，丢失触发属性；全量布局重复展示，补给后的增量又重复刷新大量行动风险。当前属性区已有一份最早耗尽时间，职责重叠。

本片把“按当前条件继续会怎样”集中到属性附近；行动区只说明“该行动改变了什么条件”。所有 layout 与后续 LLM 消费同一份冻结材料，不靠解析风险字符串重建预测。

## 最小共享模型

新增持久值 `CycleAttributeForecast(WarningAt?, DepletionAt?)`，分别表示数值到达警戒阈值和零点的最早模型时刻。`CycleSurvivalObservation` 必填保存 `FoodForecast`、`WaterForecast`、`WarmthForecast` 与共享 `WarningThreshold`（当前 25）。原 `FatalAt` 不再独立保存，仅由三项耗尽时刻取最小值派生。

- **数值预测不是通知预测**：`WarningAt` 不受 `WarnedMask` 或确认消息影响。当前已低于或等于阈值时取观察时刻；视图依据当前值显示“已处于警戒区”，不声称将再次发出警告。`PendingWarningMask` 仍表示历史通知待确认，补给不会清除它。
- 当前已为零时显示“已耗尽”。无时刻表示按本片假设在可表示时间内不触及该目标，不表示尚未计算或信息不可见。
- 每项独立推算，不因另一项先耗尽而截断。共同说明须明确这是单项趋势，并不承诺角色能活到每个时刻。最早致命时间仍可作为派生查询使用，布局不必再重复一行。
- 固定预测合同：不补给、保持观察中记录的庇护状态、计入已知昼夜与数值上限、不计随机寒风、不预知抵达后的环境。条件由冻结观察的 `Sheltered` 与既定游戏规则表达；不为恒定假设引入可配置预测框架。

可复用的是“有明确条件的属性阈值预测结果”，不是要求其他游戏采用三属性、整数速率、小时或 25/0 阈值。任意阈值注册表、公式解释器、Buff 生命周期、概率天气估计均不在本片。

## 预测与保存边界

食物与饮水保持当前常速，分别求警戒线和零点。温暖按当前庇护和已知昼夜独立分段投影，沿用相同取整、限幅与回暖／散热规则；不能复用旧的“遇到任意属性死亡就退出”的循环。当前温暖规则保证最多残余夜晚、白天、下一夜晚即可判断；这不是通用任意速率预测器的终止证明。

阈值目标、nullable 语义和时刻顺序须校验；含观察时间的边界还须拒绝早于该观察的预测。当前值已在阈值内与历史告警分开校验。物理阈值调度继续使用原来的 `NextThreshold`，不把 UI 预测结果写回物理状态或调度缓存。

观察生成时一次求值并冻结；Opening、Item、完整渲染、增量、S 冷开和 pending E 恢复读取保存材料。结构比较覆盖预测结果；校验历史材料形状和观察时间，不以最新规则重新计算旧观察。冷开不得重采天气、调用控制器或改写已交付预测。

## 行动例外

`ActionWarning`／保存的命令 `Warning` 仅保留改变当前预测条件的提示。本片只有**从庇护出发移动**符合此条件：

- 说明途中暴露、失去庇护回暖和寒风保护；移动不可取消。
- 若途中温暖会降至警戒线或耗尽，使用同一温暖预测计算给出具体时刻，只显示不晚于预计抵达的结果。两个目标各自显示，不能以耗尽覆盖较早警戒时刻。
- 不推断未探索目的地安全，也不把本段终点以后假定仍暴露的预测当成本段风险。

普通等待、采集、已经暴露时的移动不再生成重复的三属性风险字符串。耗时、可执行条件、移动不能取消等行动规则照常呈现；天气窗口与寒风实际损失规则集中在环境材料中。命令查询与执行前反馈同样使用精简后的规则，不能只在某个 layout 隐藏旧字符串。

## 全量与增量呈现

属性的当前值、速率构成、限幅与两个预测在同一个展示单元中；精确位置、换行与表格形式由 layout 自由决定。共同预测假设每份完整观察说明一次。终局展示冻结值，不误称仍在推进。

`CycleAttributeView` 消费保存的预测，语义比较含预测。值未变但预测变化也应更新；饮水补给只更新饮水及实际受影响材料，不刷等待时长风险。历史警告依旧独立保留。行动无例外不输出“风险：无”；已有例外解除时增量仍须让读者知道旧提示失效。

## 实施与验收

1. 领域：新持久记录、逐项预测、精简行动例外、观察比较／校验、Schema 与 GameRevision 更新；无旧存档兼容。
2. Console：共享属性视图、decision/classic 与 delta、去掉重复全局耗尽和空风险行；保留规则与环境事实。
3. 集成：独立源码复核、两项目测试、solution Release Schema Verify、实际 Console 补给／离开庇护／冷开试玩。

测试保护语义与信息齐全，不断言完整屏幕或具体呈现位置。至少覆盖：三项原因及独立时刻；25/0 与正／零速率；已告警与待确认；昼夜和上限；时间表示边界；离开庇护的段内／段外目标；观察无副作用；预测变化的增量；旧 Opening 冻结与 S/E 恢复。真实试玩验证两种布局、补给后的局部更新以及动作例外，实际 LLM 与 Windows Terminal 视觉效果不由重定向 Console 测试代替。
