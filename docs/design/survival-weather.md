# 生存环境风险：可预告窗口与持久随机结果

状态：生存一期已验收，见[生存验收](../experiments/survival-demo-acceptance.md)。二期按[双角色合同](../implementation/survival-duo.md)扩展为一次世界抽样、按活跃角色结算；机制仍留在 ResourceCycle 应用层，不建立通用天气或效果框架。

## 1. 玩法与信息

这片山林每两小时有一次风势变化机会，从创建场景时刻开始安排。每次二选一：平静，或使暴露角色瞬间损失 10 点温暖的寒风，概率各半。停留在庇护地点可以完全挡住这次损失；平静和受庇护的窗口仍然属于已发生的随机机会。

这个机制旨在让出发时刻、庇护停留与温暖储备影响路线选择。额外停留会耗食水；移动途中没有瞬移取消。固定损失已经足以制造选择，暂不再随机伤害幅度或加入暴风持续时间。最大损失低于 25 点警告线，安全区不会被一击直接耗尽；低值区仍可能失败。

UI 展示下一次窗口、周期、暴露损失和庇护保护，不展示 seed、随机序号或未来结果。身体趋势与行动风险估计明确是**未计入未来寒风的确定性基线**，不是安全保证。天气造成低温跨线后沿用现有生存警告；不因每次平静事件额外唤醒控制器。

最近一次天气保存发生时刻、结果和当时实际个人影响。角色后来进屋，不能把先前在野外受风重新解释为免伤；角色后来离屋，也不能把先前受保护的窗口改成受伤。Console 可播报新事件，但恢复后的完整观察必须能从状态重建最近天气，不能依赖聊天历史。

## 2. 单根状态与随机边界

探索子图保存可选环境子状态：固定 seed、下一机会序号、NextDue，以及最近结果与当时影响。默认生存工厂启用；原采集/批处理不启用。纯空间与生存数值夹具可以关闭天气以隔离验收范围，生产 smoke 不关闭。

一个环境 prediction owner 只读取 NextDue 和序号生成候选。选中天气发生项后，Plan 使用既有 `DeterministicRandom`，以 seed、固定天气 stream 身份和序号寻址二元结果；没有共享可变 Random 实例。固定默认 seed 便于实验复现，工厂允许显式指定 seed；本片不增加 CLI 的 seed 配置入口。

同一个已记录事实包含推进后的环境状态，以及全部活跃角色的实际身体替换与可能的个人死亡结局。先按旧速率积分到窗口，再扣除具体损失。序号推进、下一窗口、天气结果、按 ActorId 的庇护/实际损失与身体变化一起发布；个人死亡还同时退休其空间实体，不能只保存其中一侧。

Forecast、观察、命令校验、全量重建和 Fold/Complete 不采样。E-only 恢复只应用记录，不重做随机决定、位置判断或扣值；未来机会从恢复后的序号继续。无法在模型时间范围内安排下一窗口时停止该预测，而非溢出到过去。

## 3. 同刻与终局

明确的应用仲裁顺序是：连续需求耗尽 → 资源再生/昼夜/脚本等既有自然项 → 空间到达 → 天气 → 活动完成 → 身体警告 → 控制器输入。

- 到达庇护与天气同刻：先到达，按新位置受保护。
- 到达出口与天气同刻：先个人获救，不参加该次天气；如果仍有其他活跃角色，天气照常发生。全员结束才取消后续天气。
- 连续需求耗尽与到达同刻：沿用 B，先失败，不借到达或天气挽回。
- 天气使温暖归零：天气事实自身记录失败与原因，不留给后续行动重新猜测结局。
- 天气非致死但使温暖跨警告线：同刻派生低值警告，再请求响应；确认保留活动和行程期限。

个人终局 Context 保留结束时的环境观察与历史位置，不再预告未来窗口；其他角色仍可继续经历天气。平静、受保护或全员终局取消窗口三者必须区分：前两者已经抽样，最后一种从未发生。

## 4. 验收

1. 固定 seed/初始条件/合法操作得到相同轨迹；全量与增量预测一致。
2. 暴露与庇护采用相同 seed/序号时抽到相同天气，实际损失不同；两种结果均由受控条件覆盖。
3. 到达庇护或出口与窗口相差一 tick/同刻，以及天气跨警告线/致死具有明确结果。
4. 天气窗口附近真实 S-only 冷开保持同一下一机会；实际天气 E-only 恢复只推进一次序号、不重复伤害，不调用 Plan/Forecast/控制器。
5. 查看、非法命令、命令风险查询不改变随机状态或存档；最近结果经冷开仍可见且不按新位置改写。
6. 生产 Console 在天气开启时仍有两条可完成路线，能观察到实际寒风损失、庇护免损与可解释失败。工程脚本不替代里程碑的独立完整试玩。

Schema 与 GameRevision 随真实持久形状/语义修订；本片不兼容旧开发存档。后续第二个环境机制出现后，再考虑是否需要抽取更通用的规则组件。
