# 生存需求：分段变化、阈值与角色响应

状态：生存一期 B 切片的实现合同；实际证据见[生存验收](../experiments/survival-demo-acceptance.md)。规则留在 ResourceCycle 应用层，不建立通用状态条框架。

## 1. 局部状态与时间

每角色可选一份生存子状态，表示食物、水、温暖三个游戏余量。原采集和批处理不启用，生产生存场景启用。三项范围 0～100，25 为警告线，0 为本局失败。

保存基准时刻、定点余量、当段速率与警告标记。定点单位为“点数 × CycleTime.Hour”，这样每小时变化若干点可直接乘模型 tick 数，不因发生项多少而反复取整。积分用 Int128 中间量并裁剪到合法范围，阈值到期时刻向上取整。显示值只在投影时换算，不回写舍入结果。

昼夜和位置决定温暖速率；移动不维护另一份旅行进度。当前规则是食物每小时 −5、水 −8，白天暴露回暖 +6、夜间暴露降温 −12，庇护地点回暖 +12。进入/离开庇护或昼夜切换时，先按旧速率算到该事件时刻，再安装新速率；不能用新环境回算过去。

生产场景从 15:00 开始，食物 30、水 45、温暖 60，背包一份水；先让两条路线都需要取得食物并补给，不以高初始值掩盖玩法。具体默认值以工厂为准，后续按试玩调整。调整已保存时间段的规则必须有版本决定，不悄悄用新速率重新解释旧基准。

## 2. 警告与决策

每角色一个生存预测 owner，选择最近的未处理下降阈值；没有每分钟全体扣数循环。预测归运行时派生状态，冷开从业务根重建。

警告区分两份状态：

- **已警告标记**：此指标当前低值区间已经提醒过。确认警告后仍保留，不会立刻重新提醒。
- **待确认标记**：玩家尚未处理的感知。可在原活动或移动继续存在时触发决策请求。

余量严格回到 25 以上才重新武装；恰好为 25 不算离开低值区间。历史待确认提示可在喝水后保留，UI 同时展示其发生时间与当前已恢复的值，避免把旧警告当当前数值。

`continue` 清除待确认消息，保留旅行/采集/等待和原期限。取消或另行安排合法耗时行动也视为响应；仅消费不确认。途中允许补给后继续；普通地点可取消原采集/等待再安排新活动。移动仍不能通过 cancel 瞬移，是否加入途中掉头以后另议。空闲时出现警告也必须有可结束交互的合法选择。

## 3. 补给和保暖

`use item.food` / `use item.water` 为本次响应中的不耗时行动。检查当前库存及效果有无收益，单份扣除与同刻身体补充写进同一事实；food +35、water +45，超过上限裁剪。无此物或已满则拒绝且不消耗时间/库存。

补给不替代明确的感知确认，不重新启动旅行或采集周期。pending 恢复应用具体库存与身体替换，不重查库存或再次扣除。

保暖先采用庇护与等待，回暖期间仍消耗食水。干木没有瞬时回暖效果；不为了让资源立刻有用途而暗加火堆持续时间或通用效果系统。

## 4. 同刻边界与终局

死亡阈值先于同刻到达、补给和控制器输入。耗尽与安全出口到达同刻时失败；早一 tick 抵达且余量为正可以获救。其他同刻政策由游戏组合明确，不依赖模块注册顺序。

恰好到期的前态允许恢复，正常发生项负责结算；加载不能偷偷完成死亡或警告。已错过应结算阈值的运行边界应被识别，不能无限绕过阈值。

死亡停止后续普通发生项。可以保留角色死亡地点或途中空间段作为终局真相，不虚构走完最后一段路。结局渲染不再请求正常动作，冷开也不会继续推进。

## 5. 观察与验收

观察给出当前余量、趋势、庇护情况、当前条件下的危险期限和待回应感知。预测期限不能冒充无条件保证：昼夜、位置和后续环境事件会改变速率。对等待或行进跨越已知危险的选择给出明确提示；不预知隐藏世界或后续随机结果。

验收同时覆盖纯数值与真实组合：

- 不同事件分割方式的积分相同、定点阈值与长时长计算安全。
- 警告确认不循环，补给离开低值区间后会再次提醒。
- 跨昼夜和进入庇护先旧后新积分，途中补给不改变 Spatial 期限。
- 出口比死亡早一 tick、同刻、晚一 tick 的不同结果。
- 阈值附近 S-only 冷开，以及警告/消费 E-only 恢复只结算一次。
- Console 两条补给路线获救、一条不补给失败；仍须在环境风险落地后做独立完整生存试玩。
