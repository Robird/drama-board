# 实施与验收计划

状态：实施 Goal 进行中，剩余 B–D。入口与个人连接知识已完成[切片 A 验收](../../experiments/character-navigation-a-acceptance.md)；功能合同见 [设计](design.md)，来源与自主边界见 [入口](README.md)。下列全功能验收仍是目标，不代表已经全部通过。

## 1. 实施方式

每个切片由领域实施、呈现接线与独立工程/游戏体验审视协作推进。主线程统一构建、schema 生成与验收；角色协议使用入口身份，Spatial 和原始事实保留 PassageId。下一片先贯通已知图求路与候选持久化，不同时扩充导航执行。

先读取当前 AGENTS.md、PROJECT-STATE 与本目录全部文档，确认源码变化。每轮选择一个有可运行闭环的切片；由有界子任务隔离调查/实现/审阅，主代理独立核验。共享可写构建图的 dotnet 操作串行，不让多个代理同时生成 schema/构建同一图。

不先建设通用框架。对类型名进行语义重命名与消费者审计，不盲目全库文本替换 PassageId：Spatial 真实身份与宿主原始事实仍需要它。允许新的开发存档，不覆盖用户现有 home。

## 2. 纵向切片

| 切片 | 可交付闭环 | 验收重点 |
| --- | --- | --- |
| B：求路与候选 | map/path 为两类控制器可用的普通操作；过滤后的 A* h=0；保存一份候选并显示回执 | 无未知捷径、方向与平行边正确、稳定等价路径、无路/零段/未知/显式起点、ID 隔离与冷开。 |
| C：导航执行 | navigate 启动首段，逐站唤醒，continue 下一段，cancel 只清剩余路线 | 单段逻辑复用、提醒和失败原子性、跟随同刻到达、终局/互斥/途中取消。 |
| D：组合验收 | 实际 CLI 与真实 LLM 试玩，lookahead 与 history/恢复闭环，文档与示例命令 | 同一角色视角材料、独立试玩证据、分支不污染、可继续/可取消的可理解性。 |

各切片都应覆盖自己的持久化和呈现闭环，不能把所有恢复工作推到 D。首次 schema/content 变化明确当前版本，按仓库工具生成并 Verify，不手改生成物。

## 3. 必须通过的场景

| 编号 | 轨迹或测试 | 通过条件 |
| --- | --- | --- |
| N1 | A 经别路分别到过 X/Y，但未走 X-Y 的 P | X/Y 本端入口可知，P 连接未知；当前/途中观察不因 Visits 自动显示对端。 |
| N2 | 从 X 进入 P，提醒唤醒，再抵达 Y | 途中未知，到达事实才确认；重绘、读 map、恢复不提前确认。 |
| N3 | 审计系统生成的各角色输出与默认地图文案 | 未知 PassageId/对端不在地点/入口描述、命令、结果、effect key、PendingAdvance、背景/两布局/LLM 请求/人物 history 泄漏；原始诊断与角色投影分开。 |
| N4 | 已知长路与隐藏短路，环、断开、平行边、同成本路线；纯搜索夹具的单向邻接 | 只选已知合法连接；最小成本与稳定选择；无路不变成世界不存在；不为了测试增加生产单向配置。 |
| N5 | 两角色 path、重复查询、无路查询、显式异地起点、零段路径、分叉继承候选 | 只查当前根本角色候选，旧/他人 ID 不误用，继承候选继续有效；启动检查真实起点，异地零段查询不声称本人已抵达。 |
| N6 | 三地点导航，到中间点 say/use/map/path，再 continue | 中间点先观察；即时代办不隐式出发；新候选不修改活动计划；最终清计划。 |
| N7 | 导航中间点尝试 gather/produce/go/follow；途中已有提醒唤醒后 cancel、补给、continue | 耗时动作明确要求取消；取消只清导航，保留本段期限与提醒；continue 后能放行，到点不走下一段；不新增异步输入。 |
| N8 | 队员不能出发，或单段执行校验夹具拒绝；同一段 go/navigate/导航 continue 预览对照 | 所有人原地，进度/提醒不部分改变；本地原因可读，不自动改道；三个出发入口保留相同已有危险预览，无整路模拟。 |
| N9 | 队伍逐实体同刻抵达；领队/队员终局 | 到达中间 S 可恢复，控制器不能插入半队到达窗口；跟随者不继承未走路线；终局无遗留自动出发。 |
| N10 | 候选、途中、待确认、取消后途中各边界 S 冷开与 E-only/pending；篡改知识/进度事实负例 | 不重问/重搜/分配不同 ID，不重复出发；局部因果校验拒绝非本人到达授知或错误推进，取消后不复活计划。 |
| N11 | lookahead 分支发现新地点/求路/前移导航，随后丢弃 | 实际根不变；正式命令只提交一次；可见输入变则不采用预取，不可见地图改变不泄漏到请求。 |
| N12 | Human 入口真实 CLI 运行和真实 LLM 运行 | 能探索、求路、逐站确认、取消和续局；保存原始证据及角色 history，失败和未执行项明确标注。 |

N3 使用不同未知拓扑但相同已知观察的成对世界更有说服力：角色可见地图/查询响应不因隐藏对端变化而不同。比较语义材料和真实请求，不断言固定 Markdown 位置；用户输入中的猜测文本单独标注。

不要求为纯文本排版建立快照测试。工程测试应针对知识获得时机、合法性、持久化与控制节奏。最终跑受影响领域/CLI/Completion 测试及 Release Schema Verify；必要时扩至全 solution，按实际运行报告，不沿用历史通过数。

真实 LLM 试验开始前记录端点/模型/调用预算和停止条件，凭据运行时读取，不写仓库或日志。只为验证新角色命令与体验做小规模调用，不重跑整套性能研究。代理操作 Human Console 必须标为代理试玩，不能宣称实际人类体验已验收。

## 4. Goal 完成条件

1. 入口探索、求路候选、导航执行与组合验收全部闭环，N1–N12 逐项有证据或明确的不适用理由；不能以“编译成功”代替恢复/真实运行。
2. 两类控制器看到同源知识，未知入口身份不泄漏；普通移动、跟随、提醒与生存语义无回归。
3. 候选与导航同版本存档、pending、分支工作；没有额外宿主状态成为恢复依赖。
4. 设计、术语、README/PROJECT-STATE、示例 home/试玩命令与实现一致；验收另存专题结果，不把工作计划变成逐轮日志。
5. 记录遇到的产品分歧；已能由证据解决的技术细节自主收敛。保留未解决项时不能把整个 Goal 标为完成。
