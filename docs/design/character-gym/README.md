# 角色实验环境（Character Gym）

状态：2026-11-02，独立反馈已实施并通过工程与脚本 CLI 验收，现行合同见[独立宿主反馈](../independent-feedback.md)；以下一期范围保留历史背景。一期已实现并完成工程及真实模型串联验收；二期未启动。证据见[工程验收](../../experiments/character-gym-acceptance.md)与[真实试玩](../../experiments/character-gym-playtest.md)，直接操作见[使用说明](usage.md)。

长期愿景是利用虚拟世界的结构化事实、可保存的角色上下文和分支历史，让角色运行产生可定位的问题现场，支持后续反事实实验。Gym 在这里指可观察、可反馈、可分叉重跑的实验环境，不表示已经采用某种训练协议或提供强化学习平台。

**一期只建设基础能力：角色轨迹可回看、控制器可提交 feedback、开发者可按反馈线索从指定位置 fork 世界并继续运行。** 比较修改方案、判断改进效果和自动优化属于二期，不能成为一期完工前提。

## 两期关系

一期交付可用的实验工具和证据链，允许开发者亲自选择分支、配置并重跑；不承诺角色一定主动发现高质量问题，也不要求模型重现同一句话或同一失败。

二期才考虑以现场为案例，修改提示词、呈现或游戏能力，运行对照，建立可核对的效果判据。反馈是线索，不是缺陷已证实、功能已批准或收益已成立的证明。批量运行、统计、反馈归纳和案例库按一期使用经验选择，不自动进入施工范围。

## 一期 Goal 的原任务表述

> 依据 docs/design/character-gym/ 与 docs/implementation/character-gym-plan.md，逐步实现角色实验环境一期。使真实 LLM 角色运行可导出按角色组织的完整记录，可提交与实际上下文及存档位置关联的反馈，并可据此从明确的决定前已完成 S 边界创建分支、冷开和重新调用控制器继续游戏。自主消解内部工程问题，按需有界委派并由主线程验收，持续维护实施入口的剩余问题。保持原游戏恢复、信息可见性与源分支不变等边界。以里程碑验收完成为终点；不实施方案优化、对照收益评估或自动改进闭环，不要求重跑复现相同模型行为。

这段文字保留一期任务范围，不授权完成后重复施工或进入二期。后续 Goal 应依据新的使用证据重新限定范围。角色游戏内 Goal 与 Coding Agent 的执行 Goal 是不同概念。
