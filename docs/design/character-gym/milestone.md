# 角色实验环境一期里程碑

状态：2026-10-31，一期已完成。证据见[工程验收](../../experiments/character-gym-acceptance.md)与[真实模型串联试玩](../../experiments/character-gym-playtest.md)。设计边界见[设计思路](design.md)，动态剩余工作只维护在[实施入口](../../implementation/character-gym-plan.md)。

## 1. 交付能力

| 能力 | 一期要求 |
| --- | --- |
| 角色轨迹回看 | 从开启记录的运行起，按角色导出可独立阅读的 UTF-8 Markdown/文本。覆盖实际输入材料、控制器输出/工具调用、提交或拒绝、可感知结果、反馈与中断；跨进程续局可衔接，缺失明确标注。概要可导航到完整内容，不以裁剪后的 Context 冒充完整轨迹 |
| 需求反馈 | LLM CharacterController 可选用工具提交 issue / feature-request；宿主记录稳定身份，自动关联角色、调用、实际材料和决定前存档位置。反馈有简短回执，不成为世界行动；提交后仍能正常选择行动 |
| 反馈定位与分叉续跑 | 开发者可从反馈找到支持的已完成 S 边界，使用 DurableGraph 分支能力建立新分支、选择并冷开该分支，以原有或显式选择的控制器配置继续。原分支的头、状态与既有历史不被改写，子分支记录来源 |

首版以 Playground 生存模式及现有 Completion 控制器为消费者，包含双角色中的角色隔离；不要求提取通用引擎或新建 GUI。实际 CLI 和文件布局见[使用说明](usage.md)。

## 2. 最小端到端验收

1. 启动启用记录及反馈能力的真实模型游戏；至少获得一条模型实际提交的反馈。可用明确任务提示触发工具试用，但记录提示来源，不能称为模型自发发现缺陷；不能由脚本伪造模型反馈冒充接线成功。
2. 同一角色经历多个独立调用，并至少一次正常退出、冷开继续。导出该角色轨迹，能找到反馈所在请求的准确材料、前后操作及实际结果；其他角色的私有内容不混入其视角。
3. 按该反馈定位并从对应的决定前 S 创建分支；即使源分支已继续推进，也仍选中记录的位置，不能退化成“从最新状态重新开始”。关闭后可按新分支身份重新打开。
4. 子分支实际重新调用控制器并至少提交一项合法游戏操作；角色目标、Context、库存、活动、时间游标等从该分叉边界继承。反馈与轨迹能追溯父来源，不混入源分支分叉后的未来记录。
5. 独立核对源分支未被移动/改写，新运行的日志与身份不会覆盖或误配旧记录。导出子分支轨迹并说明共享前缀与新生成后缀。

**到此一期完成。** 不要求修复该反馈、不要求提出改进方案或运行 A/B，不要求子分支再次触发同一问题，也不要求整局通关。

## 3. 工程验收边界

- 反馈不推进模型时间、不改变角色物理状态/目标/活动、不轮转服务、不确认警告；宿主调用预算仍有效。反馈关闭时，工具目录和提示词均不承诺该能力。
- 实际发送的请求与最终提交分别留证；调用失败、被拒绝、输出未完成或结果暂时未知不能伪装为成功行动。反馈接收失败不得返回成功收据。
- 真实磁盘验证反馈持久保存、冷开定位、分支恢复及身份隔离；分支发布成功但打开失败时可辨认现存分支，不能盲目再次创建。日志与游戏的非原子边界须有明确恢复/缺口语义。
- 只从支持的已完成 S 分叉。pending E 按正常恢复合同处理，不能为了重新决策而丢弃已发布 E；不支持的位置明确拒绝或显示可选的已完成边界，不静默换位置。
- 轨迹导出只读；以原记录呈现旧输入。源码/配置、GameRevision、模型与呈现版本等可追溯，不记录凭据，不声称拥有提供方未暴露的完整内部推理。
- 同版本续跑必须可用。跨版本只接受应用明确支持的表示升级；不支持时清楚拒绝且不破坏源存档，不以“Gym 化”承诺全面兼容。
- 按改动运行相关构建、测试与 Schema Verify，并回归既有游戏 E/S 恢复、普通无反馈运行和 Console 入口。真实模型试玩验证可用性；确定性夹具验证故障与隔离，不相互替代。

## 4. 二期及延期范围

二期：选取真实问题现场，修改程序/提示词/材料，运行对照并判断效果；进一步建设评测判据、案例归纳和回归集。一期不能提前以“需要证明收益”为由扩入这些工作。

批量并行调度、多模型统计、自动聚类/审批 issue、自动生成补丁、通用 Gym 标准适配、完整原生工具会话恢复、任意 E 中间位置分叉、历史存档长期兼容和专用可视化界面均不要求。首版可串行运行分支；不能在没有跨进程占用证据时默认可并行编辑同一仓库。

历史材料与存档有保留前提。移动/删除原证据后的可用性、独立可分发案例包、跨机器恢复按实际需要扩展；一期必须能识别缺失，不能把哈希或文件名当成证据本身。
