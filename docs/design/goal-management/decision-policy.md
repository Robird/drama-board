# LLM 角色决策规约

状态：2026-10-31，目标能力对应的固定提示词已接入并完成首轮场景试用，真实模型效果见[试玩记录](../../experiments/goal-management-playtest.md)。本文定义提示词的职责与验收，不以接通代码宣称模型行为达标。目标数据与操作语义以[设计草案](design.md)为准。

## 1. 目的与当前基础

让独立模型调用持续关注同一组重要问题：当前处境、既有目标、需要保存的变化以及下一项行动。固定的是决策检查与语义边界，不保证模型给出相同判断或相同行动，也不替代游戏权威校验。

当前 [LlmCharacterController](../../../src/Playground.Completion/LlmCharacterController.cs) 的 `SystemPrompt` 保存共同协议与信息边界，`PromptFor` 按观察能力选择 `GoalGuidance` 或原有 `HandoffGuidance`。目标能力可用时，长期事项由目标记录承载，handoff 保留一次性交接用途。每次请求由完整角色材料重新构造；同一决策回合可有多次请求，控制器不保留 assistant 历史。

首版在这个入口整理并补充行为指引，不建立固定用户消息问答流程，不把 LLM 拆成代码管线中的分析、规划、审查节点，不新增“思考到第几步”的持久状态机。

## 2. 职责分配

| 内容 | 归属与约束 |
| --- | --- |
| 稳定决策纪律 | 系统提示词固定部分：使用可知信息、检查目标与变化、按需保存、遵守提交协议。可供多个角色共用，不夹带某角色的目标、路线或私有知识。 |
| 角色偏好与承诺 | 游戏提供的显式角色材料。决定角色看重什么；先检查危险不意味着强制把自保排在承诺之前。本文不前置人格配置系统，具体偏好只在已有材料或受控实验中表达。 |
| 当前事实与可用操作 | 冻结观察、保留经历和本回合反馈，以及按游戏规则提供的行动说明；不能把地图答案、当前库存或工具可用性写死在固定规约中。 |
| 必须成立的性质 | 代码与测试保证身份隔离、权限、容量、提交原子性、恢复语义和活动边界。提示词提醒不构成这些性质的证明。 |

Human 和 LLM 共用领域规则与角色信息边界；这份规约仅指导 LLM 的决策方式，不要求人类按步骤填写表格。

## 3. 四项决策检查

这些问题构成简短检查框架，不要求逐项输出、逐项工具调用或固定执行顺序。简单局面可以直接选择行动，重大变化才需要更多调查与修订。

| 检查 | 期望行为 |
| --- | --- |
| 现在发生了什么？ | 读取当前身体、活动、最新结果与警告；区分观察、历史记录和推测，使用最新已提供的相关状态。 |
| 哪些既有打算需要重看？ | 对照未结束目标、完成标准和复查线索。方法失效时检查方法及依赖，保留仍成立的目的；允许因新信息、判断或偏好变化修订。 |
| 什么需要跨回合留下？ | 新采纳的承诺、实质进展、方法变更和调查结论按需显式保存；已记录且无相关变化时不重复编辑。 |
| 现在采取什么行动？ | 选择服务于当前意图的合法操作；关键未知会影响选择且值得调查时获取信息。利用已有反馈纠错，避免无意义整理或在拒绝原因未变化时原样重试。 |

保存简短的决策产物及必要依据，例如“原水源耗尽，改去溪流；仍需赠阿青两份水”。不要求完整推理过程、每轮自评报告或分析矩阵；完成检查也不需要额外的确认命令。

调查仅使用当时可用的查询或游戏行动；无耗时查询能力不能凭规约假定存在，探索、移动等仍遵守游戏耗时规则。看到危险需要作出取舍，但不要求每次都打断当前活动；实际取消、继续或移动仍须提交对应行动。

## 4. 同回合续接与提示词候选

新模型请求不等于新游戏回合。每次根据保存的 Context 和反馈接着处理：编辑成功后读取结果继续行动；拒绝后根据原因修正；不能因请求重新开始，就重复创建目标或重写同一份计划。没有额外的阶段游标，也不把自由文本当成已经保存的记忆。

实施时使用[操作合同](operations.md)及[材料规则](capacity-and-context.md)：默认目录列全未结束事项，show 用于展开已有记录，不凭空探索世界。最新成功查询若标为过期，应重查或依据当前目标区，不能将旧详情当现值。敏感修订需简短理由；误判可重开，正常消耗后的新需求另建。不要把这些语义写成每轮必做的管理动作，容量整理也只在实际需要时进行。

以下为行为指引的设计表达；实际已发送文本以 `LlmCharacterController` 及试玩请求记录为准，具体措辞可随实验调整。它不替代现有工具协议、可见性限制及能力说明，也不用于没有目标工具的运行路径：

> 根据当前角色可知的观察、保留经历、目标记录及本回合反馈接续决策。注意身体危险、当前活动和最近结果；区分当前事实、历史成果、他人陈述和自己的推测。
>
> 对照未结束目标检查是否有需要重看的变化。方法失效不自动取消仍成立的目的；切换焦点不撤销其他承诺，也不会取消世界中的活动。是否冒险或改变优先事项，结合角色已提供的偏好、承诺与处境判断。
>
> 新采纳的承诺、重要进展、方法变更或调查结论，需要保留时通过实际可用的编辑操作记录简短内容与必要依据。已经保存且没有相关变化时直接行动，不重复整理。检查同回合反馈，不重复已完成的编辑；拒绝原因未变化时不要原样重试。
>
> 选择当前可用且符合意图的行动。关键未知会影响选择时，考虑是否值得调查；不能把未知当成确定。无需输出检查清单或完整推理，自由文本不等于对白或持久记录。

## 5. 实施顺序与 handoff 迁移

1. 目标工具接通前，保留现有 handoff 能力及其必要指引；可以整理通用检查文字，但不能提示不存在的目标命令。
2. 目标操作、自动材料与反馈可用后，将长期承诺/进展的维护指引迁到目标记录；替换原先要求为这类内容写 handoff 的条款，不叠加两份维护义务。
3. handoff 保留短期、一次性交接用途。不要求将目标已经保存且会自动呈现的内容再抄进去；未启用目标能力的路径继续获得与自身能力一致的指引。
4. 同回合成功、拒绝与后续行动沿现有独立请求接线。耗时行动放行后的结果在下次 Context 中处理，不新增动作后收尾阶段或固定用户提示词流程。

首版可直接维护短固定文本与现有提示词组装点，不前置通用 prompt 模板引擎。实验应保留实际系统提示词、模型配置和角色输入，能区分规约版本；不因此新增游戏 Schema 或角色私有阶段字段。

## 6. 验收与逐步提取机制

结合[用户故事](user-stories.md)观察：方法失效后是否保留目的；否定调查结果能否正确记录；同回合成功编辑后是否继续行动；已知拒绝是否导致调整；无变化时是否避免反复维护；短期 handoff 与目标是否重复。记录真实行动与成本，不以模型声称“已检查”作为证据。

工程检查验证提示词与实际能力一致、角色材料隔离、操作反馈可见和原有提交规则。真实模型运行验证这些指引是否被合理使用；读过提示词或通过确定性测试不等于模型行为通过。比较效果时尽量固定场景、工具、角色材料和模型配置，只改变规约；若同时改变目标工具和提示词，只能报告组合效果，不能单独归因于规约。记录多次运行中的遗漏、重复编辑、重复拒绝、行动结果与调用成本。

遇到反复失败，先检查材料是否缺失、呈现是否歧义、工具是否难用，再决定修改指引或提取代码规则：

- 客观且必须保证的性质直接交给代码，例如权限和原子提交，不等待模型试玩失败才保护。
- 语义已明确但仍依赖判断的习惯先放固定规约，例如区分推测与事实、保留仍有效的目的。
- 何时调查、如何取舍等尚不明确的策略继续由模型尝试；有可复现问题、可机械判断的条件和明确验收时，再提取最小机制。

新增机制需说明触发条件、权威数据和误触发边界，不把一次失败变成通用管线。完整规划器、自动目标判定、固定阶段编排和行为预测继续遵循里程碑的延期条件。
