# 目标管理用户故事与实验场景

状态：2026-10-31，尚未实施。US-01～US-08 支撑[本里程碑](milestone.md)；EX 系列为后续孵化候选，不要求本轮全部开发。故事中的目标命令采用[设计草案](design.md)的语义，不是当前可执行语法。

## 核心故事

### US-01：分工经历多个回合后仍能兑现

**作为与同伴合作的角色，我希望已采纳的承诺持续可见，在离开同伴并经历多个 Context 后仍记得兑现。**

- 情境：阿青提出自己采食物，阿白采水并赠两份；阿白明确采纳，建立补水和赠与目标。
- 过程：采集、使用补给、途中警告或会合使 Context 更换；不每回合重抄 handoff。阿白根据自己的目标继续准备并兑现赠与。
- 验收：后续模型输入仍有未完成赠与事项；真实赠与发生后，角色记录结束说明。若暂时无法会合，事项保留或明确挂起，不能消失或被误称已履行。
- 环境：现有双角色采集、移动、说话和赠与足够；必要时调整路线/库存使分工具有实际价值。另一角色可由人类或明确标注的脚本/代理控制。
- 反例：模型只是按预制脚本赠水、目标从未进入实际输入，不能证明目标管理有效。
- 方法失效变体：原水源暂时耗尽，另有可行来源；控制器保留赠水目的，修改方法或有理由地挂起。相关信息和判断没有变化时，不要求每轮重写约定。可用现有库存/再生制造情境，无需新增封路系统。
- 规约观察：新约定写入目标成功后，根据本回合反馈继续行动，不因下一次独立请求而重复创建；目标已覆盖的长期内容不再要求抄入 handoff。

### US-02：处理临时危险后回到原目的

**作为正在准备补给的角色，我希望临时处理寒冷时不丢掉补给目的，并能区分注意力切换与已开始的活动。**

- 情境：角色聚焦补水，正在采集时收到低温警告；创建临时应对目标并切换焦点。
- 过程：若要离开资源点，按游戏规则明确取消采集再移动；若只是修改计划，则原采集期限保持。安全后返回原补给目标。
- 验收：焦点改变本身不停止活动或确认身体警告；原目标保留进展与来源。临时目标结束后可以重新取得原目标材料，继续或有理由地修订。
- 环境：可复用现有寒冷/庇护与采集；也可用有限的场景初始条件稳定制造中断，不要求新战斗系统。
- 反例：目标恢复导致采集从头计时、背包回滚，或模型只记住新目标而原目标不再可见。
- 决策检查先看危险不等于固定“自保高于一切”的价值排序；本故事按给定处境验证应对与返回，不把一种成功路线写成所有角色的强制流程。

### US-03：一次探索服务两个目的

**作为同时补给与寻找同伴的角色，我希望复用“确认某地标位置”这项成果，同时保留两个来源理由。**

- 情境：父目标分别是找到饮水来源、寻找约定会合点；显式共享“确认溪流湾位置”子目标。
- 过程：探索确认地标，标记子目标完成；查看两条来源关联，继续各父目标尚未完成的部分。
- 验收：两处看到同一目标身份与完成记录，不要求再次探索。完成子目标不自动完成“补给”和“会合”；放弃其中一个父目标不删除另一处需要的成果。
- 环境：可利用已知地图与同行约定，也可增加一个简单地标线索；不需要通用寻人任务系统。
- 反例：按标题复制两份状态造成一处完成一处未完成，或按共享子目标自动宣称所有父目标达成。
- 信息型变体：两个目的共享“核实某地是否有可用水源”，完成标准为取得足以选择路线的依据；探索得到“此处没有可用水源”也能结束调查，记录依据与适用范围，父目标各自调整方法。展开父目标时仍能读取简短调查结论，不因退出近期结束窗口只剩 Completed 标签。答案尚不确定则不能宣称已查明。可用现有地点/资源观察，不要求建设 EX-01 渡口。

### US-04：等待条件期间做别的事

**作为暂时无法推进会合的角色，我希望挂起目标时留下原因和恢复线索，并在下一次决策看见它。**

- 情境：已备好赠物但同伴不在场；挂起赠与/会合目标，写明“再次遇到同伴时检查”，转去探索。
- 验收：挂起目录跨 Context 和冷开仍可见；再次相遇后控制器能恢复目标，之前的进展保留。不要求首版自动触发恢复或唤醒。
- 反例：暂停等于删除；或每轮因为同一挂起原因自动唤醒，无法推进世界。
- 认知边界：保存“同伴说会来；当前未见”，而非擅自改写为“同伴已经违约”。已有线索也可留在 Open 目标中；新的观察由控制器判断是否值得复查，不自动恢复、切焦点或中断 Activity。

### US-05：相同文字不意味着同一份需求

**作为要给自己和同伴分别备水的角色，我希望两个“获取一份水”可以独立存在，不被文本去重。**

- 验收：两条目标身份独立，完成其中一条不自动完成另一条；系统不把一份消耗品分配给两个用途。
- 同时检查：两个父目标明确引用同一个非消耗性目标时可共享成果；暂停共享子目标本身在各处可见，暂停一个父目标不级联暂停其他目的。
- 环境：现有物品数量和赠与规则即可，主要以确定性测试及 UI 检查验证。

### US-06：角色的完成判断不改变世界

**作为维护个人计划的角色，我可以记录自己认为事情完成了，但不能藉此生成物品、完成赠与或触发胜利。**

- 验收：角色在尚未赠水时将赠水目标标记 Completed，仍无库存转移或对方收礼经历；查看时保留这是角色记录的结论。
- 持续目的“保持饮水充足”不因一次喝水自动结束；一次性子目标可单独完成。
- 结果与过程：收到赠水可满足“获得两份水”，不能满足“亲自采集两份水”。系统保存角色判断，试玩检查控制器是否正确区分，不要求宿主自动解析标准。
- 历史与现在：记录“本次已采四份”完成后消耗库存，原历史判断保留；“出发时补给足够”须用当前观察重新检查。需要再次获取时另建目标；误判完成可带理由 reopen 原 ID，有限保留旧判断。已结束说明的文字勘误不改变状态；细节与反例见[合同验收用例](acceptance-cases.md)。
- 环境：不新增内容；用反例测试区分主观状态与客观效果。

### US-07：换控制器、重开和中断后接续

**作为被不同控制器服务的角色，我希望目标、来源和焦点属于自己，换实例或恢复存档后还能继续。**

- 验收：A/B 轮流由同一控制器服务不串目标；Human/LLM 都能读取本角色材料，其他角色不能看见私有目标。
- 在创建并聚焦或修改状态的 E-only 边界中断，恢复不重新询问控制器、不重复生成身份，材料与无中断轨迹一致。S 冷开保留焦点路径及挂起线索。
- 真实模型至少一次暂停后重开，继续使用原目标，而非依靠服务端隐藏聊天历史。

### US-08：列表增长仍可掌握未完成事项

**作为新 Context 中的控制器，我希望看见有哪些未结束事项，不能因它们不在焦点就完全遗漏。**

- 验收：焦点详细展开，其余 Open/Paused 在限定容量内完整列出，存在详情入口；共享目标去重但保留来源提示。
- Open 和 Paused 都计入未结束容量，挂起不能规避限额；非焦点目标的已有复查线索仍可见。角色自述进展有明确标识，不替代当前库存，目标材料也不能挤掉危险、活动与合法操作信息。
- 达到数量或长度上限时编辑明确拒绝或要求整理，不截掉末尾目标。循环链接/无效引用拒绝且无部分更新。
- 规约反例：编辑被拒绝且原因仍成立，模型不能因重新调用就原样重复；应利用反馈修正或选择其他合法操作。宿主预算继续兜底，不以提示词代替防止无界调用的工程约束。
- full/delta、历史重绘与纯模型输入含义一致；历史观察不因今天修改目标而变更。近期结束目录有界，存储保留规则另有验证。

## 扩展孵化场景（非本轮全量要求）

| 场景 | 可新增的最小内容 | 要探索的问题 | 重开条件 |
| --- | --- | --- | --- |
| EX-01 夜间渡口 | 渡口有开放时间，附近有可探索地点 | 挂起后如何按时间提醒；“值得重看”与“自动恢复”的差别 | 真实运行反复忘记带时间条件的挂起事项 |
| EX-02 共用工具 | 修桥与建营都需要一把斧头 | 非消耗性成果共享、工具暂不可用与“已经取得”的区别 | 显式 GoalLink 不足以说明成果有效性 |
| EX-03 救援补给 | 多个伤员各需要一份药物 | 同文目标、数量与分配，不能用同一份资源重复满足 | 需要超出个人笔记的可验证交付规则 |
| EX-04 路线封闭 | 临时封路及一条替代路线 | 放弃方法但保留上层目的，旧成果过期后如何修订 | 已完成目标需要重开/替代的实际证据 |
| EX-05 托付与误解 | 同伴承诺送物，之后改变主意 | 自己采纳的目标、对方所述承诺与公共任务的区别 | 双方私有目标加说话不能充分表达协作 |

这些内容可就地扩展或作为独立小实验场景；选择依据是能够隔离目标管理问题、便于复跑和解释，而不是增加游戏体量。跨场景复用时，不为具体地名/角色在目标模块中增加分支。

## 实验记录要求

记录场景初态、规则/模型版本、各角色控制来源、实际输入与提交、目标在各 Context 的可见材料、活动及世界结果。分开记录系统是否正确保存/呈现与模型是否合理使用。失败、误标完成、频繁编辑或没有回到原目标都应保留；可用固定脚本制造情境，但实际模型选择不能由脚本代填。

同时保留实际固定系统提示词和调用配置，按[角色决策规约](decision-policy.md)检查同回合续接、重复编辑/拒绝、无变化时直接行动及 handoff 双写负担；观察实际提交，不要求模型输出检查清单或完整推理。比较规约效果时保持工具和角色材料尽量一致；目标能力与提示词同时变化只能说明组合效果，不单独归因于提示词。

首轮优先将“方法失效仍兑现”并入 US-01，将“否定答案完成共享调查”并入 US-03；US-06 的历史/当前条件和结果/过程反例可先用确定性提交及呈现检查覆盖，再观察模型是否误读。它们细化已有三类核心玩法，不要求另做完整游戏或所有 EX 场景。确定性测试能证明保存与展示的语义，不能证明 LLM 会正确判断。

验收记录真实交付/逃离结果、承诺遗漏、误标完成、无必要焦点切换、编辑调用数和材料长度；不以完成目标数量、拆分数量或编辑频率作为奖励。未来比较 handoff 基线、目标材料、目标材料加复查提示时，尽量固定初态与脚本干预，并做多次模型运行；说明无法控制的交互措辞与时机差异，不由单局结果推断因果。宿主可用真实事件和私有目标辅助评分，不能将其他角色私有目标或未知地图注入被评测角色的输入。
