# 角色目标管理设计草案

状态：2026-10-31。目标图、独立焦点、显式状态、自动呈现及与 Activity 分离的方向已获用户认可。本稿吸收[跨领域研究](../../research/goal-management/README.md)，并在内部反例审查后逐项确定首版实施合同。以下是待实现的设计，不是现有生产 API；尚需处理的问题集中在末节。

## 1. 三种独立的信息

- **目标（Goal）**：角色想达成什么，为什么，已经推进到哪里。
- **焦点（Focus）**：当前优先围绕哪个目标思考，以及从哪条目的路径进入。
- **活动（Activity）**：世界里已经开始的耗时过程，由原游戏规则推进。

函数栈适合展示“为了什么而处理当前子问题”。持久目标采用图，焦点采用路径，不以严格 LIFO 栈保存全部意图。切换、结束或挂起目标不会撤销移动、取消采集或重设期限；角色仍须提交独立的游戏行动。

Focus 不代表角色的全部承诺，也不代表一种固定方法。目标材料应同时说明想达成什么、当前打算怎么做；方法失效时先检查方法及其依赖，不静默取消上层目的。角色可以因新观察、重新理解已有信息、发现计划错误或改变偏好而修订目标；重要约定的修订留下简短理由。没有相关变化时直接行动，不要求每个 Context 都更新目标。

配套的[角色决策规约](decision-policy.md)将这些语义组织为简短的系统提示词行为指引。它固定检查问题，不固定角色价值排序或模型行动；强约束仍由代码保证。首版不建立固定用户消息流程或持久化思考阶段。

## 2. 目标与来源关联

首版数据职责（尚未实现）：

| 对象 | 最小信息及职责 |
| --- | --- |
| Goal | 稳定 ID、标题/想达成的结果、完成标准、状态、进展、下一步提示；可选复查线索，挂起原因或结束说明 |
| GoalLink | 独立关联 ID、父目标 ID、子目标 ID、该来源为什么需要此目标 |
| Focus | 当前目标及选定的来源路径；路径可以只包含一个目标 |
| 角色目标集合 | 该角色的目标、关联和焦点；属于游戏根下角色私有状态 |

来源可先用角色写下的文字表达，已有感知/操作身份可按实际需要附引用；不以自然语言实体抽取或完整经历档案作为前提。

同一 Goal 可被多个父目标引用；每条 GoalLink 保留自己的理由。同文目标允许拥有不同身份。只有显式关联才表示复用同一次成果，不按文字相同自动合并。

例如“确认溪流湾位置”可以同时服务补水与寻找同伴；“获取一份水给自己”和“获取一份水给同伴”不能因为标题都叫取水而抵扣同一份消耗品。首版不推断数量需求、预留和分摊。

首版以无环有向图表达父子目的，拒绝自身引用、环和无效 ID；同一父子对最多一条关联，理由可显式修改，不因重复提交另建平行边。不借父子关系表达执行先后、AND/OR 依赖或自动完成条件。子目标完成不自动完成父目标，父目标结束不级联删除子目标或其他来源。无父目标的未结束事项仍可存在并被发现。

### 2.1 完成标准：结果、过程与有效时间

完成标准需说明所要求的结果或过程，以及何时需要它成立；这是文本编写规则，不新增目标类型枚举或条件执行器。

| 标准示例 | 含义与反例 |
| --- | --- |
| 获得两份水 | 采集或接受赠与都可能满足；是否要求当前仍持有，应在标准中说明 |
| 亲自采集两份水 | 要求特定过程，收到赠水不算达成 |
| 本次已采到四份水 | 历史成果；后来喝水不抹掉已经发生的采集 |
| 出发时携带足够到达出口的饮水 | 出发前须结合当前库存和角色所知路线重新判断，旧采集记录不足以证明 |
| 旅途中保持饮水充足 | 持续目的；一次补给不意味着永久完成，可包含多次补给子目标 |

上述区分借鉴 [HTN 的结果与过程语义](../../research/goal-management/ai-planning.md)及[行动与效果评估](../../research/goal-management/military.md)，不继承自动规划算法。Completed 保存角色当时的完成判断，不是对当前库存或持续条件的实时保证。

一次性成果后来被消耗或失效，保留原完成记录，需要再取得时另建目标；持续目的在其适用期间保持 Open 或显式 Paused，期间结束后可显式记录结束判断。发现原完成判断错误属于更正，不能伪装成“成果后来失效”；按第 3 节显式重开并保留更正依据。系统检查操作结构，不自动判断自然语言是否诚实或成果是否有效。

### 2.2 信息获取也是可完成的工作

“核实渡口是否开放”的完成标准可以是“取得足以决定路线的可知依据，并记录结论及其时点/适用范围”。可靠的“关闭”答案也能完成调查；“经渡口离开”则需要改方法。没有取得足够信息时记录未知、继续调查或挂起，不能为了关闭目标而编造答案。

多个父目标可以显式共享这项调查及其结论；共享不意味着上层目的自动完成，也不意味着结论永久有效。后来开放状态改变，可启动新的调查，不抹去当时的调查结果。来源、结论和适用范围先用进展/结束说明表达，无需 InvestigationTask 或完整证据图谱。

展开父目标详情时，应能看到其引用的已结束子目标的简短结论及适用范围，不能只显示 Completed 而丢失“渡口关闭”的答案。近期结束窗口与存储保留分开；有任何关联的目标不可 forget，必须先显式解绑，见[容量政策](capacity-and-context.md)。

### 2.3 关键假设与复查线索

复查线索回答“依赖什么尚未确定或可能变化的信息，以及何时值得重新看”。例如：`待核实渡口是否开放；若关闭，改选出口。` 首版采用独立可选 revisit 字段，Open 和 Paused 的默认目录均展示；暂停的恢复线索是其用途之一，不另建两套近义机制。

线索是控制器可读文本，不是事件订阅或调度条件；没有线索也不禁止重新考虑。有线索不自动唤醒、恢复、聚焦或取消 Activity。只记录影响行动的短依据与下一项检查，不要求保存完整推理过程或每轮填写分析矩阵。

私有目标文字可记录“阿青说会来”“猜测他在途中”“尚未确认”，呈现时应保留这些限定，不能改写成已验证的世界事实。观察到缺席不等于确认违约，暂时切换行为也不等于放弃。首版通过指引和反例约束这种使用，不做语义自动核验；他人意图识别、数值置信度及证据图谱继续延期。

## 3. 状态与焦点

| 状态 | 含义 |
| --- | --- |
| Open | 仍打算完成；不保证当前可执行，也不表示正在物理执行 |
| Paused | 暂时不推进，保留原因和恢复线索 |
| Completed | 已记录角色的完成判断及说明 |
| Abandoned | 不再追求，保留放弃原因 |

Open 与 Paused 都属于“未结束”。Focus 不作为第五种状态；自动条件判断延期。

### 3.1 显式转换与更正

| 操作 | 允许前态 → 后态 | 必要信息与效果 |
| --- | --- | --- |
| create | 不存在 → Open | 分配新身份；不按文字合并 |
| pause | Open → Paused | 非空挂起原因；可同时设置复查线索 |
| resume | Paused → Open | 清除当前挂起原因，保留进展和复查线索；不自动聚焦 |
| finish | Open / Paused → Completed / Abandoned | 非空结束说明；清除当前挂起原因，不级联结束子目标 |
| reopen | Completed / Abandoned → Open | 非空理由；保留身份、关联和进展，将原结束判断记入有限修订记录后清除当前结束说明；不自动聚焦 |

未列出的状态转换明确拒绝，重复 pause/finish 等不作为静默成功。恢复或重开后是否聚焦由显式操作决定；重开需满足未结束额度，超额时包括留痕在内全部不变。原完成判断错误或重新采纳已放弃目的可 reopen；成果后来正常消耗则另建，避免将多次履行揉成一次历史。

普通 update 只编辑未结束目标的文字，不改状态和焦点。修改标题/目的或完成标准必须附短理由并保留旧值。已结束目标只允许带理由勘误结束说明；若需修改其目的、标准、进展或下一步，先 reopen。不能用更新标准悄悄覆写旧完成判断；宿主只能保证显式字段和留痕，无法证明文字含义没有偷换。

每个目标保留最近 3 条敏感修订：reopen、标题/目的或完成标准变化、已结束说明勘误。记录原状态、原标题、原标准、原结束说明、修订理由及角色内的 Context/操作序号对；同次多字段修改只追加一条，满时裁掉最旧一条。普通进展更新不产生第二份审计日志。这不是完整承诺审计或永久历史；已保留的旧冻结观察不被改写，也不承诺历史 Context 永久留存。默认数值及查看规则统一在[容量政策](capacity-and-context.md)。

### 3.2 来源路径与回退

挂起只改变指定 Goal，不递归暂停子图。若共享子目标本身被挂起，各引用处均看到该状态；若某个父目标被挂起，另一父目标仍可使用共享子目标。界面应说明这两种作用范围。

Focus 是有序 Goal ID 路径，相邻目标间必须有实际的父 → 子关联，末端必须为 Open。指定目标而不提供路径时，明确表示单节点路径 `[目标]`；不推测父来源、不恢复旧焦点栈。提供路径时必须以该目标结尾，整条验证失败则不修改 Focus。

路径上的 Paused / Completed / Abandoned 祖先允许保留为来源背景，必须显示状态。Paused 仍是未结束事项，不能因出现在路径上推断它正在推进；Completed / Abandoned 不呈现为当前仍追求的目的。挂起或结束祖先不移动末端焦点，也不暂停后代。共享子目标的其他父来源仍在详情中可见，未选中不等于删除。

挂起或结束焦点末端时，在原路径上从近到远寻找最近仍 Open 的祖先，保留到它为止的前缀；没有则清空。不跳到另一条父分支，不选任意未结束目标。结束独立临时目标后不自动回到之前的另一个独立目标，后者仍在完整未结束目录中，角色可显式聚焦。

首版提供 unlink，删除指定来源关联，不删除两端目标或改变其状态。若删除的关联位于 Focus 路径中，保留包含原末端的最长有效后缀；单节点路径始终合法。该变化与 unlink 同次原子提交，并在反馈中说明。首版不另建 reparent：先 link 新来源，再 unlink 旧来源；若关联额度已满可反向操作，中间无父来源的目标仍合法且可发现。无需两个操作间保持图连通。

这些规则只维护注意力和解释路径，不自动执行、恢复或取消任何世界活动。

“保持水分充足”是持续目的，可长期 Open；“本次补充两份水”可成为一次性子目标。系统不因短暂满足持续条件就永久关闭长期目的。

## 4. 操作与提交

```text
create-goal {"title":"准备补给","criteria":"出发时有足够饮水","focus":true}
pause-goal {"id":"G1","reason":"目前没有可用水源","revisit":"发现新水源时重看"}
show-goal {"id":"G1"}
```

首版选用固定命令名 + 严格 JSON 对象，Human/LLM 共用语法和权威校验，不新增通用 DSL。创建、可选父关联及聚焦可一次原子提交；字段/状态/额度错误全部拒绝。完整字段、身份和原子范围统一见[操作合同](operations.md)，人类易用性与模型转义成本需实测。`pause` 与 `suspend` 不建立两套近义状态。

show 是目标图/物理世界只读的**记录式查询**：交互结果与身份写入 E/S，使独立模型调用和重开能续读；它不是完全无副作用的工具。新的纯详情投影函数可复用，但不另加本地工具循环。

首版不自动理解完成标准；角色的完成判断仍是主观记录。世界的逃离、赠与和库存只由游戏事实决定。将来引入可验证目标时，明确区分角色判断与规则验证，不追溯篡改当时认知。

`update` 的字段与状态限制见第 3 节。不能把“赠水给同伴”悄悄改成“自己有水”再声称兑现原承诺；这是控制器指引，宿主只校验明确操作和留痕，不能保证自然语言语义不被偷换。复查本身不要求新增命令：读取当前观察、比较目标材料，必要时使用编辑操作即可。

## 5. 自动进入上下文

默认材料展开焦点、上层理由、完成标准、进展、下一步和复查线索，同时保留所有其他未结束目标的简短目录。目录包含身份、状态、简短目的及已有复查线索，不能只有标题而藏起恢复条件。不能只保存于可选工具背后，让新 Context 不知道还有哪些事项。

```text
目标记录（角色自述；库存与危险以当前观察为准）
当前焦点：离开山林 → 准备补给 → G7 获取四份水
标准：本次累计亲采四份水。进展：上次记录已采两份。
下一步：继续采集。复查：若原水源耗尽，改换来源。
其他未结束：G8 [Open] 赠阿青两份水；G9 [Open] 调查山脊出口。
挂起：G10 [Paused] 与阿青会合；原因：当前不在场；复查：再次相遇时检查。
最近结束：G6 [Completed] 抵达溪流湾；角色已记录到达。
```

数量/文本上限、完整目录、直接关联结论、显式 forget 和清理出口统一见[容量与 Context 投影](capacity-and-context.md)。Open 与 Paused 都占未结束额度，聚焦或挂起不释放额度；共享目标按身份去重并保留来源。容量是材料规模限制，不是工作量或绩效指标。近期结束和回执窗口只控制展示，不能用 UI 隐藏冒充存储回收。

长期进展文字可能已过时，不能渲染成自动同步的库存/位置事实。当前观察保持权威，目标材料明确属于角色记录；不为更新数字每回合强制重抄。目标预算须与 Context 总预算配合，保留身体危险、当前活动和合法操作所需信息，不能用增加目标容量挤掉生存决策材料。

目标正文不应成为第二份每回合复制的 handoff。handoff 保持一次性交接用途，目标负责长期未完成事项；新约定由角色明确采纳为目标，收到一句话不自动承担承诺。目标编辑属于私有认知，不自动发送给他人。

目标能力接入时同步替换长期事项的 handoff 提示条款，不要求双写；接入前保持现有可用指引。固定规约不包含角色私有目标或当前世界答案，每次请求依据本角色保存的材料续接；同一 Context 中已成功编辑的事项不因重新调用模型而再次创建。具体接线与验收统一见[规约设计](decision-policy.md)。

冻结 Opening 与有序 Item 携带当时可见的目标快照；当前完整输入只投影一次该边界的默认目标区、有限短回执及最近有效 show。历史不读取今天的可变目标来替换旧观察，也不重复回显所有目标长编辑；原始提交仍保存。完整模型输入与 Console full/delta 来自同源材料，详情失效在 delta 中也须明确提示，游标不是目标存储权威。

## 6. 状态归属与工程接线

在 [CharacterInteractionState](../../../src/ResourceCycle/CharacterContext.cs) 所在角色私有状态中设置独立目标集合及计数，不能仅附着于 CurrentContext 或控制器字段。目标操作走现有原始提交、校验、Fact、E/S 路径；恢复已发布编辑不再次调用模型，不重新生成目标 ID。初始化、能力启用和具体源码接线见[操作合同](operations.md)。

目标编辑不耗模型时间，不改变活动、身体、库存、随机序列或确认待响应警告。成功编辑/show/no-op 与 handoff 一样轮转服务，拒绝不轮转；均保存交互元数据，Context 保持 Open。只在已有合法输入机会执行，移动中有输入机会也可使用。模型调用预算和既有同刻护栏继续有效，不允许靠编辑清零；不新增通信发送额度。

局部目标规则和数据应避免依赖 ResourceCycle 的具体植物、地图与 NPC；游戏组合负责关联行动、Context、控制器和发布。先在应用中形成清楚边界，之后按证据提取模块；不向 Kernel 填入目标解释器，不复活归档可执行程序系统。

## 7. 剩余问题与重开条件

| 问题 | 当前裁决/默认 | 需要的下一类证据 | 是否阻塞第一施工切片 |
| --- | --- | --- | --- |
| 限额、目录密度及 JSON 操作是否易用 | 采用容量文档的数值与操作合同，不静默截断 | 最大合法输入渲染、Human 操作、模型转义失败和整理成本 | 否；默认预算若装不下须在施工验收前调整 |
| Focus 回退与三条更正记录是否足够 | 确定性路径回退与有限修订，无隐藏栈 | US-02/US-06 中恢复旧意图和更正的实际困难 | 否 |
| 复查线索/规约是否改善实际兑现 | 独立短字段、固定提示词，世界事实与角色记录分开 | 真实模型遗漏、误标完成、切换、编辑成本与结果 | 否；是里程碑 C 的验收，不由文档定论 |
| 是否需要更多历史或查询材料 | 当前目标完整有界；一次有效 show；成功 Item 沿用既有保留 | 长局存储/Context 压力，反复丢失已查信息的可复现样本 | 否；不前置通用召回或新持久视图槽 |
