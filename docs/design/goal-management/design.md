# 角色目标管理设计草案

状态：2026-10-31。目标图、独立焦点、显式状态、自动呈现及与 Activity 分离的方向已获用户认可。本稿进一步吸收[跨领域研究](../../research/goal-management/README.md)中用户认可的建议，明确目的与方法、完成标准、复查线索和认知边界。以下类型和命令仍是候选形状，尚无对应生产 API；待裁决细节集中在末节。

## 1. 三种独立的信息

- **目标（Goal）**：角色想达成什么，为什么，已经推进到哪里。
- **焦点（Focus）**：当前优先围绕哪个目标思考，以及从哪条目的路径进入。
- **活动（Activity）**：世界里已经开始的耗时过程，由原游戏规则推进。

函数栈适合展示“为了什么而处理当前子问题”。持久目标采用图，焦点采用路径，不以严格 LIFO 栈保存全部意图。切换、结束或挂起目标不会撤销移动、取消采集或重设期限；角色仍须提交独立的游戏行动。

Focus 不代表角色的全部承诺，也不代表一种固定方法。目标材料应同时说明想达成什么、当前打算怎么做；方法失效时先检查方法及其依赖，不静默取消上层目的。角色可以因新观察、重新理解已有信息、发现计划错误或改变偏好而修订目标；重要约定的修订留下简短理由。没有相关变化时直接行动，不要求每个 Context 都更新目标。

配套的[角色决策规约](decision-policy.md)将这些语义组织为简短的系统提示词行为指引。它固定检查问题，不固定角色价值排序或模型行动；强约束仍由代码保证。首版不建立固定用户消息流程或持久化思考阶段。

## 2. 目标与来源关联

候选数据形状：

| 对象 | 最小信息及职责 |
| --- | --- |
| Goal | 稳定 ID、标题/想达成的结果、完成标准、状态、进展、下一步提示；可选复查线索，挂起原因或结束说明 |
| GoalLink | 独立关联 ID、父目标 ID、子目标 ID、该来源为什么需要此目标 |
| Focus | 当前目标及选定的来源路径；路径可以只包含一个目标 |
| 角色目标集合 | 该角色的目标、关联和焦点；属于游戏根下角色私有状态 |

来源可先用角色写下的文字表达，已有感知/操作身份可按实际需要附引用；不以自然语言实体抽取或完整经历档案作为前提。

同一 Goal 可被多个父目标引用；每条 GoalLink 保留自己的理由。同文目标允许拥有不同身份。只有显式关联才表示复用同一次成果，不按文字相同自动合并。

例如“确认溪流湾位置”可以同时服务补水与寻找同伴；“获取一份水给自己”和“获取一份水给同伴”不能因为标题都叫取水而抵扣同一份消耗品。首版不推断数量需求、预留和分摊。

建议首版以无环有向图表达父子目的，拒绝自身引用、环和无效 ID；不借父子关系表达执行先后、AND/OR 依赖或自动完成条件。子目标完成不自动完成父目标，父目标结束不级联删除子目标或其他来源。无父目标的未结束事项仍可存在并被发现。

### 2.1 完成标准：结果、过程与有效时间

完成标准需说明所要求的结果或过程，以及何时需要它成立；这是文本编写规则，不新增目标类型枚举或条件执行器。

| 标准示例 | 含义与反例 |
| --- | --- |
| 获得两份水 | 采集或接受赠与都可能满足；是否要求当前仍持有，应在标准中说明 |
| 亲自采集两份水 | 要求特定过程，收到赠水不算达成 |
| 本次已采到四份水 | 历史成果；后来喝水不抹掉已经发生的采集 |
| 出发时携带足够到达出口的饮水 | 出发前须结合当前库存和角色所知路线重新判断，旧采集记录不足以证明 |
| 旅途中保持饮水充足 | 持续目的；一次补给不意味着永久完成，可包含多次补给子目标 |

上述区分借鉴 [HTN 的结果与过程语义](../../research/goal-management/ai-planning.md)及[行动与效果评估](../../research/goal-management/military.md)，不继承自动规划算法。Completed 保存角色当时的完成判断，不是对当前库存或持续条件的实时保证。

首版设计默认：一次性成果后来被消耗或失效，保留原完成记录，需要再取得时另建目标；持续目的在其适用期间保持 Open 或显式 Paused，期间结束后可显式记录结束判断。发现原完成判断错误属于更正，不能伪装成“成果后来失效”；更正/重开的具体操作及留痕政策仍在末节裁决，不借本条隐含禁止更正。

### 2.2 信息获取也是可完成的工作

“核实渡口是否开放”的完成标准可以是“取得足以决定路线的可知依据，并记录结论及其时点/适用范围”。可靠的“关闭”答案也能完成调查；“经渡口离开”则需要改方法。没有取得足够信息时记录未知、继续调查或挂起，不能为了关闭目标而编造答案。

多个父目标可以显式共享这项调查及其结论；共享不意味着上层目的自动完成，也不意味着结论永久有效。后来开放状态改变，可启动新的调查，不抹去当时的调查结果。来源、结论和适用范围先用进展/结束说明表达，无需 InvestigationTask 或完整证据图谱。

展开父目标详情时，应能看到其引用的已结束子目标的简短结论及适用范围，不能只显示 Completed 而丢失“渡口关闭”的答案。近期结束窗口与关联成果的可读取性分开；仍有未结束来源引用的记录如何保留/清理，纳入容量政策统一裁决。

### 2.3 关键假设与复查线索

复查线索回答“依赖什么尚未确定或可能变化的信息，以及何时值得重新看”。例如：`待核实渡口是否开放；若关闭，改选出口。` Open 和 Paused 都可携带；暂停的恢复线索是其用途之一，不另建两套近义机制。具体使用独立可选字段还是现有正文，在操作形状收敛时决定。

线索是控制器可读文本，不是事件订阅或调度条件；没有线索也不禁止重新考虑。有线索不自动唤醒、恢复、聚焦或取消 Activity。只记录影响行动的短依据与下一项检查，不要求保存完整推理过程或每轮填写分析矩阵。

私有目标文字可记录“阿青说会来”“猜测他在途中”“尚未确认”，呈现时应保留这些限定，不能改写成已验证的世界事实。观察到缺席不等于确认违约，暂时切换行为也不等于放弃。首版通过指引和反例约束这种使用，不做语义自动核验；他人意图识别、数值置信度及证据图谱继续延期。

## 3. 状态与焦点

| 状态 | 含义 |
| --- | --- |
| Open | 仍打算完成；不保证当前可执行，也不表示正在物理执行 |
| Paused | 暂时不推进，保留原因和恢复线索 |
| Completed | 已记录角色的完成判断及说明 |
| Abandoned | 不再追求，保留放弃原因 |

Open 与 Paused 都属于“未结束”。Focus 不作为第五种状态。首版以显式 pause/resume/finish 修改状态；自动条件判断延期。

挂起只改变指定 Goal，不递归暂停子图。若共享子目标本身被挂起，各引用处均看到该状态；若某个父目标被挂起，另一父目标仍可使用共享子目标。界面应说明这两种作用范围。

焦点需指向 Open 目标。多父来源不能默默选错；可通过关联或明确路径选择，具体语法待定。路径中已结束/挂起祖先能否作为纯理由保留，以及路径变更规则，实施前统一裁决。

建议结束或挂起当前焦点后，退回原路径上最近仍 Open 的祖先；没有则清空焦点并展示其他未结束事项。只改变注意力，不自动执行下一个任务。此回退政策为待验证默认，不是引擎调度规则。

“保持水分充足”是持续目的，可长期 Open；“本次补充两份水”可成为一次性子目标。系统不因短暂满足持续条件就永久关闭长期目的。

## 4. 操作草案

```text
create-goal ... [--parent G1] [--focus]
link-goal G3 --parent G2 --reason ...
update-goal G3 ...
focus-goal G3 [--via ...]
pause-goal G3 --reason ... --revisit ...
resume-goal G3
finish-goal G3 --outcome completed|abandoned --note ...
```

语法和参数并未冻结。Human/LLM 共用目标语义与权威校验；不要求把带文本字段的编辑硬塞成难转义的命令。应有可发现的只读查看入口，创建并聚焦可原子提交以减少管理调用。`pause` 与 `suspend` 不建立两套近义状态。

首版不自动理解完成标准；角色的完成判断仍是主观记录。世界的逃离、赠与和库存只由游戏事实决定。将来引入可验证目标时，明确区分角色判断与规则验证，不追溯篡改当时认知。

`update` 可更新方法、进展和复查线索，不默认改变状态或焦点。调整完成标准需显式指出变更及简短原因，不能把“赠水给同伴”悄悄改成“自己有水”再声称兑现原承诺；此为控制器指引，宿主只校验明确的操作结构，不能保证自然语言语义不被偷换。已结束记录如何更正须随留痕政策一并确定。复查本身不要求新增命令：读取当前观察、比较目标材料，必要时使用现有候选编辑操作即可。

## 5. 自动进入上下文

默认材料展开焦点、上层理由、完成标准、进展、下一步和复查线索，同时保留所有其他未结束目标的简短目录。目录包含身份、状态、简短目的及已有复查线索，不能只有标题而藏起恢复条件。不能只保存于可选工具背后，让新 Context 不知道还有哪些事项。

```text
目标记录（角色自述；库存与危险以当前观察为准）
当前焦点：离开山林 → 准备补给 → G7 获取四份水
标准：本次累计亲采四份水。进展：上次记录已采两份。
下一步：继续采集。复查：若原水源耗尽，改换来源。
其他未结束：G8 [Open] 赠阿青两份水；G9 [Open] 调查山脊出口。
挂起：G10 [Paused] 与阿青会合；原因：当前不在场；复查：再次相遇时检查。
最近结束：G6 [Completed] 抵达溪流湾；角色已记录到达。
```

首版以明确的数量和文本上限控制材料大小；达到上限应反馈并要求整理，不能静默删除未结束事项。Open 与 Paused 都占未结束额度，按目标身份计数，关联及文本另有上限；聚焦或挂起不释放额度。该容量是材料预算，不是工作量估算或绩效指标。共享目标按身份去重，但可显示多个来源。结束记录的默认展示窗口与持久保留政策必须分别规定，不能用 UI 隐藏冒充存储回收。

长期进展文字可能已过时，不能渲染成自动同步的库存/位置事实。当前观察保持权威，目标材料明确属于角色记录；不为更新数字每回合强制重抄。目标预算须与 Context 总预算配合，保留身体危险、当前活动和合法操作所需信息，不能用增加目标容量挤掉生存决策材料。

目标正文不应成为第二份每回合复制的 handoff。handoff 保持一次性交接用途，目标负责长期未完成事项；新约定由角色明确采纳为目标，收到一句话不自动承担承诺。目标编辑属于私有认知，不自动发送给他人。

目标能力接入时同步替换长期事项的 handoff 提示条款，不要求双写；接入前保持现有可用指引。固定规约不包含角色私有目标或当前世界答案，每次请求依据本角色保存的材料续接；同一 Context 中已成功编辑的事项不因重新调用模型而再次创建。具体接线与验收统一见[规约设计](decision-policy.md)。

冻结 Opening 与有序 Item 应携带当时可见的目标材料；渲染历史不读取今天的可变目标来替换旧观察。完整模型输入与 Console full/delta 来自同源材料，delta 游标不是目标存储权威。

## 6. 状态归属与工程接线

复用 [CharacterInteractionState](../../../src/ResourceCycle/CharacterContext.cs) 所在的角色私有状态边界，具体是否另设子对象由实施方案决定。不能仅附着于 CurrentContext 或控制器字段，否则换回合/换实例会丢。目标操作走现有原始提交、校验、Fact、E/S 路径；恢复已发布编辑不再次调用模型，不重新生成目标 ID。

目标编辑不耗模型时间，不改变活动、身体、库存、随机序列或默认确认待响应警告。合法编辑、非法编辑、服务轮转与防止零时间循环的具体合同在实施时与现有 handoff 对齐核验。模型调用预算仍有效，不允许靠编辑清零。

局部目标规则和数据应避免依赖 ResourceCycle 的具体植物、地图与 NPC；游戏组合负责关联行动、Context、控制器和发布。先在应用中形成清楚边界，之后按证据提取模块；不向 Kernel 填入目标解释器，不复活归档可执行程序系统。

## 7. 实施前需收敛的细节

1. 目标数、关联数、正文长度及结束记录保留限额；清理关联时如何保持来源与历史观察有效。
2. Focus 路径的选择/回退，父目标结束后共享子目标的可发现呈现，目标解绑或重挂的首版需求。
3. 按“一次性成果失效则另建”的默认设计，进一步确定错误完成判断的更正/重开、已结束文字编辑和完成标准变更的留痕方式；保留当时判断，不要求无限历史。
4. 多字段编辑与创建并聚焦的原子形状、纯查询入口、同刻交互规则；不为批量编辑引入通用 DSL。
5. 复查线索的具体字段与目录长度；场景判据与角色自评如何并列记录。真实交付、遗漏、误标完成、无必要切换与管理成本分别评估，不用完成目标数作成功指标；实际模型失败应保留。

这些问题影响实施合同，但不妨碍先确定用户故事和范围；不能把候选字段/命令写成现有能力。
