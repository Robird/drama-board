# 角色目标管理里程碑

状态：2026-10-31，方向已采纳，尚未施工。机制细节见[设计草案](design.md)，可观察行为见[用户故事](user-stories.md)。

## 1. 要得到的能力

Human 或 LLM 为角色创建、维护和切换目标；目标随游戏状态保存，未结束事项自动进入该角色后续 Context。角色可以处理中断、挂起暂时推进不动的事情，并复用服务于多个目的的子目标。系统保存和呈现意图，世界规则决定实际结果。

将游戏环境作为这项可复用能力的孵化器。优先复用 ResourceCycle 的角色、移动、采集、赠与、身体需求和持久化；允许为验证目标管理扩展内容或增加小场景，不要求先做成完整的新游戏。具体地图、命令、数值与实验安排可在实施中调整，但不得把“目标可编辑”当作跨回合目标管理已经验收。

## 2. 首版范围

1. 角色私有的目标记录、独立身份、完成标准、进展和续接/复查提示；不同角色不共享唯一可变副本。文本明确目的与方法、结果与过程、历史成果与当前条件；信息获取可作为普通目标，不增设专用目标类型或自动条件判断。
2. 父子来源关联和显式共享子目标；同文目标可独立存在，不以文本相等自动合并。关系保留来源理由，不承担自动依赖调度。
3. 独立焦点及来源路径；Open、Paused、Completed、Abandoned 状态。切换/挂起目标不改变已经开始的 Activity。
4. 创建、更新、关联、聚焦、挂起、恢复和结束操作，以及可发现的查看入口。具体语法可调整；创建并聚焦宜支持一次提交。
5. 未结束事项跨 Context 自动呈现：焦点详细展开，其他 Open 与 Paused 目标保留完整的有界目录及已有复查线索；两类都计入容量。结束目标提供有限近期摘要与明确查看/保留政策，目标记录不冒充当前世界观察。
6. 接通 Human Console 与现有 Completion 控制器，复用冻结材料、操作反馈及 full/delta 呈现；不依赖控制器私藏历史。
7. 真实 S 冷开与 E-only 恢复、原有游戏回归、角色隔离和容量边界验证。
8. 配套的[LLM 角色决策规约](decision-policy.md)：整理固定系统提示词，按当前能力指导目标维护与行动；不强制逐项输出，不新增固定用户消息流程或代码阶段管线。

目标管理是零模型耗时的显式状态编辑，不能无限新增材料或用编辑操作规避宿主调用预算。同刻预算、服务轮转和警告确认规则须在实施合同中明确；不默认照搬通信发送额度。

## 3. 建议推进顺序

| 切片 | 可运行交付 | 退出条件 |
| --- | --- | --- |
| A：目标模型与状态闭环 | 目标/关联/焦点的局部规则及持久提交，最小 Console 操作 | 身份、关系、状态、焦点不变量有行为证据；冷开及 pending 恢复不重做决定 |
| B：跨 Context 工作材料与决策规约 | 自动目标目录、焦点详情、编辑反馈，Human/LLM 同源输入；固定指引随目标能力接通 | 换 Context 后未结束事项仍可见；长期事项无需与 handoff 双写；同回合反馈可用于续接；容量与私有性明确 |
| C：玩法孵化与真实模型验证 | 三类核心场景、必要的小型内容扩展、真实模型运行与修订 | 记录目标材料如何影响行动，完成下述验收；不能只由脚本代写正确目标来证明 LLM 会使用 |

切片可重排或合并；A/B 应尽早形成一个可玩的跨回合闭环。实施前先收敛设计草案中的状态转换、焦点选择和保留限制，不前置通用规划器。

## 4. 完成标准

- 用户故事 US-01～US-08 均有对应证据；其中 US-01、US-02、US-03 是三类核心玩法验证，其余可主要用确定性测试与呈现检查覆盖。
- 至少一次真实 LLM 运行覆盖跨回合分工兑现，另有真实 LLM 场景覆盖临时切换后返回、共享子目标理解；可以在一局或多局中完成。明确谁操作其他角色，不把代理输入称作真人试玩。
- 核对模型确实收到目标材料，实际创建/维护目标并据此行动；保留原始输入、操作、关键结果和失败。预置目标可用于测试夹具，不能替代模型自行维护的证据。
- 保留实际固定提示词及配置；确认没有要求不存在的操作、重复 handoff 维护或固定检查报告。同回合成功编辑后继续行动，拒绝后利用反馈调整，无变化时避免重复整理；工程约束与模型行为分别验收，标准见[决策规约](decision-policy.md)。
- 关键约定在多个 Context 中保留，不靠每回合复制 handoff；挂起事项可发现，焦点变化不丢其他目标，关联共享不重复执行已经完成的非消耗性子目标。
- US-01 纳入方法失效后保留目的、US-03 纳入共享调查得到否定答案的变体；用现有内容或最小夹具支持。完成标准区分过程/结果与历史/当前条件；具体证据层次见用户故事，不能用确定性脚本代替模型理解的验证。
- 目标编辑不改变活动期限、身体数值、库存或随机结果，不偷偷确认现有警告；世界行动继续走原规则。角色标记完成不伪造世界结果。
- S 冷开保留目标/关联/焦点；E-only 恢复恰一次应用已记录编辑，不重新询问控制器。至少一个真实模型场景暂停重开后继续使用原目标。
- Human 操作与文本界面有可复现的运行说明；Schema Verify、相关测试及受影响旧玩法回归通过。模型效果与工程正确性分别报告。
- 记录困惑、承诺遗漏、误标完成、无必要切换、编辑调用成本、目标数量/材料长度、仍需 handoff 的信息及剩余限制；目标数只作规模统计，不以关闭数量或编辑频率作成功指标，不由少数成功样本宣称目标规划的一般可靠性。

内容扩展须服务于以上证据：可以为共享目标增加共同地标，为挂起恢复增加会合机会，但不要求新战斗系统、完整任务剧情或额外世界规模。目标数据和操作不应内置“阿青/溪流湾/采水”的特例。

## 5. 延期与重开条件

- 全量经历档案、按实体的记忆召回、自然语言别名解析：目标材料仍不足以保持关键事实时重开。
- 自动完成判定、事件驱动提醒、结构化恢复条件：手动检查反复遗漏且有具体可判定条件时，选择少量规则扩展。
- 自动分解、AND/OR 依赖、资源分配、优先级调度、可执行计划语言：单靠目标记录无法表达已验证玩法需求时再设计。
- 固定用户提示词流程、将 LLM 拆为多阶段处理节点及持久思考阶段：首版仅用固定决策指引；反复失败经材料/呈现/工具排查后，存在可机械判断的稳定条件与验收依据时才考虑最小机制。
- 他人目标识别、行为预测、证据图谱与数值置信度：合作预判出现可复现缺口后另开实验；当前只要求角色文本区分所闻、观察与推测，允许未知，不读取他人的私有目标补齐判断。
- 跨角色共享目标对象、公共任务板、团队承诺协议：先用双方各自的目标与显式说话合作；社会关系不由私有目标编辑自动产生。
- 通用模块/程序集提取：在玩法接线与局部规则边界清楚后决定，不要求多个完整游戏，也不提前设计统一框架。

本文件确立下一个里程碑，不自动启动 coding agent 的 Goal 循环，也不将扩展用户故事全部变成必做范围。
