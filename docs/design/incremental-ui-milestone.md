# 增量 UI：阶段功能目标

> 2026-10-28。用户已确认“事件 → 缩进效果 → 尾部受影响状态最新值”及下述三个规则。[切片 A](incremental-ui-slice-a.md)已接入生存模式；[验收记录](../experiments/incremental-ui-slice-a-acceptance.md)集中保存工程与试玩证据。跨回合最近事件列表仍属于 B，窗口与容量尚未裁决。
> Mud 调查基线：DramaBoard `42f1776`、durable-graph-mud `66e12a7`；该次调查只读源码与测试，未运行 Mud。下列当前实现入口已按 A 的代码更新。

当前实现以[角色上下文 Model](character-context-model.md)为基础：Opening + 当前保留 Items 是共享持久材料，完整重绘和 Console 增量由同一渲染入口消费。成功操作、纯拒绝、自然感知与冷开均不依赖旧屏幕；角色经历采用局部身份，世界提交来源只进入独立诊断。已交付上次放行区间与本轮操作，最近 n 回合（含零耗时事件）的完整窗口仍是后续 B 的范围。

## 1. 目标与已有边界

让读者在同一决策回合内，容易回答：**刚才的操作发生了什么、带来了哪些效果、现在是什么状态。** 回合内按事件的发生与因果先后展开，效果缩进附在所属事件下，一次更新末尾统一列出所有受影响状态的最新值。新回合仍用自足的完整观察开始，并以列表展示最近已见事件；历史与当前状态各自清楚。

沿用[决策回合信息继承](decision-context-handoff.md)的控制流程：放行模拟后旧控制会话结束，下次唤醒提供冻结行动结果与一次性交接。本目标进一步扩展可继承的信息，增加有界的已见事件历史，包括窗口内的零耗时操作事件，不再只保留最后一个耗时行动区间。放行后旧 Context 关闭，接受效果与其后可感知结算在下一 Opening 交付；新回合必须自足，不能依赖旧 Console 文字。此阶段不重开动作后收尾阶段或 `:end`。

当前实现已提供：

- [CycleObservation](../../src/ResourceCycle/CycleObservation.cs)：角色范围内的观察、当前动作校验和风险，不向布局交付完整世界。
- [IPlayLayout](../../src/ResourceCycle.Cli/IPlayLayout.cs)：两种可切换布局，共用事件/效果及尾部状态选择；`full` 与 `delta` 是独立的会话偏好。[Human Console 边界](console-command-boundary.md)将元命令及输入提示移到会话，布局只生成游戏内容，不改变 B 的历史窗口合同。
- [PlayPresentationSession](../../src/ResourceCycle.Cli/PlayPresentationSession.cs)：按角色与 ContextSequence 管理上下文开始/结束，提交后从当前角色的 Items 追加反馈；消费游标在写出并 Flush 成功后推进，仅为绘制优化。宿主管理输出明确带外。
- [CycleObservedEvent](../../src/ResourceCycle/CycleObservedEvent.cs)：有序事件与实际效果随 E 保存；[正常及恢复答复](../../src/ResourceCycle/CycleOperationResults.cs)共用这些材料。GameRevision 9；事件材料覆盖普通采集与无生存需求角色，尚无最近 n 回合事件窗口。
- [CycleInteractionRules](../../src/ResourceCycle/CycleInteractionRules.cs)：按接收者 Open/Closed 状态追加 Item 或收集待交付经历；新 Opening 冻结上次放行信息、经历与完整观察，替代独立累计 Incoming。[CharacterContextRenderer](../../src/ResourceCycle.Cli/CharacterContextRenderer.cs) 统一从 Opening 与保留 Items 渲染；纯输出包含完整角色材料和范围标记，不含宿主提示、输入回显、ANSI 或诊断。Closed 后不向旧上下文输出结算。

增量是呈现能力，不改变游戏时间、活动期限、警告确认或行动合法性。完整与增量模式应产生相同的游戏轨迹。

### 已确认的三个规则

1. **效果保留过程，当前值只汇总一次。** 同一状态先减后增，分别列在所属事件下面；末尾对所有受影响状态取并集，只列最终值。净变化为零也保留事件与效果。
2. **显示实际效果。** 数值使用结算后的实际变化量，包括上限裁剪；物品消耗、活动取消等同样属于效果。不能把配置收益或预期结果冒充已发生的效果。
3. **历史复用同一份事件记录。** 下一回合用列表回顾窗口内的事件，包括零耗时操作事件，保留当时的效果；不重复每次操作后的“当前值汇总”。倾向按决策回合分组、组内按发生顺序，具体 n 留给试玩决定。

三个规则是功能约束；A 的 API 以源码与实现合同为准，B 的窗口及保留建议仍待裁决。

## 2. Mud 的可借鉴成果及限制

Mud 的 **delta 与因果注解是两条输出路径**，不能当作已经合一的可移植组件：

| 能力 | 已核对的实现 | 借鉴点与边界 |
| --- | --- | --- |
| 整块更新 | [MarkdownObservationCursor](../../../durable-graph-mud/src/Mud.Engine/Presentation/MarkdownObservationCursor.cs) | 稳定键、替换、显式撤销；差分不比全量短时回退全量。仍构造完整观察，不等于增量计算。 |
| 可重同步 | 同上及 [CLI 元命令](../../../durable-graph-mud/src/Mud.Cli/Program.cs) | 首次、切线、倒退、手工请求输出完整观察；游标属于阅读上下文，成功生成不证明读者收到。 |
| 实际效果归属 | [EventRecorder](../../../durable-graph-mud/src/Mud.Engine/Rules/EventRecorder.cs) | 规则声明事件作用域，快照采集效果；进入子事件前结算父变化，退出后更新父基线，避免重复归因。父子表示过程包含，不是完整因果证明。 |
| 状态注号 | [MarkdownDashboardRenderer](../../../durable-graph-mud/src/Mud.Engine/Presentation/MarkdownDashboardRenderer.cs) | 事件效果和当前状态共享状态键；一个当前值可关联多个事件，净零变化仍能留下过程。当前状态只关联最新行动，历史显示最近四个完整行动。 |
| 观察边界 | [StateFacts](../../../durable-graph-mud/src/Mud.Engine/Rules/StateFacts.cs)、[EventViews](../../../durable-graph-mud/src/Mud.Engine/Presentation/EventViews.cs) | 两端分别判断可见性，未知与不存在分开；过滤不重新编号。作者编写的摘要和日志也必须遵守可见性。 |

[购物样张](../../../durable-graph-mud/docs/event-effects-samples/buy-bread.md)中，同一事件注号关联金币减少、面包获得和商店库存减少。跨事件的损伤与恢复则分别保留，即使最终值不变；同一快照间隔内未记录的中间过程仍会丢失。

Mud 的局限也应保留在判断中：四个行动限制不了单次行动大小；历史、叙事、当前状态有重复；delta 路径没有接入 dashboard 的 RecentTurns；状态键和字段投影需要维护。DramaBoard 使用不可变事实和异步活动，不直接复制可变世界的嵌套快照机制，也不引入整个 Mud.Engine 依赖。

## 3. 切片 A：按事件组织的回合内增量

这一片独立可用，但从第一片就需要最小的结构化事件及实际效果。原先“先只做语义块差分，再补因果”的切分被替换；跨回合历史窗口和可选注号放在 B。回合内主要靠相邻位置和缩进表达事件与效果的归属，不要求读者跳转查注号。

### 一次更新的阅读顺序

```text
> use item.food
你吃了一份野果。
  食物 +45
  背包野果 -1

当前：
食物 75
背包野果 2 份

>
```

数值仅示意。一个操作产生多个事件时，先按实际发生顺序列出事件，各自紧随所属效果；最后对所有受影响状态取并集，只展示一次最新值。同一状态先减少再恢复，两个效果都保留，尾部仅显示最终值，即使它与更新前相同。

事件间有已记录的因果先后就保留；同刻事件沿用已提交的结算顺序，不按 UI 分类重排。一个事件内并列的多项效果可以稳定排序，不宣称属性写入之间存在因果关系。缩进表示效果从属，不凭叙事文本推断原因。

效果展示实际变化量，例如上限裁剪后只增加 20，就显示 `+20`；未观察到前值时不能猜差值。非数值效果使用“活动已取消”“进入庇护”等表达。尾部除了直接受影响的值，还包括已变化的相关可执行性、风险等决策信息；派生预测更新不能冒充直接施加的世界效果。

### 玩家可观察的行为

1. **首次、冷开、新回合、切换角色**：从保存的 Model 重放完整角色材料；新身份使用带角色/回合号的开始标记，重返同一 Open Context 不伪造新边界。重定向使用纯文本。
2. **同回合成功操作**：按上述顺序输出事件、所属效果和末尾当前状态。例：`use item.water` 先报告饮水及实际补充量、物品消耗，再汇总身体、背包和变化的风险信息；未确认的历史警告仍明确有效。`handoff` 报告草稿编辑与最新草稿，不把草稿内容当成已发生的世界事件。
3. **无变化或拒绝**：给出结果或原因；没有新状态就不伪造变化。纯拒绝是持久请求/结果条目，没有经历或新观察，只保留本角色本轮最近 3 次操作窗口；旧终端文字无需擦除，后续完整渲染只使用仍存活的条目。查看不确认警告。
4. **信息失效**：物品用尽、活动取消、行动不可用等都必须明确表达。撤回时保留对象与历史/当前归属；历史与当前状态始终分开，不能将旧历史字段的撤回显示成当前“食物：无”。读者不能因为某条旧信息本次没被打印，就猜测它是否仍有效。
5. **最新状态与完整材料分开**：`:look` 和 `:layout <名称> once` 在带外块中预览保存的最新观察，不重新观察世界、不消费 Item。内部 `CharacterContextRenderer.RenderFull` 才是完整 Opening + 保留 Items 的纯上下文输出；两种入口不混称全量重放。
6. **模式可发现且与布局独立**：`:mode [full|delta]` 无参数列出当前模式和合法参数；`:help` 同样列出。显式切换模式或布局后预览最新保存状态，不新增上下文边界、不改世界或消费游标。生存模式默认 `delta`，`full` 保留作对照；`--play` 明确回退为 full，拒绝 delta 请求，多角色经历已由 Context 层交付；`--play` 的 delta 仍未开放。
7. **耗时行动**：提交后关闭旧 Context，旧正文不展示启动或结算效果。角色可感知的过程进入待交付经历，在下一 Opening 按序展示；开发者世界诊断走独立提交后 sink。终局新建自足只读 Context，输出成对边界，无新输入或未来交接草稿提示。EOF/exit 只关闭宿主会话，不冒充领域放行。

### 重构方向

- 一次更新需要有序的可见事件、各自实际效果，以及受影响状态的当前投影。事件和效果共享稳定的状态身份，尾部按身份去重；布局不从中文结果字符串反推效果。
- 布局仍可用带稳定键的语义块组织完整画面及尾部汇总，但整块替换只是实现手段，不规定每次操作都重印整个身体/背包区域。不按 Markdown 标题、行号或正则拆文本。
- 最新值按读者任务组织；必要时带上理解它所需的关联信息。最小更新语义是明确更新、移除或不再可见；物品归零、活动结束和操作失效不能仅靠省略表达。不是终端原地擦写，也不要求 LLM 应用字符编辑脚本。
- Console 消费游标只在宿主内存中保存，按角色/上下文隔离；布局与模式是会话偏好，不影响持久材料。完整重绘不依赖已输出内容；相邻快照取自 Model，布局变化不要求重建领域观察。
- 已统一使用 Context 消费路径，避免 Fact 与 Item 双重输出。先准备输出，正常写出及 Flush 后推进消费游标；写出失败停止宿主，冷开从保存的 Model 重绘。Console 写入成功不等于模型已接收，不提前实现通用交付确认协议。
- 查询和模式切换继续使用既有操作记录；观察帧不冒充新 ToolCallId。操作身份与配对保持不变；成功操作答复已改为投影 E 中的实际效果，冷开补录也不能退回配置收益。完整 LLM 工具会话和增量帧重放仍不在本片范围。
- 增量比较 Item 前后已保存观察以补齐受影响状态；渲染时不重新感知世界。实际因果来自已记录的事件效果，不能由快照差分冒充。暂不引入 UI 依赖追踪或增量规则计算。变化太多时尾部可以改为完整当前观察，前面的事件与效果仍保留；回退本身不新增上下文边界。

### 验收

自动验证“完整基线＋更新＝最新完整语义内容”，覆盖新增、替换、撤销、同版本呈现变化、重同步与角色隔离。还需验证事件顺序、效果归属、实际增减量，以及尾部包含所有受影响状态且每项仅有一个最终值，包括净零过程。验证用水耗尽后的背包、动作可用性和风险一起更新，确认历史警告没有意外消失；Opening 历史经历不被当前补给改写。

不写整屏快照、具体行号、章节顺序或块划分的固定断言。“事件先于所属效果，全部事件之后统一汇总当前值”是本次选定的语义合同，可验证其结构；具体缩进宽度、措辞和视觉排版不锁死。

## 4. 切片 B：跨回合最近事件历史

在 A 可独立试玩后实施，复用 A 的 `CycleObservedEvent` / `CycleObservedEffect`，增加有界保留与历史列表。当前 E/S 已保存角色 Opening、保留 Items 与待交付经历，冷开可完整重绘本轮材料。B 要进一步保留最近 n 个完整回合，尤其是已经结束回合中的零耗时操作经历；不把每个 Kernel occurrence 都变成一条玩家日志。

### 玩家可观察的行为

- 下一回合的完整画面用列表展示窗口内所有已见事件，保留效果从属。例如按回合分组：

  ```text
  最近事件（历史）：
  - 第 7 回合
    - 你吃了一份野果。
      - 食物 +45
      - 背包野果 -1
    - 你开始等待 1 小时。
  ```

  历史保留当时的事件与效果，不为每条旧事件重印一份“当前”值；当前完整观察单独展示。具体列表样式不固定。

- 一个事件可以影响多个状态，一个状态也可以关联多个事件；先下降再恢复到原值仍保留两段实际过程。
- 警告是“曾发生的提醒”，当前指标是“现在的值”；旧事件的终值不能冒充当前值。交接文字仍是角色意图，不列为游戏证实的效果。
- 区分实际效果、持续过程、观察范围变化。时间流逝产生的消耗不能算作恰好最后提交的天气事件；走进地点看见资源也不表示资源刚刚生成。
- 没有足够证据时只报告差异或区间净变化，不杜撰精确因果。天气额外扣除使用实际结算值，不能用配置最大损失代替。
- 若之后为历史与当前状态增加注号，完整画面中的注号须有同画面可找到的说明；增量中的引用必须已在本阅读上下文定义或随消息一起给出。新回合不能引用仅存在于旧上下文的定义。注号是可选增强，不是 A/B 阅读流程的必要前提。

### 最小数据与窗口建议

按用户提出的**最近 n 条或 n 个决策回合的已见事件**定义独立窗口，包含窗口内的零耗时操作事件；不将窗口限定为当前 Opening 的上次放行区间。建议优先按决策回合分组，组内保持发生/观察顺序，n 和最终裁剪单位待试玩决定。不能把调用次数、Kernel transition 数或 Activity 次数冒称决策回合数。

“已见”以角色已获得的可见经历为领域口径，不宣称人类已阅读或 LLM 已接收，也不引入交付确认协议。模拟推进期间产生、直到唤醒才首次交给控制器的事件，在新回合明确区分为新获知结果；不能假定旧 LLM 会话已经看到 Console 输出。重复查看、切布局与再次列入历史不生成新事件。初次获知时机与实际发生时刻可不同，不为排列方便改写发生顺序。

过程条目有稳定身份、发生时刻/区间、事件种类、角色可见摘要和实际效果。效果用稳定状态键关联受影响对象/属性，记录可见的前后值；状态键与 UI 块键独立。同一属性换位置、换布局，不改变它的身份。人类短注号只是显示别名，不能把数组下标、ToolCallId 或仅模型时间当成通用事件身份。

控制器动作关联原 OperationRecordId/ToolCallId；天气、自然消耗和采集完成不编造工具调用。当前 `CharacterExperience.ExperienceSequence` 按角色单调分配，Context Item 以角色/回合/ItemSequence 定位；B 应延续这些身份，不在规划时绑定尚不存在的提交游标。`(LineageId, TransitionCount, FactOrdinal, EventOrdinal)` 只用于开发者诊断溯源；局部经历不暴露世界其他接收者的序号。

需要跨回合/冷开保留的经历已作为角色领域数据随 E/S 记录，而非从终端日志恢复；B 的新保留窗口继续使用同一发布边界。实际效果在规划结算时形成或从明确的事实效果导出；Fold 安装已记录值，不能在恢复时重新推断或重复追加经历。继续复用现有结构化效果，不另建独立累计摘要形成双重权威。

在施工前选定窗口边界与容量策略。“窗口内所有已见事件”意味着不能在窗口内部偷偷挑选或合并已经展示过的独立事件；按条数保留时不拆事件及所属效果，按回合保留时不拆回合。仅限制回合数不能限制长循环或大量零耗时操作，若另加硬容量限制，需要明确缩短保留窗口并提示历史范围，不能仍声称保留了完整 n 回合。持续过程若合成为区间事件，应在首次呈现前定义其语义，不能事后抹掉已经展示的关键过程。存活事件不重新编号，不保留悬空引用。

暂不引入通用因果图、任意深度事件树、规则作用域追踪框架。A/B 共用的第一批事件覆盖：补给、取消/确认、采集获得与停止、途中/抵达、昼夜和庇护带来的变化、寒风实际损失、危险唤醒与终局。未覆盖的原因显式降级为结果描述。

### 验收

除 A 的事件效果和重建验证外，验证零耗时事件跨回合保留、历史列表与当时增量中的事件/效果一致、重复查看不新增事件、实际发生与首次获知的区分、不可见端点不泄漏、窗口裁剪与引用完整性；S 冷开和 pending E 恢复都得到同样的经历身份且不重复追加。显示、查询与重放不能改变游戏结果。

Mud 的 [EventEffectsTests](../../../durable-graph-mud/tests/Mud.Tests/EventEffectsTests.cs)、[EventDashboardTests](../../../durable-graph-mud/tests/Mud.Tests/EventDashboardTests.cs)、[MarkdownDeltaTests](../../../durable-graph-mud/tests/Mud.Tests/MarkdownDeltaTests.cs)可作语义用例来源；不复制其中绑定具体章节或 Markdown 格式的断言。

## 5. 切片 C：独立试玩与取舍

A 完成先做一轮，B 完成再复验；全量和增量使用同一场景/输入轨迹对照，并安排不了解实现的 subagent 自主试玩。

| 场景 | 读者应能回答的问题 |
| --- | --- |
| 连续两次补给、最后一份用尽 | 当前数值、剩余物品和可用操作分别是什么？哪些历史警告仍在？ |
| 在途警告后补给并继续 | 是否还暴露在寒冷中？抵达期限是否改变？警告与当前状态是否混淆？ |
| 采集中途介入、取消或继续 | 已拿到多少？活动是否仍在进行？当前资源和可执行动作是什么？ |
| 编辑/清空交接、查看帮助、切布局 | 草稿是否已更新？这些查看是否推进时间或确认消息？ |
| 天气、时间消耗与恢复叠加 | 哪些是实际效果，哪些只是区间净变化？净零是否掩盖过程？ |
| 冷开、新回合、终局 | 只看这一份完整画面，能否理解当前状态、上次行动结果及可做的事？ |

记录总输出字符/行数、重复区域、手工 `:look` 次数和漏读/误判；不能只测 delta 正文而漏算重复 prompt、结果和事件说明。字符减少不等于 token 减少，也不能证明未来 LLM 决策更好。暂不预定压缩率；以必需信息完整、典型零耗时操作明显减少重复且试玩未增加误判为交付依据。

## 6. 建议的下一步

下一步聚焦 B 的软件设计：复用已落地的事件材料，裁决历史窗口与容量、各回合归组和窗口裁剪，复用当前已分配的角色经历身份及首次交付边界。先完成这些决策再施工；可选注号不阻塞历史列表。不要重新采集一套效果、从 Markdown 反推事件，或把 A 的操作日志当作完整角色经历。C 的独立试玩在 B 完成后复验，尤其检查历史窗口与 Opening 上次放行经历是否重复。

本阶段不包含 LLM 端点接入、完整工具会话恢复、GUI、终端光标局部重绘、跨世界线游玩、旧存档迁移或全量行为轨迹系统。具体存储修订按实际数据变化决定，保持当前无兼容性包袱的约束。
