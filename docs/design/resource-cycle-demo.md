## 已定范围

首片只有昼夜系统、太阳花（白天 3 小时成熟）、月光草（夜晚 4 小时成熟）和程序化销毁。昼夜变化会打断不适时段的资源刷新。不需要角色、采集所得、物品、背包、空间或 Player 输入。

用户提出由时间运行层维护显式预测实例和事件广播：创建预测时确定预计结束时刻，并声明关心的事件；事件响应可修改或取消预测。不逐 tick 递减数值。持久化需要替代 .NET Delegate 的数据表示；诊断应展示预测、响应条件与变化原因。

继续遵循新逻辑先写应用层、经实例验证后提取引擎共性的方向。独立业务子图组成单根。原多人采集、Human/LLM 决策和空间演进后置，见[项目状态](../../PROJECT-STATE.md)。

## 当前实现与新方向的差异

- [ForecastRound](../../src/Kernel/Simulation/ForecastRound.cs) 目前每轮调用所有规则重新收集临时候选，不是持久预测注册表。
- [OccurrenceScheduler](../../src/Kernel/Scheduling/OccurrenceScheduler.cs) 已提供稳定仲裁，但其同刻 seed/key 排名不是业务事件广播顺序或昼夜边界语义。
- [SimulationKernel](../../src/Kernel/Simulation/SimulationKernel.cs) 提供 facts 的 scratch fold、E/S 发布和 pending 恢复接缝。它尚不提供本实例的磁盘 adapter。
- 首片在应用根保存预测/订阅数据，用薄的应用规则将现存预测投影为 Kernel 候选；业务预测在创建与事件响应时更新，不借投影重新计算一遍全部业务预测。持久预测表是权威，运行时订阅索引可重建，不维护第二套独立权威。
- Spatial 暂不参与本实例；是否将来迁移相同模式，依据实例经验再裁决。

## 原型选用的最小规则

- 06:00 日出、18:00 日落；默认从 D0 16:00 开始，销毁脚本覆盖跨边界生长。
- 昼夜切换暂停生长、保留已完成的有效时长；下一个适宜时段重新预测剩余生长的完成时刻。
- 每种植物一个固定资源点，成熟后保持成熟直到被脚本销毁，不自动叠加产量。
- 固定时间表销毁，避免先引入 RNG；销毁重置生长进度并增加生长代次，在适宜时段重新生长，否则等待。未成熟时也允许销毁并重置。

暂停生长和销毁重长是两个不同的领域规则，不应因为都取消了预测就混用语义。生长进度只在相关边界更新：记录时间锚点与累计有效时长/剩余工作量即可，不周期性扣减。

## 数据化行为与事件交互

### 采用的复杂性折中：依赖驱动的失效与统一重算

事件响应首先处理真实业务状态，再询问相关预测者是否需要重新预测。预测者声明事件类型与目标 ID 依赖；运行层先用索引找到相关者，再细筛并标记 dirty。同一转换内重复 dirty 可合并，但不能省略有业务意义的中间事件。

业务事件 → 更新状态 → 依赖索引粗筛 → 预测者判断失效 → dirty 去重 → 基于当前状态完整重算 → 发布 facts/State → 选择下次事件。旧的失效预测不得在重算前执行。

预测者与其输出分离：暂停植物保留预测者和订阅，但输出零个成熟预测。原型仅需固定订阅集合、少量持久行为种类和运行时索引，不引入任意 Delegate、动态代码或可持久执行栈。订阅描述和预测结果入单根；dirty 集合与索引可作为规划期临时结构，完成状态不留下待重算数据。

保留全量重算模式作为对照：执行相同业务规则，但所有预测者均重算。重算次数不能改变预测身份或业务事件。对比完整结果用于发现遗漏依赖；计数展示跳过多少业务预测，不等价于总运行时间加速。当前 Kernel 的候选扫描和本实例不可变子图集合替换仍可能为线性成本。

持久预测记录 owner、动作种类、目标、到期时刻及代次；持久响应绑定记录事件种类、匹配对象与预测者 owner。owner 在本实例中对应固定代码分派，不建立通用反射调用或表达式解释器。预测身份由业务数据决定，不包含重算次数。

例如 `MaturePlant(plantId, generation)` 是保存的行为描述，加载后由应用代码解释。光照业务处理先更新受影响植物，再通过绑定路由失效通知。它不是可持久化任意闭包，也不捕获旧世界对象。业务状态、预测与绑定共同发布；销毁后旧预测被替换，新的代次区分旧一轮生长。首片使用固定绑定，动态订阅创建/撤销留待后续实例。

订阅者声明和诊断共用数据来源。保留因暂停而没有到期预测的植物及其光照订阅，否则下一次日出/日落无法唤醒它。响应绑定的生命周期不必与单个到期预测完全相同。

首片每次只规划一项预测对应的业务事件，匹配绑定按稳定 owner 顺序遍历，dirty 集合按 owner 排序重算。光照处理仍是应用内显式业务逻辑；绑定系统服务于预测失效，不宣称实现了任意业务事件广播。以后若支持投递中动态改变订阅，须另定接收者快照与生效时点。

规划阶段生成具体子图变化事实；恢复只应用这些 facts，不再次广播或预测。相关业务变化、预测表与绑定共同成为完成的 S。E 与 S 仍是两次发布；当前 DG 支持替换整个完整根，应用 adapter 无需引入额外仓库。

## 必须覆盖的边界

- 太阳花在日落前生长 2 小时后被打断，下次日出如何续接；月光草对应夜间场景。
- 同刻按成熟→光照→销毁处理，确保恰在日出/日落完成的生长得到成熟结果，再允许同刻销毁清零。应用先筛选业务优先级，Kernel 仅仲裁同优先级的候选；不改变 Kernel 本身的排序合同。
- 预测取消/替换后旧实例不能触发；暂停期间即使没有成熟预测仍能响应光照。
- 冷恢复时预测、订阅、植物状态和昼夜状态一致；pending 完成不重复销毁/成熟，不丢下次预测。
