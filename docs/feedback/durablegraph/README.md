## 持续维护

- 按相关主题形成一份短报告，文件用稳定编号和可搜索的主题名；不按每轮对话新建文件。
- 每项反馈写清使用场景、当前行为及证据、影响、最小建议和验收方式。区别已复现问题、源码确认的限制与待试用假设；注明核对的上游提交、包版本及依赖条件。
- 报告中的建议供上游评估，不自动成为已采纳需求；对外发送或收到回复时，再更新实际处理状态。
- 新证据、上游回应和裁决直接更新原条目，不追加聊天流水。解决后只保留结论、实现提交/文档及消费者验证指针；延期项保留重开条件。
- 同一事实只在一处详述：此处留索引，报告留反馈，[PROJECT-STATE](../../../PROJECT-STATE.md) 留当前工作方向，源码/测试及 Git 留详细证据。

后续优先补充：真实模型声明与升级的工作量、完整 E/S 续局流程、长轨迹读取/保存成本，以及需要翻内部源码才能完成的操作。
