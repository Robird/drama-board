### 尚未冻结的选择

## 2. 审查方法

采用用户指定的 `dialectical-simplification`：三位独立审查者分别担任需求怀疑者、最小架构者、语义捍卫者。审查期间只读；先独立提出论点，再交换最强反例进行交叉质询。主会话核对证据并修订，必要时仅对未收敛事项进行第三轮。

每项论点包含位置、主张、需求来源、当前消费者、复杂度、最小替代、删除后的失败轨迹、裁决与置信度。共同阅读同一用户提案不算三个独立需求来源。

## 3. 裁决

最小模型：一个角色持续保存主观材料与未开始程序；领域规则维护当前执行；一个冻结的维护机会接收未来程序、主观区域及执行意愿的整体修订；顺序执行到缺指令、受阻或 Think 完成时交回维护。空响应可正常停驻。

| 裁决 | 对象 | 证据、反例与最终处理 |
|---|---|---|
| keep / simplify | World VM 与 Player Process 隐喻 | U2/U3；VM 表示规则和状态所有权，Process 是其中的角色实例。没有第二个世界、独立角色时钟或 OS 线程的当前消费者；用术语表限定含义 |
| keep | 主观编辑与世界/设施状态的区别 | U3；“我已到 D”的文字若能覆盖位置或经历，就直接改变现实。允许改判断，系统事实与执行进度由所属规则维护 |
| keep / simplify | 当前执行与未开始尾部 | U4/U5 与现有出发/到达提交；最后一条移动出发后 Buffer 空，不等于到达。保留边界，执行进度复用 Spatial，避免 Process 再镜像一份运动状态 |
| simplify | 编辑操作族 | 无逐项远程补丁、多人或并发 Programmer 消费者。冻结机会整体替换尾部与主观区域即可表达追加/删改/重排，无须由此引入逐条身份和 patch 协议 |
| keep | 整体生效与明确执行意愿 | 修改笔记“取消去 D”却未改成功 Buffer 会使行为矛盾；相同 Buffer 既可能表示重试，也可能表示停驻。一次响应整体接受，并明确继续/停驻，不能靠内容 diff 猜测 |
| simplify / keep | 多原因合并与一次需求处理 | 最强反例：Think 完成且 Buffer 空→保持空→马上再发缺指令。首批用一个主原因和可见的空状态，并让一次响应处理该边界需求；无需独立中断对象再合并 |
| keep / defer | 空响应停驻与恢复 | U7 裁决后，停驻是合法片段终点；撤回首批必须恢复的要求。主动恢复、按钮与成本延期；全局无候选正常静止，角色停驻不阻止其他事件 |
| keep / simplify | 执行受阻 | 静态图也有真实反例：`Move(ac), Move(bd)` 到 C 后第二条不适用。保留失败位置、尾部和解释，明确继续才再试；无需新增封路机制或通用重试器 |
| keep | Think 的耗时和交回时点 | U6；Think 后直接执行尾部会错过承诺的维护机会，直接加时会漏掉中间事件。固定正耗时与 2500 ms 测试事件足以验证；时间值仅是夹具 |
| simplify | 笔记的当前内容与历史来源 | 当前笔记 N 可显式改为 N2；历史事实不能随之改写，也不能自动把 N 恢复成当前文本。保留来源与续用保证，不要求多套笔记数据库或全历史永久保留 |
| defer | 目标树、脚本、中断平台、完整认知、持久化 | 没有当前消费者要求成为执行核心；按正文第 9 节的真实机制需求重开 |

### 交叉质询与立场修正

- 需求怀疑者初判停驻会迫使新增恢复 API；另外两位也指出静态场景没有恢复路径。U7 将片段终止明确为合法结果，三者撤回首批必须恢复的前提。
- 最小架构者与语义捍卫者接受单主原因；需求怀疑者接受“Think 完成后空状态不能再唤醒”的反例，保留一次边界需求处理，删去首批通用合并要求。
- 整体替换方案经“同值 Buffer 的重试/停驻歧义”质询后，明确保留执行意愿，缩减的仅是编辑操作族。
- 语义捍卫者确认笔记续用保证不禁止显式修改，避免把来源区别扩大成多仓库或不可变主观真相。

三者收敛于行为边界，没有需要第三轮的新失败类别。审查票数不作为需求依据；上述结论由用户裁决、当前消费者与具体轨迹支持。

### 文档与现状的差异

现有 Server 在地点逐次请求单一移动，缺少 Buffer、主观修订及 Think；这些是待实现能力。`SimulationKernel` 返回 `Exhausted` 表示无候选，`FreePlaySession.RunAsync` 却将非 `Committed` 一律判为异常；新停驻语义要求工程明确适配这一处。保持 Kernel 单时间线同步等待、统一提交与查询只读的原有边界。

可观察的简化：首批从多原因合并缩为单主原因；从编辑操作族缩为整体替换；移除首批恢复入口要求；客观执行进度继续复用领域状态。没有新增代码类型或系统依赖。
