# 双角色生存实施合同

状态：2026-10-29 已实施并通过[规则、恢复、宿主与真实模型接线验收](../experiments/survival-duo-acceptance.md)。承接[二期里程碑 §3.3](../design/survival-demo-milestone.md#33-2b双角色生存与控制器路由)；交流、赠与与真实合作仍属于 2C。

2026-11-01：人数和路由已随[角色跟随](../design/character-following.md)扩展至 1–3 人。当前入口为 `--survival --characters 1|2|3`，`--duo` 仅是显式二人快捷参数；续局省略人数时读取存档，显式人数必须匹配。多人 LLM 模式中 a 为 Human，其余角色共享同一模型调用预算。下文保留最初双角色切片的领域合同，当前启动方式以[README](../../README.md#two-or-three-explorers-in-one-survival-world)为准。

## 一个世界，两个独立角色

复用 ResourceCycle 应用和一套 Kernel、模型时间、E/S 发布根。双角色工厂组装 `a`（阿青）、`b`（阿白），各自拥有身体、背包、活动、Context 和地点观察。地图、资源余量、昼夜和天气是共享世界状态。规则无需知道角色由 Human 还是 LLM 控制。

继续保留单人生存、多人采集和批处理入口。`--duo` 是双人生存入口，默认同一 Human Console 轮流服务；`--duo --llm` 将 `a` 绑定 Human、`b` 绑定 LLM。绑定在宿主装配，身份匹配须显式校验；客户端与凭据不进入领域图。恢复 pending E 不请求控制器、不重抽天气，之后才按仍活跃的绑定初始化外部调用。

```powershell
dotnet run --project src/ResourceCycle.Cli -c Release -- --duo --store artifacts/my-duo
dotnet run --project src/ResourceCycle.Cli -c Release -- --duo --llm --model gpt-6.1-sol --store artifacts/my-mixed-duo
```

同一入口和路径续局；两个入口互斥于 `--survival` 和 `--play`。双人初始补给与单人相同，每人各有一份水。模型认证、连接目录、预算和审计沿用 [2A 配置](survival-llm-controller.md)；无 `--store` 时只在内存运行。Human 的 `:exit` 或 EOF 暂停世界，LLM 预算/协议失败也显式暂停，均不代选动作。

## 个人结束与世界结束

`CycleCharacter.Ending` 是唯一的个人结束权威，保存获救/死亡、时刻、原因和结束位置快照；空值表示仍在探索。删除 Expedition 和 Fact 中旧的全局结束权威。全局总结从个人记录派生：仍在探索、全部获救、部分获救、无人获救。最后一个角色结束后停止模拟；在此之前，结束者不再产生决定、活动或需求预测。

个人结束在同一事实中完成身体积分与冻结、活动/待响应通知清理和空间实体退休。结束位置是历史快照，不能作为活跃空间位置供可达性或互动判断使用。途中死亡也移除空间实体，避免另一角色推进时间后遇到本已死亡角色的过期到达预测。此切片不引入尸体占位、返场、复活或救援机制。

终局 Context 只属于本人，并保持冻结；不得因为其他人继续移动、天气或时间变化而刷新。局内观察不广播远处同伴的位置或结局，宿主全局总结只在全员结束后显示，且不写入任何角色的知识。个人旅程状态仍可映射到现有观察的 Outcome 字段；它不代表全局结束。

## 一次天气，多份效果

环境保留唯一随机 seed、sequence、下一发生时刻和最近天气种类。每次天气只抽样一次，再按稳定角色顺序对当时全部活跃角色计算暴露/庇护效果。`CycleWeatherEffect` 按 ActorId 保存实际温暖损失和庇护条件；天气事实不指定唯一 ActorId，而保存所有相关角色替换和环境替换。

个人死亡、空间退休、天气记录与角色反馈同根发布。恢复应用已保存结果，不能重新选择参与者或抽样。每个角色的观察只呈现自己的天气效果。结束角色不接受后续天气或昼夜的身体更新。

## 调度、观察与宿主

沿用当前同刻决定的服务游标和确定性仲裁；先结算到达、需求、天气和活动，再请求相应角色决定。控制器仅收到本人持久 Context，路由按 ActorId 精确选择目标。共用控制器实例不意味着共用角色记忆。

Console 的终局交付由单个布尔标记改为按角色跟踪；一人结束后交付其终局，但另一人仍可继续。混合宿主沿用 2A 的模型输入、输出和已提交操作审计，不从 Console 字节反向构造模型材料。错误入口不得意外恢复不匹配存档；LLM 角色已经结束时无需初始化端点。

## 验收切面

- 两人独立移动、采集和身体消耗，共享资源竞争仍保持先完成先得。
- 同一场天气，不同位置和庇护产生不同效果；随机流只前进一次。
- 一人途中死亡，另一人继续越过其原到达时刻；一人获救后另一人继续越过昼夜变化。
- 双人同刻服务顺序稳定；可从不同出口获救，支持全部、部分和无人获救总结。
- 角色 Context、handoff 与地图知识隔离；远方终局不泄漏；结束者材料保持不变。
- 双角色 S 冷开、个人终局和天气 E-only 恢复，效果与空间退休只应用一次；增量预测和全量重建一致。
- Human 共享 Console 与 Human/LLM 精确绑定可运行；旧单人生存、采集和批处理回归。

本轮没有旧存档兼容负担。游戏修订号与受影响 Schema 同步提升，使用新存档验证；生产不增加历史迁移分支。真实 Human＋LLM 合作验收在 2C 完成交流与赠与后进行，不能以当前双角色规则测试替代。
