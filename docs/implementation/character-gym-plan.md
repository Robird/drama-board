## 每轮如何维护与推进

1. 阅读 PROJECT-STATE、本文件与所选问题对应章节，核对源码当前事实。一次选择一个可验收问题或紧密关联的小切片，不反复重开整套设计。
2. 写清本轮输出与验收。适合委派时给出问题、只读/可写范围、共享契约、不得改动的边界和返回证据；简单工作主线程直接处理。主线程负责集成和独立复核，subagent 报告不等于验收。
3. 内部工程选择依据证据自行裁决；需要用户裁决的产品边界明确记录，同时继续无依赖的工作。不以模型体验尚不确定为由无限设计或提前建设二期。
4. 本轮完成后更新切片状态与“当前下一步”。已解决问题从上表删除，结论进入设计/源码/测试，并在切片中留一处证据链接；未解决项补充真实阻碍与下一项最小验证，不追加逐轮讨论日志。
5. 新增问题先判断是否一期必要；非必要项放回里程碑延期范围，写明重开条件。PROJECT-STATE 仅随焦点/边界实质变化更新，不复制此表。
6. 用集成 diff 与适当构建/测试核对改动；纯文档查链接和状态一致性。保留真实执行证据，标明脚本操作、模型实际提交、人工提示、夹具与尚未验证部分。

完成态以里程碑为准：代码可运行、故障边界验证、实际反馈定位分叉续跑可用、说明和证据可查。没有出现高价值 issue 或没有证明某改动改善角色，不影响一期验收；没有真实模型接线或只有模拟日志则不能宣称完成。
