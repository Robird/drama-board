# ResourceCycle 原型施工契约

> 历史命名说明：本文保留当时的 ResourceCycle / Cycle 类型、命令与验证记录。当前应用已重命名为 Playground；现行入口与持久身份边界见[重命名说明](../../docs/implementation/playground-rename.md)。旧名称源码链接固定到重命名前的 Git 版本。

状态：本切片已完成，结果与限制见[原型验收](../experiments/resource-cycle-acceptance.md)。以下保留实施契约，不作为新一轮派工清单。

本轮目标：应用层昼夜/植物/固定销毁脚本，通过声明依赖、失效标记和统一重算维护显式预测；提供可运行 Console、单根 DG 冷恢复及增量/全量对照。不修改 Kernel/Spatial 的既有语义，不增加角色或通用事件框架。

## 本轮采用的实验规则

- 逻辑时间沿用 Kernel 的毫秒刻度；06:00 日出、18:00 日落；默认从 D0 16:00 开始。
- 太阳花需要白天累计 3 小时，月光草需要夜晚累计 4 小时。不适时段暂停，保留进度；成熟保持至销毁。销毁清零并开启新一轮生长，包括未成熟时的销毁。
- 固定、有限销毁时间表，覆盖暂停、重新预测和同刻边界；无需物品产出或随机数。
- 同一时刻先成熟、再光照转换、再脚本销毁。同类使用稳定身份/现有 Kernel 仲裁；不得依赖注册或集合枚举顺序。应用规则可只暴露最早时刻最高业务优先级的候选给 Kernel，不修改 Kernel 排名算法。
- 非法/陈旧预测不能执行；当前响应和 dirty 重算完成后才允许选下一个候选。

## 增量模式

预测者和预测结果分离。预测者及其数据化绑定可在没有到期结果时继续存在。依赖键采用事件类型与目标 ID；先索引筛选，再由预测者判断是否需要重算。业务状态更新先发生，dirty 标记可合并，业务事件不能因此遗漏。

持久 World 分为光照、植物、脚本及预测/响应绑定子图；不存在持久委托。绑定使用少量枚举/强类型参数和代码分派。预测输出基于当前权威状态完整重算，不编写一套逐事件修补截止时间逻辑。首片订阅集合固定，由持久数据重建运行时索引；动态订阅语义留待后续。

全量对照模式仍执行同样业务事件，仅把所有预测者视为 dirty；不能因重算次数不同而改变预测身份、业务状态或事件序列。计数诊断属于运行期测量，不作为玩法状态。声明依赖遗漏由全量对照检测。

E 记录已规划的具体 facts（含预测变更），S 保存完整世界与 KernelCursor。fold/recovery 仅应用 facts，不重新触发广播、预测或外部行为。沿用不可变 scratch 子图替换，未变子图共享；不深拷贝整世界。不自动兼容旧档。

## 工作包与接口

- 核心包：`src/ResourceCycle/` 模型与规则，排除 `Persistence/`；命名空间 `DramaBoard.ResourceCycle`。确定类型 `CycleWorld`、`CycleFact`、`CyclePrediction`，使用 `IOccurrenceHistory<CycleWorld, CycleFact>`。具体工厂/诊断接口由核心作者及时发出契约。
- 持久化包：`src/ResourceCycle/Persistence/`，封装完整根与当前 DG adapter；定义注册覆盖 Kernel 与 ResourceCycle。不得持有另一套独立世界或双写日志。
- 主线程：项目/solution 集成、Console 与文档、最终实跑验收。
- 独立测试/审查：单独测试项目；验证业务边界、增量/全量一致性、冷恢复与 pending，不只验证实现自身输出。

构建共享上游输出，所有 dotnet build/test 串行，由主线程调度。各包不提交、不改他人文件；必要契约调整通知主线程。

## 验收

可运行脚本多昼夜，诊断展示状态、预测、依赖与最近因果信息；记录真实重算计数。测试固定预期时间、相同输入全量/增量事件与状态一致、无关目标不触发其他植物重算、暂停无到期仍能唤醒、旧预测被撤销、同刻边界、正常 S 冷开以及 E-only 恢复。真实 Console 多进程续跑与连续执行终态对照。报告区分业务重算节省与总耗时，不声称已解决大规模调度性能。
