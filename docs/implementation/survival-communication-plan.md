# 生存 2C：交流、赠与与合作实施方案

> 历史命名说明：本文保留当时的 ResourceCycle / Cycle 类型、命令与验证记录。当前应用已重命名为 Playground；现行入口与持久身份边界见[重命名说明](../../docs/implementation/playground-rename.md)。旧名称源码链接固定到重命名前的 Git 版本。

## 选择的最小规则

同一个实际地点的活跃角色可以 `say <actor-id> <text>` 和 `give <actor-id> <item-id> <count>`，不耗模型时间。只接受 AtPlace 的同地对象，不用个人终局历史位置判断可交互性，也不把同一通道内运动视为同地。文本非空，最多 2000 个 Unicode 字符；内部空白保留。物品数量为正整数。

每个角色每个模型时刻共允许 **4 次成功说话或赠与**。预算按模型时间分段，查询有效计数不写状态；新时刻首次成功通信才写新的计数锚点。换 Context、确认通知、收到回复、取消活动及冷开不返还同刻额度。失败操作不扣额，沿用已有持久拒绝与宿主模型调用预算。

收到通信设置一个可合并的待响应标记，触发正常决定请求；活动、StartedAt、Due 和已得成果保持。`continue` 清除待响应通信并保留原活动；取消或接受新耗时安排也按当前感知确认语义处理。闲置时确认不会凭空推进时间，仍须安排耗时行动。模型自由文本不自动发送，只有显式 say 进入领域。

**不增加本时刻永久关闭接收唤醒的 Closed 标志。** 双方各 4 次发送已使本时刻成功通信最多 8 次，由通信引起的额外唤醒也有有限上界。每次重新唤醒都消耗发送方额度；持续 handoff/非法输入不是通信新增的循环，仍由原宿主预算处理。

曾考虑“开始耗时行动或 continue 后，本时刻消息只入经历、不再唤醒”。独立反审查发现：a 已确认低水警告并开始等待，b 稍后同刻第一次赠送救命饮水，若不能唤醒 a，就可能持有水仍在等待期间死亡。发送额度已经提供有限性，额外关闭位反而吞掉首次交互，故不采用。

## 状态与分层

`CycleCharacter.Communication` 保存 `CycleCommunicationState(BudgetAt, SentCount, AttentionPending)`。待响应标记与预算重置独立。它不保存第二套 Inbox；署名话语、赠与结果和相关效果仍由现有角色 Context / UndeliveredExperiences 交付。

`NeedsDecision` 与 attention 预测识别待响应通信；成功 say/give 更新发送者服务游标，沿用已有 round-robin。接收者原 Context 已 Closed 时，正常开启新 Context 并显示先前活动仍在进行。当前 Open 的接收者得到新 Item；不因收到消息直接取消活动或关掉其 Context。

说话是“谁声称了什么”，不是世界已确认的事实。不能自动写入 Visits、共享地图或整个私有 Context。双方只知道消息本身以及各自可见的身体/库存/活动效果；不把模型分析文字当对白。

赠与在同一个事实中完成发送方扣除、接收方增加、双方通信状态和感知交付。先验证数量、可见同地对象、库存和容量；拒绝没有部分转移。未知、远处和已结束对象采用同类拒绝，不暴露隐藏位置；容量失败也不披露接收者完整库存。Inventory 的 `Add/CheckAdd(itemId, count = 1)` 以明确数量一次验证容量和整数上界，不循环制造中间图。

`SpeechSent` / `ItemGiven` 事实保存 `TargetActorId`、`SpeechText` 或 `ItemId/ItemCount` 及双端替换。E-only 恢复验证记录与前态的一致性并应用替换，不重新询问、调用规划或再次扣物。游戏修订为 14，不兼容旧开发存档。

`CycleObservedCommunication` 保存发言者、接收者与内容；观察只投影自己的剩余额度/待响应，目标和物品参数域复用当前可见人物与自身背包。两种布局及差分渲染使用同一材料，话语作为带署名的数据文字显示，不成为 Markdown 结构或 Console 命令。

模型时间推进后的额度恢复是纯派生值；`CommunicationBudgetRenewed` 只解释角色可感知的额度变化，不增加业务事实或改写预算锚点。说话、赠与不确认身体警告、不更改身体速率来源；明确确认和耗时安排仍按既有规则处理。

真实预演表明新采纳的合作约定需要写入 handoff；旧 Context 的完整对白不自动进入下一回合。模型提示要求在草稿未覆盖新分工/承诺时更新一次交接，记录承诺、下一步和待核实信息。第二轮已保持分工并共同逃离，但 Human 入口由 coding agent 操作；仍须真人合作验收。

## 实施和验收顺序

1. 核定命令/事实/通信状态合同，补数值批量库存边界；规则、观察、Host 继续职责分离。
2. 同地说话/赠与、有限发送与稳定轮转；界面显示剩余额度、待响应通信和明确的 continue 含义。按本轮实际渲染体验微调文案。
3. 活动途中收到通信、回复/消费/继续后原期限保持；同时存在身体警告和交流时不得漏确认或重置活动。特别覆盖上面的救命饮水反例。
4. 两人持续互答达到额度后仍可放行时间；跨 Context 和冷开不返还额度；非法/远处目标不泄漏；赠与 E-only 不重复增减，容量拒绝守恒。
5. 先自动代理预演并打磨，再由实际人类控制 a、真实 LLM 控制 b，完成共同逃离；记录对白或赠与实质改变了哪些决定与结果。两个角色独自走同一路不算合作验收。

保留真实模型证据与原三个模式回归。完整笔记本、长期召回、远距通信、后台插话、聊天会话框架和通用事件总线仍不在本片范围。
