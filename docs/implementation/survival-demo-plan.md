## 2. A：空间接线的组合合同

### 单根与运行时

默认继续使用 ResourceCycle 库与 CLI；原批处理和多人采集场景保持可运行。游戏业务根增加可选探索子图，包含 Spatial 业务状态、按角色的探索记录与结局。没有探索子图的场景沿用原规则。

固定地图由稳定内容身份与游戏修订号绑定应用定义。GraphDefinition 是运行时定义，不冒充可持久化对象；加载时必须能按相同内容身份还原相同地图。地图语义变更需修订游戏版本或明确转换，无旧开发存档兼容负担。

CycleWorld 保存组合后的运行时视图，空间预测和资源预测都是派生缓存。游戏只运行一个 Kernel；使用 SpatialPlanner、空间发生项规则、事实 reducer 和 Complete/Rebuild 接缝，不驱动第二个 Spatial Kernel。所有模块的业务变化由同一游戏根发布。

### 移动与行动

角色位置和移动期限只来自 Spatial，不新增另一份旅行 Activity。游戏统一判断决策资格与可用动作：移动中不能另开采集或等待；本片不提供途中取消/掉头，不能以取消为由瞬移。后续生存警告可唤醒移动中的角色，具体响应另在 B 切片定义。

移动开始改变空间状态和角色请求代数；到达事实同时表达空间到达、角色结果、探索记忆及可能的胜利。恢复这些记录时不重新观察隐藏世界、不推断胜负、不重新询问控制器。资源与非移动活动仍使用原规则。

当前应用同刻优先级为：生存耗尽 → 资源再生 → 昼夜切换 → 脚本销毁 → 空间到达 → 采集/等待完成 → 生存警告 → 角色输入；同类别再沿用 Kernel 的确定性仲裁。测试覆盖昼夜与到达同刻，以及死亡和出口相差一 tick 或同刻的结局。终局停止普通发生项调度，续局不重新执行结束过程。随机风险加入时显式扩展该政策。

### 可见性

控制器接收角色 DecisionContext，其中包括已构造的 Observation 与只读行动校验能力，不直接接收完整世界。Console 从观察结果渲染。权威校验留在游戏，避免 UI 复制业务规则。

校验必须先按可见/可交互域处理目标身份，再查询隐藏状态；不能通过“无此物”与“有此物但太远”等差异泄露未知目标。未访问的邻接方向可以有地形或路标线索，但不能直接搬出 Spatial 的全部目标身份或世界地图。

当前地点的资源是实时观察，离开后的记录带时间并明确可能过期。自然事件的 Console 文本也遵循角色感知范围，不能用全局再生播报绕过观察边界。

### 验收重点

- 地点间移动耗时、到达唤醒、资源可达性和到出口结局。
- 原批处理/多人采集回归，以及新旧场景打开方式的错误处理。
- 远处/未知 ID 校验、未探索出口、历史资源记录的隔离。
- 真实磁盘 S-only 移动续局、移动相关 E-only 恢复；恢复不调用控制器或重新规划。
- 全量/增量预测一致，空间与游戏业务在同一边界校验，不允许只保存一侧变化。

## 3. B 生存需求与 C 环境风险

B 的分段积分、阈值、警告去重、消费、庇护、终局与恢复合同集中在[生存需求设计](../design/survival-needs.md)。规则保留在游戏层，Inventory 负责局部扣除；身体与库存变更由同一个应用事实记录，不建立通用状态条或效果框架。

生产 `--survival` 默认启用需求；原多人采集和批处理不受影响。纯空间回归可通过工厂显式禁用需求保留 A 证据，但不能代替 B 的真实玩法验收。木材暂保留为资源，没有燃料用途；后续依据玩法需要决定火堆等机制。

C 仍需设计明确的随机发生机会、可感知征兆、实际后果及同刻顺序。持久随机状态随业务图保存；只在选中的规划中抽样，记录结果与随机状态推进。查看、校验、预测重建与 pending 恢复不抽样。优先组合现有身体/活动/空间规则，而非先建独立战斗系统。
