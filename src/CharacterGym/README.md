# Shared model audit projection

`GymMessageProjection` preserves concrete Completion content for the full raw model audit, including native replay fields. Those fields are host evidence, not automatically character-visible dialogue. Do not supply clients or credential configuration to this projection.

The Playground host now owns the single semantic timeline in `host/events.jsonl`: [PlaygroundHostJournal](../Playground.Cli/PlaygroundHostJournal.cs), [PlaygroundOperationAudit](../Playground.Cli/PlaygroundOperationAudit.cs), and [PlaygroundHostSession](../Playground.Cli/PlaygroundHostSession.cs). [LlmRawAudit](../Playground.Cli/LlmRawAudit.cs) creates an independent hash-chained file lazily on the first model request. A Human-only run creates no raw audit file. The old shared `GymJournal` and `GymTraceExporter` have been removed; the assembly keeps its name for this remaining projection responsibility.

The main timeline contains inline character material and a [readable model projection](../Playground.Cli/ModelHistoryProjection.cs) that only uses `ReasoningBlock.PlainText`, ordinary text and tool facts. [CharacterHistoryExporter](../Playground.Cli/CharacterHistoryExporter.cs) selects one actor/branch and follows only proven `branch-fork` source cutoffs. Its ordinary export neither loads nor validates raw files, so missing raw does not prevent the core history from being read. Unknown or unreadable material is a coverage gap, never a native payload dump.

Games provide the completed-State decision boundary and world recovery authority. Independent feedback remains in `feedback.jsonl`; its queries and forks do not require a healthy main timeline. Request forks record an exact source cutoff before the selected model request. Feedback forks have no proven host cutoff and report missing ancestry rather than guessing one. See the [unified host contract](../../docs/design/character-history-and-diagnostics.md), [feedback contract](../../docs/design/independent-feedback.md), and current [management commands](../Playground.Cli/Gym/GymCommands.cs). This assembly does not reference the game or its save model.

Native content projection tests remain in `tests/CharacterGym.Tests`; host journal, readable projection, operation recovery, export and fork tests live in `tests/Playground.Cli.Tests`.
