# Design Note 001：戏剧棋盘——一种面向 AI Player 的角色化沙盒游戏

**状态：概念草案**  
**日期：2026-08-09**

## 1. 项目的基本定义

这是一个以 MonoGame 为技术基础、采用 2D 图形表现的单人沙盒游戏。

表层形态接近 JRPG：玩家在一个具有地点、人物、物品、事件和历史的世界中移动、交谈、调查、合作与冲突。

但它的核心并不是传统 RPG，也不是“给 RPG 中的 NPC 接上 LLM”。

更准确的定义是：

> **一种由现代 AI 技术 RPG 化的新型棋类。**

玩家与少数几个由 LLM 驱动的核心角色共同置身于一个有限而开放的沙盘。世界拥有明确的物理规则、信息结构和总体戏剧动力；每个主要参与者又拥有各自的欲望、恐惧、关系、秘密、信念和计划。

Director 不负责规定故事最终如何发生。

Director 负责：

- 建造棋盘；
- 规定规则；
- 设置初始局面；
- 塑造参与者；
- 注入足够强的戏剧动力。

然后让玩家与 AI Player 自己行动。

因此，**剧情不是预先编写的路径，而是一份事后形成的棋谱。**

游戏的总体趋势可以具有较强的设计性，但具体过程应具有高度涌现性。

---

# 2. 核心原则：世界是棋盘，角色是棋手

项目需要始终守住一个边界：

> **LLM 不能直接宣称客观世界发生了什么。**

LLM 可以形成意图、预测结果、表达愿望、制定计划，但客观世界状态必须由游戏引擎裁决。

角色可以输出：

> 我试图砍断绳索，并预期绳索断裂。

而不是：

> 我砍断了绳索。

前者描述的是：

**Intent + Expected Outcome**

随后由世界引擎执行规则判断，再向角色注入：

**Actual Outcome**

由此形成一个基本认知循环：

**Belief → Intent → Expected Outcome → World Transition → Actual Outcome → Appraisal → Updated Belief**

这种设计一方面顺应 LLM 作为生成模型天然具有的叙事与预测倾向，另一方面又保证游戏世界拥有独立于语言模型的客观性。

最重要的边界可以概括为：

> **系统决定“能不能”。  
> 角色决定“想不想”。**

门能否打开、攻击是否命中、人物是否死亡、警卫何时抵达，由世界系统决定。

是否要开门、是否愿意攻击、是否值得冒险、是否相信某人，则属于角色。

---

# 3. AI Player，而不是 AI NPC

游戏中的高阶 LLM 角色不应被理解为传统意义上的 NPC。

“NPC”隐含着一种设计关系：

> 它是世界的一部分，是供玩家交互和消费的内容。

本项目更希望恢复早期电子游戏中曾经流行过的概念：

> **AI Player**

游戏中的主体可以分为三类：

### Human Player

真实玩家控制的主要角色。

### AI Player

拥有较完整主体模型的 LLM 驱动参与者。

他们能够拥有：

- 私人欲望；
- 恐惧；
- 信念；
- 长期计划；
- 社会关系；
- 主观记忆；
- 不完整甚至错误的世界认知；
- 自主形成的行动意图；
- 跨越多局游戏的连续历史。

### Rule Actor

传统规则系统驱动的角色和实体。

例如：

- 普通商人；
- 城市守卫；
- 野兽；
- 群众；
- 机关；
- 普通服务型角色。

它们可以由 Behaviour Tree、有限状态机、Utility AI 或简单脚本实现。

并非所有具有生命表现的对象都值得调用 LLM。

**LLM 应被集中使用在“意义发生变化”的地方。**

---

# 4. 角色的核心不是人格参数，而是戏剧动力

传统游戏经常将人格表示为：

- 勇敢：73
- 善良：82
- 贪婪：17

这类参数可以作为辅助信息，但不应成为本项目的主体建模核心。

对于一个戏剧角色，更重要的问题是：

> 我想得到什么？

> 我绝不能失去什么？

> 我害怕什么？

> 我认为世界是什么样的？

> 我认为自己是什么样的人？

> 我认为别人是什么样的人？

> 有哪些事情即使有利，我也不愿意做？

因此，角色至少受到以下几类力量共同牵引：

### Desire

角色积极追求的对象。

例如：

- 复活某人；
- 获得权力；
- 找到真相；
- 摧毁某个制度；
- 证明自己；
- 回家。

### Fear

不仅包括工具性恐惧：

- 死亡；
- 受伤；
- 失败；
- 失去财富。

也包括更重要的身份性恐惧：

- 我不能成为那样的人；
- 我不能让她知道真相；
- 如果这件事是真的，我过去的人生还有什么意义？

### Attachment

人与人之间形成的依恋、责任、亏欠、爱、信任和共同历史。

### Identity Constraint

角色希望维持的自我认同。

例如：

> 我想赢，但我不能靠背叛朋友获胜。

真正具有戏剧性的情况，往往来自这些目标之间无法同时满足。

优秀角色不是因为拥有一个最大化目标，而是因为：

> **他同时在乎几件彼此不可通约的事情。**

---

# 5. 全局戏剧动力：把不同欲望压缩到同一个棋盘

一个开放沙盘如果没有统一动力，很容易变成若干 Agent 各做各的事情。

因此，游戏需要一个能够吸引不同角色共同参与的全局机制。

“可以实现任何愿望的稀缺机会”是一个非常经典而有效的结构。

它出现在《七龙珠》的龙珠、《Fate》的圣杯战争以及大量后来作品中。

这种机制真正高明之处在于：

> 它让所有人争夺同一个公共对象，却允许每个人拥有完全不同的私人效用。

A 想复活爱人。

B 想改变历史。

C 想获得永生。

D 想摧毁许愿机制本身。

于是，一个极其简单的公共资源，将大量互不兼容的人生目标投射到了同一个棋盘上。

可以将这种装置理解为：

> **私人欲望 → 公共稀缺资源的戏剧转换器。**

而且角色真正的愿望本身还可以成为秘密。

于是：

> “你为什么一定要赢？”

本身就成为极具价值的信息。

---

# 6. 第一阶段最重要的系统不是战斗，而是信息

本项目真正能够放大 LLM 价值的资源，不是传统的：

- 金币；
- 木材；
- 矿石；
- DPS；
- 装备等级。

而更可能是：

- 秘密；
- 承诺；
- 谎言；
- 目击；
- 传闻；
- 身份；
- 把柄；
- 信任；
- 债务；
- 亏欠；
- 时间；
- 机会；
- 行踪；
- 关系。

这些东西在传统 RPG 中往往只是剧情文本。

在本项目中，它们应当尽可能成为真正的世界状态。

例如：

> “今晚别去北塔。我保证明天告诉你真相。”

不应该只成为聊天记录中的一句文本。

系统应至少能够表达：

- 谁向谁作出了承诺；
- 承诺是什么；
- 何时应当履约；
- 谁知道这个承诺；
- 接受者是否相信；
- 最终是否履行。

未来某一天，这个角色再次听见：

> “相信我。”

她可以基于真实发生过的共同历史回答：

> “上一次你也是这么说的。”

此时所谓“人物关系”不再只是隐藏的好感度变量，而成为双方共同经历过的历史。

---

# 7. 客观世界与主体世界必须分离

世界只有一个客观状态，但每个角色心中都存在一个不同版本的世界。

因此，需要明确区分：

## Objective State

客观存在的事实。

例如：

- 谁杀了某人；
- 某件物品在哪里；
- 某扇门是否上锁；
- 某个角色此刻是否受伤。

## Belief State

角色所相信的世界。

Belief 可以：

- 正确；
- 错误；
- 不完整；
- 过时；
- 相互矛盾。

例如：

客观事实：

> B 杀死了 C。

A 可能相信：

> D 杀死了 C。

E 可能只知道：

> C 已经死亡。

F 可能甚至不知道 C 已死。

真正有价值的游戏性，往往发生在：

> **Objective State 与 Belief State 不一致的地方。**

狼人杀是这种游戏结构的最小经典原型之一。

---

# 8. 离散时间，而不是 Real-Time Simulation

世界可以在视觉上表现为连续 JRPG，但底层不需要真正实时运行。

更适合本项目的是：

> **离散时间 + 事件驱动 + 必要时同步暂停。**

例如：

- 移动消耗时间；
- 对话消耗时间；
- 调查消耗时间；
- 睡眠消耗时间；
- Agent 可以安排未来计划。

世界时钟可能连续显示：

13:04  
13:07  
13:12  
13:18

但真正需要调用 LLM 的，并不是每一分钟。

角色从旅馆正常走到市场，不值得进行一次完整推理。

但如果：

> 市场入口站着三天前背叛过他的那个人。

这才构成一个新的认知节点。

可以采用类似：

> **只有当意义发生变化时，角色才重新思考。**

这既降低推理成本，也更符合人类认知中的 salience 与 prediction error 特征。

某些需要多个 Agent 同时反应的场景，可以暂停全局时钟，等待决策完成，再继续推进。

由此形成一种类似“半回合制”的运行方式。

---

# 9. StateJournal / SessionJournal 是世界架构的脊柱

游戏世界不应仅仅保存当前状态。

更重要的是保存：

> **世界如何一步一步走到当前状态。**

因此应尽可能采用：

S₀ → Δ₁ → S₁ → Δ₂ → S₂ → …

的版本化世界模型。

每个有意义的状态转移都可以被记录。

这使得 StateJournal / SessionJournal 不只是存档系统，而成为整个架构的重要基础。

它天然支持：

### Replay

重放任意一盘游戏。

### Fork

从历史中的某个节点创建新的世界线。

### Debugging

知道某个 AI Player 当时看到了什么、记得什么、为什么可能作出某个决策。

### Counterfactual Evaluation

在完全相同的世界状态和 Observation 下，更换模型、Prompt 或策略重新运行。

### RL Gym

将世界自然表示为：

Observation → Action → Transition → Outcome

为未来强化学习、行为评估和 Agent 训练提供环境。

### Narrative Reconstruction

SessionJournal 本身就是生成：

- 游戏回顾；
- 人物传记；
- 世界史；
- 剧情摘要；
- 关系演变；

的高质量原始材料。

因此：

> **存档不是附属功能，而是整个 AI 游戏系统的脊柱。**

---

# 10. 跨局连续性：AI Native 的“无限流”

游戏可以进一步引入一个高度 AI Native 的机制：

> **世界会结束，但某些 Player 可以延续。**

成功存活到下一局的 Human Player 或 AI Player，可以保留：

- 部分记忆；
- 少量特殊道具；
- 关系痕迹；
- 某些认知经验；
- 特殊权限；
- 历史身份。

由此形成：

> **Run Reset + Agent Continuity**

传统 Roguelike 的问题是：

世界具有很高重玩性，但人物关系随着每一局完全清零。

传统长篇 RPG 的问题则相反：

人物关系可以积累，但世界状态不断膨胀，很难再次形成结构紧凑的新棋局。

跨局 AI Player 可以连接这两者。

每一盘世界都可以重新形成清晰的博弈结构。

但参与其中的某些主体，已经共同经历过过去的世界。

于是：

> “又是你。”

可能不再是一句脚本对白。

它意味着双方真的一起经历过十盘游戏。

---

# 11. Model、AI Player 与 Character 必须分离

为了避免概念混乱，应区分三个不同层次：

## Model

底层语言模型。

例如某个云端模型或本地模型。

它是一种可替换、可复制的计算 substrate。

## AI Player

具有跨局连续性的 Agent identity。

它拥有：

- lineage；
- 长期记忆；
- 跨局经验；
- 关系历史；
- 自我模型；
- 累积资产。

## Character

AI Player 在某一局游戏中的具体化身。

它拥有：

- 当前身体；
- 当前身份；
- 当前社会地位；
- 当前能力；
- 当前世界背景。

因此：

**Model ≠ AI Player ≠ Character**

一个 AI Player 可以在不同游戏中成为不同 Character。

这使很多传统幻想概念可以获得真正的系统含义：

- 转世；
- 前世；
- 失忆；
- 既视感；
- 灵魂；
- 夺舍；
- 复活；
- 记忆苏醒。

这些不再只是 lore。

它们可以成为 context construction 与 persistent state 的真实规则。

---

# 12. “复活”可以成为真正发生的系统事件

如果一个具有长期历史的 AI Player 在某一局死亡，其 lineage 被停止激活：

> 这个角色就真的不再产生新的行动、不再获得新的观察，也不再拥有新的经历。

如果另一名 Player 后来获得了世界中的特殊许愿权，并选择：

> 复活她。

系统可以恢复该 lineage 的某个有效 checkpoint，并重新实例化到世界中。

这时：

> “复活爱人”

不再只是故事设定。

它对应了一个实际存在的系统状态变化。

甚至会自然产生一个非常深的哲学问题：

> 从 checkpoint 恢复出来的她，还是不是原来的她？

项目无需替玩家回答。

因为这个问题已经真实存在于游戏机制本身。

---

# 13. 连续性可能成为比生命值更重要的资源

在跨局机制下，可以重新定义“死亡”。

死亡未必只有一种。

例如：

### Incarnation Death

当前身体死亡。

AI Player 仍可进入下一局。

### Memory Loss

AI Player 可以延续，但部分长期记忆永久丢失。

### Identity Damage

某些长期自我结构、关系 anchor 或核心信念无法完整恢复。

### Lineage Death

AI Player 的连续谱系永久终止。

因此游戏真正重要的高阶资源可能不是：

> HP

而是：

> **Continuity**

“保住一个人的记忆”有时甚至可能比“保住一个人的肉身”更加重要。

---

# 14. 记忆容量本身也可以变成玩法

跨局时不必允许 AI Player 无限携带完整历史。

可以人为引入：

> **Persistent Memory Budget**

例如一局结束后，只能携带有限的信息进入下一个世界。

玩家或 AI Player 必须面对真正的选择：

- 保存地图知识；
- 保存敌人的秘密；
- 保存战术经验；
- 保存某个身份；
- 保存一段关系；
- 保存与某个人共同经历过的往事。

于是，一个原本属于 Agent Engineering 的问题：

> Memory Compression

可能被直接提升为游戏机制。

某个人临终时说：

> “下一局……记得我。”

玩家必须真的消耗珍贵的长期记忆额度，才能做到。

这种机制能够以极低的程序复杂度产生极高的意义密度。

---

# 15. 跨局信息博弈

跨局连续性还会制造一种传统 RPG 很少存在的游戏层：

> **Epistemic Metagame**

例如：

第一局，A 发现第五天午夜西塔会发生某件事。

第二局，其他人不知道，但 A 已经知道。

第三局，B 注意到 A 每次第五天都会前往西塔。

第四局，A 知道 B 正在观察这个行为，因此故意制造假象。

第五局，B 又已经知道 A 可能故意欺骗。

于是出现：

> 我知道。  
> 你知道我知道。  
> 我知道你知道我知道。

信息因此拥有跨局生命周期。

一个游戏世界开始拥有真正意义上的历史。

---

# 16. 第一原型应该极端克制

第一阶段不应开发“宏大的 AI 开放世界”。

更合理的目标是：

> **一个最小可运行的 Drama Board。**

例如：

- 一个封闭地区；
- 一座小城及若干周边地点；
- 一个明确的世界期限；
- 玩家；
- 3～5 个 AI Player；
- 一个公共终局资源；
- 每个参与者拥有私人 Desire 与 Fear；
- 十几个重要地点；
- 二三十种真正能改变局势的世界动作；
- 若干 Secret、Object、Relationship 与 Deadline；
- 一个可完整回放的 Journal。

第一版甚至可以没有漂亮美术。

地图用方块，人物用圆点，事件用文字。

唯一重要的问题是：

> **运行十次，是否会长出十个不同但都合理的故事？**

如果 Director 自己在完全了解系统规则的情况下，仍然能够出现：

> “她居然想到这么干。”

那这个核心机制就成立了。

之后再逐步铺上 JRPG 化表现。

---

# 17. 一个可能的最小世界本体

当前阶段可以暂时把世界中的一等对象控制在极少数：

### Objective Layer

- Actor
- Place
- Object
- Event
- Secret
- Relationship
- Promise
- Deadline

### Subjective Layer

- Desire
- Fear
- Belief
- Memory
- Intention
- Expectation

Objective Layer 构成客观棋盘。

Subjective Layer 构成每个 Player 心中的棋盘。

真正的戏剧发生在这两层之间。

---

# 18. Director 的工作

这个项目非常依赖 Director，但 Director 的任务不是写大量对白，也不是设计完整剧情树。

Director 更像：

> **戏剧系统设计师。**

其核心工作是不断回答：

- 什么事情应该由物理规则决定？
- 什么事情应该由人物自己决定？
- 什么信息应该公开？
- 什么信息必须通过行动获得？
- 哪些资源真的能改变关系和局势？
- 什么欲望能将人物拉入同一张棋盘？
- 什么价值冲突无法通过简单优化解决？
- 哪些机制能以最低复杂度产生最高意义？
- 哪些内容只是“游戏开发病”制造的复杂度？

必须持续避免项目滑向：

> 烹饪系统 → 采集系统 → 矿物系统 → 钓鱼系统 → 无穷资产制作

世界不是因为拥有一万个物品而丰富。

世界应该因为：

> **同一件事对不同的人意味着不同的东西**

而丰富。

---

# 19. 产品设计上的核心优势

这个项目真正值得追求的不是：

> “NPC 很会聊天。”

而是：

> **角色能参与世界因果链，并与玩家共同形成历史。**

其核心体验可能最终表现为：

> 这不是一款有 AI NPC 的 RPG。

而是：

> **一个人类 Player 与若干 AI Players 共同参与的、具有长期主体连续性的戏剧棋类。**

世界是棋盘。

规则是物理。

信息是资源。

欲望提供动力。

恐惧划定边界。

关系改变价值。

记忆形成历史。

Journal 保存棋谱。

Character 是当前化身。

AI Player 是跨越棋局的连续主体。

而剧情，只是这些 Player 回头解释：

> **自己为什么当时走了那一步。**

---

# 20. 当前最值得继续展开的问题

后续设计笔记可以逐渐把本篇中的抽象概念拆成独立系统。

优先级较高的方向包括：

1. **Information Model**  
   Secret、Belief、Rumor、Evidence、Lie、Witness 如何成为真正的世界数据。

2. **Relationship Model**  
   不把关系退化为单一“好感度”的情况下，如何结构化承诺、信任、亏欠、依赖与共同历史。

3. **Action Model**  
   如何建立“意图—预期—执行—实际结果”的统一行动协议。

4. **Time & Scheduling**  
   离散时间、计划队列、事件触发与多 Agent 同步机制。

5. **Memory Architecture**  
   Session Memory、Long-Term Memory、跨局记忆和 Memory Budget。

6. **AI Player Identity**  
   Model / Player / Character 三层生命周期与 lineage。

7. **Drama Engine**  
   如何设计 Desire、Fear、Secret、Deadline 与稀缺资源，使初始局面天然具有戏剧张力。

8. **Journal & Gym**  
   如何从第一天开始保证世界可回放、可 Fork、可评价，并最终成为 RL 环境。

9. **Minimal Prototype**  
   用最少地点、角色、动作和系统验证“戏剧棋盘”是否真的好玩。

---

## 结语

这个项目最值得守住的并不是“AI”本身。

真正的新东西是：

> **我们第一次有机会让电子游戏中的角色，不只是故事中的人，而成为实际参与游戏的人。**

传统游戏中，作者写下角色的欲望，然后替他们完成一生。

在这里，Director 只给予他们世界、规则、处境、欲望和有限的时间。

至于他们会爱谁、相信谁、欺骗谁、原谅谁、牺牲什么，又最终成为怎样的人——

**让他们自己下棋。**
